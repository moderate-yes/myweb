# Frequent Patterns

## 학습 목표

빈발 패턴은 단순히 가장 많이 팔린 상품이나 가장 많이 등장한 단어를 찾는 분석이 아니다. **둘 이상의 항목이 같은 맥락에서 기대보다 자주 함께 나타나는지, 어떤 행동 뒤에 다른 행동이 반복되는지**를 찾는다.

패션 온라인 비즈니스에서는 동시 구매 상품, 리뷰 속 상품 속성과 평가 표현, 코디 이미지의 상품 조합, 이미지와 검색어의 연결, 탐색 행동의 순서를 분석할 수 있다. 다만 `상품`, `좋다`, `검정`, `사람`처럼 거의 모든 기록에 등장하는 항목은 공출현 횟수를 크게 만들기 때문에 빈도와 연관성을 반드시 분리해서 읽어야 한다.

이 장을 마치면 다음을 할 수 있다.

- 공출현·순차 출현·속성 결합을 구분한다.
- 주문·텍스트·이미지에서 ‘함께 나타남’의 범위를 정의한다.
- Support·Confidence·Lift·Leverage·PMI·NPMI를 목적에 맞게 선택한다.
- Apriori와 FP-Growth가 빈발 조합 후보를 줄이는 이유를 설명한다.
- 불용어, 출현 비율, 기대 빈도, 중복 제거로 일반적인 항목의 영향을 줄인다.
- 희귀 조합의 과장과 다중 비교 문제를 설명한다.
- 발견한 패턴을 원문·원본 이미지·다른 기간에서 검증한다.

## 1. 먼저 한 묶음의 경계를 정한다

공출현은 항상 “어디까지를 함께라고 볼 것인가?”에서 시작한다. 같은 데이터라도 분석 단위가 바뀌면 결과의 의미가 달라진다.

- 같은 **주문**에 포함된 상품: 실제 동시 구매
- 같은 **장바구니**에 담긴 상품: 구매 전 관심 조합
- 같은 **세션**에서 조회한 상품: 비교·탐색 조합
- 같은 **리뷰 또는 문장**에 등장한 단어: 상품 속성과 평가 표현의 연결
- 앞뒤 **5개 토큰** 안에 나타난 단어: 가까운 문맥의 연결
- 같은 **코디 이미지**에 검출된 상품·색상·스타일: 착장 요소의 결합
- 같은 **상품 페이지**의 이미지 태그와 설명·리뷰 단어: 이미지와 텍스트의 연결

서로 다른 고객의 행동이 한 세션으로 합쳐지거나 한 상품의 중복 이미지가 여러 장 포함되면 실제보다 강한 공출현이 만들어질 수 있다. 계산보다 먼저 분석 단위와 중복 처리 규칙을 기록해야 한다.

## 2. 평균·중앙값과 빈발 패턴은 계산 질문이 다르다

평균과 중앙값은 한 변수의 값들을 요약한다. 예를 들어 주문 금액 5개의 평균을 계산하면 “한 주문의 금액이 대체로 어느 수준인가?”에 답할 수 있다.

빈발 패턴은 한 값의 대표값을 구하지 않는다. 한 주문·댓글·이미지 안에 여러 항목이 들어 있다고 보고 다음 질문에 답한다.

- A와 B가 각각 몇 번 나타났는가?
- A와 B가 같은 묶음에 몇 번 함께 나타났는가?
- A가 있을 때 B가 나타나는 비율은 얼마인가?
- 두 항목의 원래 출현 빈도를 고려해도 특별히 자주 함께 나타나는가?

예를 들어 평균 주문 금액은 주문마다 하나의 숫자를 모아 계산하지만, 장바구니 공출현은 주문마다 `코트 있음/없음`, `머플러 있음/없음`을 기록한 뒤 두 값이 모두 있는 주문을 센다. 따라서 빈발 패턴의 핵심은 복잡한 공식보다 **묶음의 경계, 항목의 존재 여부, 분자와 분모**를 올바르게 정하는 데 있다.

항목이 m개이면 가능한 두 항목 조합은 다음과 같이 늘어난다.

\[
\frac{m(m-1)}{2}
\]

상품이 100개면 가능한 상품 쌍은 4,950개다. 세 상품 조합까지 찾으면 경우의 수는 더 빠르게 증가한다. 빈발 패턴에서는 모든 조합을 그대로 설명하기보다 최소 출현 기준으로 후보를 줄이고, Lift나 NPMI로 의미 있는 관계를 다시 선별한다.

## 3. 공출현은 여러 데이터에서 다르게 활용된다

### 거래 데이터

코트와 머플러가 같은 주문에 들어가는지, 러닝화와 기능성 양말이 같은 장바구니에 담기는지 분석한다. 세트 기획, 교차 판매, 추천 후보 생성에 활용할 수 있다.

### 텍스트 데이터

리뷰에서 `사이즈–작다`, `소재–부드럽다`, `기장–길다`가 같은 문장이나 일정한 토큰 범위 안에 등장하는지 분석한다. 상품 속성과 만족·불만·반품 이유의 연결을 탐색할 수 있다.

검색 로그에서는 `여름 원피스–하객룩`, 상품 설명에서는 `오버핏–울–롱`과 같은 표현 조합을 찾을 수 있다.

### 이미지 데이터

한 코디 이미지 안에서 `블레이저–슬랙스–로퍼`, `트렌치코트–베이지`, `퍼프소매–A라인`처럼 상품·색상·디테일·스타일이 함께 나타나는지 분석한다. 코디 추천, 스타일 트렌드, 이미지 태그 보완에 활용할 수 있다.

이미지 공출현은 보통 사람이 붙인 태그나 객체 탐지·속성 분류 모델의 결과를 이용한다. 모델이 가방을 놓치거나 검정색을 잘못 인식하면 공출현에도 같은 오류가 전달된다.

### 이미지와 텍스트를 함께 보는 교차 모달 데이터

상품 이미지의 `오버핏·롱기장`과 리뷰의 `편하다·길다`, 이미지의 `두꺼운 코트`와 리뷰의 `따뜻하다·무겁다`처럼 서로 다른 데이터 유형의 연결도 계산할 수 있다.

이미지는 형태와 색을 구체화하고 텍스트는 착용감·상황·감정을 보충한다. 이를 통해 이미지 검색어 확장, 상품 태그 검수, 상세페이지 문구 개선의 후보를 만들 수 있다.

## 4. 거래 공출현은 Support·Confidence·Lift로 시작한다

먼저 주문 5건을 직접 세어 보자. 각 행은 하나의 주문이고, 주문 안에 상품이 있으면 1, 없으면 0으로 표시한다.

| 주문 | 코트 | 머플러 | 함께 있음 |
|---|---:|---:|---:|
| 주문 1 | 1 | 1 | 1 |
| 주문 2 | 1 | 1 | 1 |
| 주문 3 | 1 | 0 | 0 |
| 주문 4 | 0 | 0 | 0 |
| 주문 5 | 1 | 1 | 1 |

전체 5건 가운데 코트는 4건, 머플러는 3건, 두 상품은 3건에서 함께 나타났다. 여기서 Support는 전체 주문을 분모로 사용한다.

\[
\text{Support}(A,B)=\frac{3}{5}=0.60
\]

Confidence는 코트가 있는 주문 4건만 분모로 삼는다. 즉 “코트 주문을 골라 놓았을 때 머플러도 있었는가?”를 계산한다.

\[
\text{Confidence}(A\rightarrow B)=\frac{3}{4}=0.75
\]

머플러는 원래 전체 주문의 60%에 등장한다. 코트 주문에서는 75%에 나타났으므로 이 차이를 원래 머플러 출현율로 나눈 값이 Lift다.

\[
\text{Lift}(A\rightarrow B)=\frac{0.75}{0.60}=1.25
\]

- **Support**는 전체 거래 중 조합이 나타난 비율이다.
- **Confidence**는 A가 있는 거래 중 B도 있는 비율이다.
- **Lift**는 B의 평소 출현율과 비교해 A가 있을 때 B가 얼마나 더 자주 나타나는지 보여준다.

Lift 1.25는 코트 주문에서 머플러가 평소보다 1.25배 자주 나타났다는 뜻이다. 코트가 머플러 구매를 일으켰다는 뜻은 아니다. 반대로 `머플러 → 코트`는 분모가 머플러 주문으로 바뀌므로 Confidence 값이 달라진다.

실제 공출현 확률에서 독립적으로 나타날 기대 확률을 뺀 **Leverage**도 함께 볼 수 있다.

\[
\text{Leverage}(A,B)=P(A,B)-P(A)P(B)
\]

Lift가 희귀한 조합에서 크게 튈 때 Leverage는 실제로 얼마나 많은 추가 공출현이 있었는지 판단하는 데 도움이 된다.

```python
orders = [
    {"코트", "머플러"},
    {"코트", "머플러", "부츠"},
    {"코트"},
    {"셔츠", "팬츠"},
    {"코트", "머플러"},
]

n = len(orders)
coat = sum("코트" in order for order in orders)
scarf = sum("머플러" in order for order in orders)
both = sum({"코트", "머플러"}.issubset(order) for order in orders)

support = both / n
confidence = both / coat
lift = confidence / (scarf / n)
leverage = support - (coat / n) * (scarf / n)

print(f"support = {support:.2f}")
print(f"confidence = {confidence:.2f}")
print(f"lift = {lift:.2f}")
print(f"leverage = {leverage:.2f}")
```

```output
support = 0.60
confidence = 0.75
lift = 1.25
leverage = 0.12
```

학습용 데이터는 작아서 주문 한 건만 달라져도 값이 크게 변한다. 실제 보고에서는 비율과 함께 전체 주문 수와 공출현 건수를 표시한다.

### 장바구니와 동시 구매는 같은 신호가 아니다

장바구니는 고객이 함께 고려한 상품을 보여주지만 실제 구매를 뜻하지 않는다. 코트와 부츠가 장바구니에는 자주 같이 담겨도 높은 합계 금액 때문에 둘 중 하나만 구매할 수 있다. 반면 결제 완료 주문의 공출현은 실제 구매 조합이지만 품절·쿠폰·무료배송 기준의 영향을 받는다.

실무에서는 분석 단계를 나누어 비교한다.

1. **같은 세션에서 함께 조회**: 비교하거나 관심을 보인 조합
2. **같은 장바구니에 함께 담음**: 구매 후보로 선택한 조합
3. **같은 주문으로 결제**: 실제 동시 구매 조합
4. **반품 후 함께 보유**: 최종적으로 고객에게 남은 조합

예를 들어 `코트–부츠`가 조회와 장바구니에서는 강하지만 결제에서 약해진다면 가격 부담이나 쿠폰 조건을 점검할 수 있다. 결제에서는 강하지만 반품 후 약해진다면 사이즈·코디 적합성이나 상품 품질을 확인할 수 있다.

## 5. 공출현 횟수만 보면 일반적인 항목이 상위에 남는다

리뷰 대부분에 `상품`과 `좋다`가 등장한다면 두 단어는 여러 단어와 높은 공출현 횟수를 만든다. 그러나 이 결과만으로 두 단어가 특정 속성이나 문제를 설명한다고 보기 어렵다.

반대로 `사이즈–길다`, `길다–반품`은 절대 횟수가 더 작아도 각 단어의 기본 출현율을 고려하면 더 특별한 결합일 수 있다.

  <figcaption><strong>그림 1.</strong> 공출현 횟수에서는 일반 단어(product, good)가 두드러지지만 NPMI로 기대 빈도를 보정하면 사이즈–길다(size–long), 길다–반품(long–return) 관계가 더 뚜렷해진다. 숫자는 설명을 위한 가상 데이터다.</figcaption>

```python
import matplotlib.pyplot as plt
import numpy as np

labels = ["product", "good", "size", "long", "return"]  # 상품, 좋다, 사이즈, 길다, 반품
counts = np.array([
    [0, 182, 146, 121, 98],
    [182, 0, 72, 66, 41],
    [146, 72, 0, 84, 57],
    [121, 66, 84, 0, 73],
    [98, 41, 57, 73, 0],
])
npmi = np.array([
    [0, .03, .02, .01, .00],
    [.03, 0, .08, .06, .01],
    [.02, .08, 0, .47, .28],
    [.01, .06, .47, 0, .39],
    [.00, .01, .28, .39, 0],
])

fig, axes = plt.subplots(1, 2, figsize=(12, 5))
for ax, matrix, title, fmt in [
    (axes[0], counts, "Co-occurrence count", ".0f"),
    (axes[1], npmi, "NPMI", ".2f"),
]:
    ax.imshow(matrix, cmap="Oranges")
    ax.set_xticks(range(len(labels)), labels)
    ax.set_yticks(range(len(labels)), labels)
    ax.set_title(title)
    for row in range(len(labels)):
        for col in range(len(labels)):
            if row != col:
                ax.text(col, row, format(matrix[row, col], fmt),
                        ha="center", va="center")

plt.tight_layout()
plt.show()
```

## 6. PMI와 NPMI는 기대 빈도를 기준으로 텍스트·태그 관계를 본다

단어 (A)와 (B)가 독립적으로 나타난다고 가정했을 때의 기대 공출현과 실제 공출현을 비교한 값이 **PMI(Pointwise Mutual Information)**다.

\[
\text{PMI}(A,B)=\log\frac{P(A,B)}{P(A)P(B)}
\]

- 0보다 크면 기대보다 자주 함께 나타난다.
- 0에 가까우면 우연히 기대되는 수준이다.
- 0보다 작으면 기대보다 덜 함께 나타난다.

PMI는 아주 드문 조합을 과대평가할 수 있다. 한 번만 함께 나타난 희귀 단어 조합이 높은 점수를 받는 식이다. 따라서 최소 공출현 횟수를 먼저 적용하고, 범위를 비교하기 쉬운 **NPMI**를 사용하는 것이 좋다.

\[
\text{NPMI}(A,B)=\frac{\text{PMI}(A,B)}{-\log P(A,B)}
\]

NPMI는 (-1)에서 (1) 사이의 값을 갖는다. 양의 관계만 남긴 **PPMI**는 단어 공출현 행렬이나 이미지 태그–텍스트 단어 행렬을 만드는 데 유용하다.

\[
\text{PPMI}(A,B)=\max(\text{PMI}(A,B),0)
\]

### 댓글 100개로 NPMI를 계산해 보기

댓글 100개 가운데 `사이즈`가 20개, `길다`가 25개, 두 단어가 함께 나타난 댓글이 10개라고 하자.

\[
P(사이즈)=0.20,\quad P(길다)=0.25,\quad P(사이즈,길다)=0.10
\]

두 단어가 서로 무관하다면 함께 나타날 기대 확률은 `0.20 × 0.25 = 0.05`다. 실제 공출현 확률은 0.10이므로 기대보다 두 배 자주 함께 나타났다.

\[
\text{PMI}=\log\frac{0.10}{0.20\times0.25}=\log 2\approx0.693
\]

\[
\text{NPMI}=\frac{0.693}{-\log(0.10)}\approx0.301
\]

NPMI 0.301은 양의 연관을 뜻하지만, 이것만으로 강한 실무 신호라고 단정하지 않는다. 댓글 수, 다른 기간의 재현 여부, 실제 문장의 의미를 함께 확인한다. 특히 “사이즈는 길지 않다”도 단순 토큰 분석에서는 `사이즈–길다`로 계산될 수 있다.

## 7. 댓글 공출현은 토큰과 문맥 범위를 함께 설계한다

패션 쇼핑몰의 상품 댓글은 고객이 상품 속성과 평가를 자연어로 연결해 놓은 기록이다. 다음 댓글을 보자.

```text
댓글 1: 오버핏이 예쁘지만 소매가 길어요.
댓글 2: 핏은 예쁜데 기장이 길어서 반품했어요.
댓글 3: 소재가 부드럽고 착용감이 좋아요.
댓글 4: 사이즈는 맞지만 소매가 너무 길어요.
댓글 5: 색상은 예쁜데 사진보다 어두워요.
댓글 6: 기장이 길지만 수선해서 입을게요.
```

`소매–길다`가 반복되면 소매 길이 문제를, `기장–길다–반품`이 반복되면 기장과 반품의 연결을 의심할 수 있다. 그러나 댓글 6처럼 `길다`가 반드시 불만이나 반품을 의미하지는 않는다. 공출현은 문제 후보를 찾고 원문 검토 위치를 좁히는 방법이다.

댓글 전체를 한 묶음으로 보면 같은 댓글 안의 멀리 떨어진 단어도 연결된다. 문장 단위나 앞뒤 3~5개 토큰의 Window를 사용하면 가까운 표현 관계를 강조할 수 있다.

- **댓글 단위**: 한 고객이 함께 언급한 주제를 넓게 찾는다.
- **문장 단위**: 같은 문장 안의 속성과 평가를 연결한다.
- **토큰 Window**: 바로 가까이에 놓인 표현 관계를 찾는다.
- **상품 단위**: 같은 상품의 여러 댓글에서 반복되는 문제를 찾는다.
- **기간 단위**: 신상품 출시 후 새로 증가한 표현 조합을 찾는다.

분석 전에는 다음을 결정한다.

- 조사·어미를 어떻게 정리하고 `길어요·길다·긴`을 같은 표현으로 묶을 것인가?
- `안 길다`, `길지만 반품하지 않았다`처럼 부정 표현을 어떻게 보존할 것인가?
- 상품명·브랜드명·사이즈 코드처럼 붙여서 봐야 하는 토큰은 무엇인가?
- 같은 리뷰에서 한 단어가 여러 번 나와도 한 번만 셀 것인가?

초보 단계에서는 형태소 분석을 완벽히 해결하려 하기보다 분석 규칙과 한계를 명시하고, 상위 조합의 원문을 다시 읽는 과정이 중요하다.

```python
from collections import Counter
from itertools import combinations

comments = [
    {"오버핏", "예쁘다", "소매", "길다"},
    {"핏", "예쁘다", "기장", "길다", "반품"},
    {"소재", "부드럽다", "착용감", "좋다"},
    {"사이즈", "길다", "반품"},
]

stopwords = {"상품", "제품", "정말", "너무"}
pair_counts = Counter()

for comment in comments:
    # 같은 댓글에서 같은 단어가 반복되어도 존재 여부만 센다.
    tokens = sorted(comment - stopwords)
    pair_counts.update(combinations(tokens, 2))

for pair, count in pair_counts.most_common():
    if count >= 2:
        print(pair, count)
```

```output
('길다', '예쁘다') 2
('길다', '반품') 2
```

이 결과는 작은 학습용 예시다. 실제 분석에서는 최소 출현 기준과 NPMI 같은 보정 지표를 적용하고 원문 문장을 함께 확인한다.

실무에서는 결과를 다음과 같이 연결할 수 있다.

- `사이즈–작다–반품`: 사이즈표, 실측 정보, 추천 사이즈 점검
- `소재–까슬하다–피부`: 혼용률과 착용 주의 문구 보완
- `색상–다르다–사진`: 촬영 조명과 색상 보정 검수
- `배송–늦다–행사`: 행사 기간 물류 지연 여부 점검
- `부드럽다–재구매`: 만족 속성과 재구매의 연관 후보 탐색

댓글에 `좋다`가 많이 나온다는 사실보다 **무엇이 좋았는지**, `반품`이 많이 나온다는 사실보다 **어떤 속성과 함께 반품이 언급되었는지**가 더 실행 가능한 정보다.

## 8. 이미지 공출현은 한 이미지당 존재 여부로 세는 것이 안전하다

같은 이미지에서 가방이 세 번 검출되었다고 공출현을 세 배로 늘리면 촬영 구도나 탐지 중복이 결과를 지배할 수 있다. 코디 분석에서는 일반적으로 한 이미지 안에 해당 요소가 **존재했는지 여부**를 사용한다.

```text
이미지 1: 블레이저, 슬랙스, 로퍼, 검정
이미지 2: 블레이저, 데님, 스니커즈, 네이비
이미지 3: 트렌치코트, 슬랙스, 로퍼, 베이지
```

이 기록에서는 `블레이저–슬랙스`, `슬랙스–로퍼`, `트렌치코트–베이지` 같은 조합을 계산할 수 있다.

세 이미지 중 슬랙스는 2장, 로퍼는 2장, 두 항목은 같은 2장에 함께 나타난다.

\[
\text{Support}(슬랙스,로퍼)=\frac{2}{3}
\]

\[
\text{Confidence}(슬랙스\rightarrow 로퍼)=\frac{2}{2}=1.0
\]

\[
\text{Lift}(슬랙스\rightarrow 로퍼)=\frac{1.0}{2/3}=1.5
\]

이 작은 표본에서는 슬랙스가 등장한 이미지에 로퍼가 항상 함께 보였다. 하지만 이미지가 세 장뿐이므로 일반적인 코디 규칙이라고 결론 내릴 수 없다. 더 많은 이미지와 다른 시즌에서 반복되는지 확인해야 한다.

### 이미지 공출현의 실무 유형

- **코디 이미지 안의 상품–상품**: 재킷과 팬츠, 원피스와 가방처럼 함께 착용된 조합
- **상품과 속성**: 트렌치코트와 베이지, 드레스와 새틴처럼 상품군과 색상·소재의 결합
- **상품과 상황**: 수영복과 해변, 패딩과 눈처럼 착용 상황과 상품의 결합
- **디자인 요소**: 퍼프소매와 A라인, 크롭 기장과 와이드 팬츠처럼 실루엣·디테일의 결합
- **이미지와 구매 기록**: 코디 이미지에 함께 노출된 상품 가운데 실제 장바구니·동시 구매로 이어진 조합

마지막 유형은 이미지 공출현과 거래 공출현을 연결한다. 코디 이미지에서 자주 함께 보였지만 장바구니에는 함께 담기지 않는다면 시각적으로는 자연스러워도 가격·재고·상품 링크가 구매를 방해할 수 있다. 이미지, 장바구니, 결제 단계의 공출현을 차례로 비교하면 이탈 지점을 찾을 수 있다.

같은 이미지에 등장했다고 반드시 같은 코디라고 볼 수도 없다. 상품 여러 개를 붙인 콜라주, 매장 진열대, 배경 포스터가 객체를 한 화면에 모을 수 있다. 가능하면 객체 위치와 `착용·들고 있음·배경` 같은 관계 태그를 함께 사용한다.

이미지 공출현 분석에서는 다음 전처리가 특히 중요하다.

- `사람·의류·실내·배경`처럼 거의 모든 이미지에 붙는 일반 태그 제외
- 객체 탐지 신뢰도 기준을 정하고 낮은 신뢰도 결과 제외
- 동일 상품의 썸네일·확대 사진·복제 이미지를 해시나 임베딩으로 중복 제거
- 하나의 이미지에서 중복 검출된 같은 객체를 하나의 존재로 변환
- 전체 패션 이미지가 아니라 코트·원피스·출근룩처럼 비교 가능한 범위 안에서 계산
- 원본 이미지 표본을 열어 태그와 검출 결과가 맞는지 검수

특정 촬영 스튜디오나 캠페인 배경이 스타일과 함께 반복될 수도 있다. 상품의 자연스러운 관계인지 촬영 정책의 반복인지 구분해야 한다.

## 9. 빈발 패턴 분석은 후보를 줄이는 과정이다

상품이나 단어가 많아지면 가능한 조합을 모두 계산하는 비용이 빠르게 증가한다. 실제 분석은 다음 순서로 후보를 단계적으로 줄인다.

1. **묶음을 만든다.** 주문별 상품, 댓글별 토큰, 이미지별 태그를 하나의 집합으로 만든다.
2. **단일 항목을 센다.** 코트·머플러·부츠가 각각 몇 묶음에 나타났는지 계산한다.
3. **최소 Support를 적용한다.** 거의 나타나지 않는 항목과 조합을 먼저 제외한다.
4. **두 항목 이상의 조합을 센다.** 최소 기준을 통과한 항목으로 상품 쌍과 단어 쌍을 만든다.
5. **연관 지표를 계산한다.** 거래에는 Confidence·Lift·Leverage, 텍스트·태그에는 NPMI 등을 계산한다.
6. **일반 항목과 희귀 조합을 거른다.** 출현 비율 상한·하한과 최소 공출현 건수를 적용한다.
7. **원본과 다른 기간에서 검증한다.** 점수가 높은 조합의 실제 주문·댓글·이미지를 확인한다.

### Apriori: 작은 조합부터 기준을 통과시키기

Apriori는 “어떤 조합이 자주 나타난다면 그 조합의 일부도 자주 나타나야 한다”는 성질을 이용한다. `코트–머플러–부츠` 세 상품 조합이 최소 Support를 통과하려면 `코트–머플러`, `코트–부츠`, `머플러–부츠` 같은 하위 조합도 기준을 통과해야 한다.

따라서 자주 나타나지 않는 하위 조합을 포함한 더 큰 조합은 계산 후보에서 일찍 제외할 수 있다. 원리를 설명하기 쉽지만 상품 수와 주문 수가 매우 많으면 후보 생성 비용이 커질 수 있다.

### FP-Growth: 반복되는 거래 구조를 압축하기

FP-Growth는 거래를 FP-Tree라는 구조로 압축하고 반복되는 경로를 이용해 빈발 조합을 찾는다. 후보 조합을 반복해서 생성하는 과정을 줄일 수 있어 큰 장바구니 데이터에서 Apriori보다 효율적일 수 있다.

초보 분석가는 트리의 내부 구현을 외우기보다 다음 차이를 이해하면 충분하다.

- Apriori와 FP-Growth는 **빈발 조합을 효율적으로 찾는 알고리즘**이다.
- Support·Confidence·Lift는 **찾은 조합을 평가하고 해석하는 지표**다.
- 알고리즘이 결과를 빠르게 찾아도 묶음 정의와 데이터 품질이 잘못되면 유용한 규칙이 되지 않는다.

```python
import pandas as pd
from mlxtend.frequent_patterns import apriori, association_rules
from mlxtend.preprocessing import TransactionEncoder

orders = [
    ["코트", "머플러"],
    ["코트", "머플러", "부츠"],
    ["코트"],
    ["셔츠", "팬츠"],
    ["코트", "머플러"],
]

encoder = TransactionEncoder()
encoded = encoder.fit(orders).transform(orders)
basket = pd.DataFrame(encoded, columns=encoder.columns_)

frequent_sets = apriori(
    basket,
    min_support=0.20,
    use_colnames=True,
)
rules = association_rules(
    frequent_sets,
    metric="lift",
    min_threshold=1.0,
)

print(rules[["antecedents", "consequents", "support", "confidence", "lift"]])
```

이 코드는 주문을 상품별 True/False 표로 바꾼 뒤 Support 기준을 통과한 상품 조합과 연관 규칙을 계산한다. 실제 데이터에서는 기준을 낮추기 전에 계산량과 우연한 규칙의 증가를 함께 고려한다.

## 10. 일반적인 출현을 줄이는 여섯 가지 방법

### 불용어와 일반 태그 사전

텍스트의 `상품·구매·정말`, 이미지의 `사람·의류·배경`처럼 변별력이 낮은 항목을 제외한다. 다만 `사이즈`, `검정`, `배송`은 질문에 따라 중요한 신호일 수 있으므로 고정된 하나의 불용어 목록보다 분석 목적별 목록을 관리한다.

### 최소·최대 출현 비율

전체 기록의 지나치게 많은 부분에 등장하는 항목과 너무 적게 등장하는 항목을 동시에 걸러낸다. 예를 들어 문서 출현 비율 80% 이상인 일반 단어와 0.1% 미만인 희귀 단어를 우선 검토 대상으로 둘 수 있다.

### 기대 빈도 보정

거래 데이터에는 Lift·Leverage, 텍스트와 이미지 태그에는 NPMI·PPMI를 사용한다. 일반적인 항목을 무조건 삭제하지 않고 원래 출현 빈도를 기준으로 관계의 특별함을 평가할 수 있다.

### TF-IDF 가중치

텍스트에서 모든 문서에 등장하는 단어의 영향은 낮추고 특정 상품이나 리뷰 집단에 집중된 단어의 영향은 높인다. TF-IDF는 문서별 중요도를 보는 방법이고 NPMI는 항목 쌍의 연관성을 보는 방법이므로 목적이 다르다.

### 중복과 반복 노출 제거

복사된 상품 설명, 동일 사용자의 반복 리뷰, 같은 상품의 유사 이미지가 공출현을 부풀리지 않도록 분석 단위별 한 번만 세거나 중복을 먼저 제거한다.

### 비교 범위를 나누기

전체 상품을 한꺼번에 분석하지 않고 카테고리·시즌·고객군·채널별로 계산한다. `검정`은 전체 패션 상품에서는 일반적이지만 여름 원피스 안에서는 특정 실루엣과 의미 있는 관계를 가질 수 있다.

## 11. 희귀 조합의 과대평가도 함께 막는다

일반 항목만 제거하면 충분하지 않다. 두 번 중 두 번 함께 나타난 조합은 Confidence 100%지만 안정적인 규칙이라고 보기 어렵다.

실무에서는 다음 조건을 함께 사용한다.

- 최소 공출현 건수
- 최소 Support
- Lift 또는 NPMI 하한
- Leverage 또는 실제 추가 공출현 건수
- 다른 기간·채널에서의 재현 여부
- 여러 조합을 동시에 검사할 때의 우연한 발견 가능성

학습용 출발점으로 거래 데이터는 `공출현 10건 이상, Support 0.5% 이상, Lift 1.5 이상`, 텍스트·이미지 태그는 `공출현 5건 이상, NPMI 0.2 초과`처럼 시작할 수 있다. 이 숫자는 표준이 아니며 데이터 규모와 잘못된 추천의 비용에 맞춰 조정해야 한다.

## 12. 순차 출현은 시간의 순서를 보존한다

**순차 패턴(Sequential pattern)**은 같은 고객이나 세션에서 행동이 어떤 순서로 나타나는지 본다.

`검색 → 상품 상세 → 사이즈표 → 장바구니 → 구매`

순차 분석 전에는 다음을 정한다.

- 고객 ID와 기기 ID 중 무엇으로 사용자를 연결할 것인가?
- 몇 분의 비활동 뒤 세션이 종료되는가?
- 같은 행동의 반복을 하나로 합칠 것인가?
- 두 사건 사이 최대 시간은 얼마인가?
- 구매하지 않은 경로도 같은 분모에 포함하는가?

공출현은 같은 묶음에서 함께 나타나는지를 보고, 순차 출현은 앞뒤 순서를 보존한다. 순서가 있다고 해서 앞 행동이 뒤 행동을 일으킨 것은 아니다. 구매 의도가 강한 고객이 사이즈표와 장바구니를 모두 더 자주 이용했을 수 있다.

## 13. 발견한 패턴을 검증하고 행동으로 연결한다

상위 점수만 보고 즉시 모든 고객에게 추천하지 않는다.

1. 상위 조합의 리뷰 원문과 원본 이미지를 사람이 확인한다.
2. 다른 기간·채널·고객군에서도 관계가 반복되는지 확인한다.
3. 계절, 프로모션, 진열 위치, 촬영 콘셉트가 공통 원인인지 점검한다.
4. 재고·마진·반품률과 상품 호환성을 검토한다.
5. 추천 후보로 제한해 작은 실험을 진행한다.
6. 구매율뿐 아니라 객단가·반품률·추천 피로도·공헌이익을 함께 평가한다.

공출현은 탐색과 후보 생성에 강하지만 인과효과를 자동으로 증명하지 않는다. 추천이 실제 추가 구매를 만들었는지는 대조군을 둔 실험으로 확인한다.

## 14. 단계별 실습: 장바구니 규칙과 행동 순서

실습 데이터의 주문은 한 건에 상품이 하나뿐이라 공출현을 계산할 수 없다. 가상 주문 400건으로 거래 공출현을, 실습 데이터의 `events.csv`로 순차 출현을 연습한다.

### 1단계: 주문별 상품 집합을 만든다

```python
import numpy as np
import pandas as pd

rng = np.random.default_rng(11)
items = ["코트", "머플러", "니트", "부츠", "셔츠", "슬랙스", "로퍼", "스카프"]
baskets = []
for _ in range(400):
    picked = rng.choice(len(items), size=rng.integers(1, 4), replace=False)
    basket = {items[i] for i in picked}
    if "코트" in basket and rng.random() < 0.55:
        basket.add("머플러")
    if "슬랙스" in basket and rng.random() < 0.45:
        basket.add("로퍼")
    baskets.append(sorted(basket))

print(baskets[:5])
print("주문 수:", len(baskets))
```

```output
[['머플러'], ['니트', '셔츠', '스카프'], ['머플러', '부츠'], ['셔츠', '코트'], ['니트', '로퍼', '부츠']]
주문 수: 400
```

실제 데이터에서는 `orders.groupby("order_id")["product_id"].apply(set)`으로 같은 표를 만든다. 1절의 묶음 경계(주문·장바구니·세션)를 여기서 정한다.

### 2단계: 존재 여부 표로 바꾼다

```python
from mlxtend.preprocessing import TransactionEncoder

encoder = TransactionEncoder()
basket_df = pd.DataFrame(encoder.fit(baskets).transform(baskets), columns=encoder.columns_)
print(basket_df.head(3))
print(basket_df.mean().sort_values(ascending=False).round(2))
```

```output

```

열 평균이 곧 각 상품의 Support다. 머플러는 39%의 주문에 들어가므로 어떤 상품과도 공출현 횟수가 높게 나온다.

### 3단계: Apriori로 규칙을 찾고 최소 건수로 거른다

```python
from mlxtend.frequent_patterns import apriori, association_rules

frequent = apriori(basket_df, min_support=0.05, use_colnames=True)
rules = association_rules(frequent, metric="lift", min_threshold=1.2)
rules = rules[rules["support"] * len(baskets) >= 10]
rules["pair"] = rules["antecedents"].apply(lambda s: ",".join(s)) + " → " + rules["consequents"].apply(lambda s: ",".join(s))
print(rules.sort_values("lift", ascending=False)[["pair", "support", "confidence", "lift", "leverage"]].head(8).round(3))
```

```output
       pair  support  confidence   lift  leverage
3  머플러 → 코트    0.200       0.510  1.772     0.087
2  코트 → 머플러    0.200       0.696  1.772     0.087
0  슬랙스 → 로퍼    0.115       0.484  1.562     0.041
1  로퍼 → 슬랙스    0.115       0.371  1.562     0.041
```

데이터를 만들 때 넣은 두 관계(코트–머플러, 슬랙스–로퍼)만 남았다. `코트 → 머플러`와 `머플러 → 코트`는 Lift가 같지만 Confidence가 다르다. 분모가 다르기 때문이다.

### 4단계: 고객별 행동 순서를 만든다

```python
DATA = "templates/01_fashion_bigdata/data"
events = pd.read_csv(f"{DATA}/events.csv", parse_dates=["event_time"]).dropna(subset=["customer_id"])
events = events.sort_values(["customer_id", "event_time"])

sequences = events.groupby("customer_id")["event_type"].apply(list)
print(sequences)
```

```output
customer_id
C001              [view, add_to_cart, purchase]
C002           [view, purchase, view, purchase]
C003                           [view, purchase]
C004    [view, purchase, add_to_cart, purchase]
C006                           [view, purchase]
Name: event_type, dtype: object
```

`customer_id`가 비어 있는 익명 방문은 제외했다. 12절의 질문대로 세션 경계와 사용자 연결 기준을 먼저 정해야 한다.

### 5단계: 연속 두 행동의 전이 빈도를 센다

```python
from collections import Counter

bigrams = Counter()
for seq in sequences:
    steps = [s for i, s in enumerate(seq) if i == 0 or s != seq[i - 1]]
    bigrams.update(zip(steps, steps[1:]))
print(bigrams.most_common())

starts = Counter(step[0] for step in bigrams.elements())
for (a, b), count in bigrams.most_common():
    print(f"{a} → {b}: {count}건, {a} 이후 비율 {count / starts[a]:.2f}")
```

```output
[(('view', 'purchase'), 5), (('add_to_cart', 'purchase'), 2), (('view', 'add_to_cart'), 1), (('purchase', 'view'), 1), (('purchase', 'add_to_cart'), 1)]
view → purchase: 5건, view 이후 비율 0.83
add_to_cart → purchase: 2건, add_to_cart 이후 비율 1.00
view → add_to_cart: 1건, view 이후 비율 0.17
purchase → view: 1건, purchase 이후 비율 0.50
purchase → add_to_cart: 1건, purchase 이후 비율 0.50
```

같은 행동의 반복은 하나로 합쳤다. `view` 뒤에 `add_to_cart` 없이 바로 `purchase`가 오는 경로가 많다면 장바구니 이벤트 수집 누락을 먼저 의심한다. 다섯 고객의 결과이므로 패턴이 아니라 계산 형식을 익히는 예다.

<div class="lesson-section-box lesson-summary-box"><strong>이 장의 핵심</strong></div>

- 공출현은 거래뿐 아니라 텍스트·이미지·교차 모달 데이터에도 적용할 수 있다.
- 함께 나타남의 의미는 주문·문장·토큰 Window·이미지·세션 등 분석 단위에 따라 달라진다.
- 거래에는 Support·Confidence·Lift·Leverage, 텍스트와 이미지 태그에는 NPMI·PPMI가 유용하다.
- Apriori와 FP-Growth는 조합을 찾는 알고리즘이고, Lift와 NPMI는 찾은 관계를 평가하는 지표다.
- 일반 항목은 불용어, 출현 비율, 기대 빈도 보정, 중복 제거, 비교 범위 분리로 영향을 줄인다.
- 너무 흔한 항목뿐 아니라 너무 희귀한 조합의 과대평가도 막아야 한다.
- 패턴은 원문·원본 이미지와 다른 기간에서 검증하고, 실제 효과는 실험으로 평가한다.

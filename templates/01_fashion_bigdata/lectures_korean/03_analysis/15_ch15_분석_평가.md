# Evaluating Analysis Results

## 학습 목표

분석은 숫자나 모델을 만드는 것으로 끝나지 않는다. 결과가 질문에 맞는지, 새로운 데이터에서도 유지되는지, 특정 집단을 빠뜨리지 않았는지, 행동했을 때 이익이 비용과 위험보다 큰지 평가해야 한다. 평가는 마지막 한 번의 시험이 아니라 가설·전처리·분석·운영 전 과정에 이어진다.

이 장을 마치면 다음을 할 수 있다.

- 다섯 분석 방법별 평가 질문을 구분한다.
- 전환율을 비롯한 그로스·커머스 지표의 분자와 분모를 설명한다.
- Accuracy·Precision·Recall을 혼동행렬에서 계산하고 목적에 맞게 선택한다.
- MAE 등 회귀 지표와 허용오차 내 적중률의 차이를 이해한다.
- 기준선과 학습·검증·테스트 데이터의 역할을 설명한다.
- 효과 크기·신뢰구간·p-value와 확률 보정을 해석한다.
- 연관·예측과 인과효과를 구분하고 실험의 역할을 이해한다.
- 편향·재현성·업무 가치·비용·보호 지표를 함께 평가한다.

## 1. 먼저 질문과 결과의 형태가 맞는지 본다

모델 성능이 높아도 원래 질문과 다른 결과를 만들면 좋은 분석이 아니다.

- 발주량이 필요한데 인기 여부만 분류하지 않았는가?
- 고객 경험 개선이 목표인데 클릭률만 높이지 않았는가?
- 상품별 의사결정인데 카테고리 평균만 제시하지 않았는가?
- 다음 주 예측인데 월말 이후에 알 수 있는 정보를 사용하지 않았는가?
- 원인을 묻는 질문에 상관관계만 제시하지 않았는가?

평가의 첫 기준은 “이 결과로 누가 어떤 결정을 바꿀 수 있는가?”이다.

## 2. 다섯 방법은 평가 기준도 다르다

### 특성화·차별화

- 분자·분모·기간과 제외 규칙이 명확한가?
- 평균뿐 아니라 표본 수와 분포를 보여주는가?
- 비교 집단의 구성과 노출 기회가 비슷한가?
- 다른 기간·채널에서도 차이가 유지되는가?

### 빈발 패턴

- support·confidence·lift와 실제 거래 수를 함께 보았는가?
- 다른 기간에도 패턴이 반복되는가?
- 진열·추천 정책이 공출현을 만들지 않았는가?
- 패턴을 적용했을 때 증분 성과가 있는가?

### 분류·회귀

- 학습에 사용하지 않은 데이터에서 성능을 측정했는가?
- 단순 기준선보다 나은가?
- 중요한 오류 유형과 집단별 성능은 어떤가?
- 확률과 예측 범위가 실제 빈도와 맞는가?
- 오류 비용을 반영한 임곗값인가?

### 군집

- 표본과 기간을 바꿔도 군집이 안정적인가?
- 군집을 설명할 수 있고 충분한 규모가 있는가?
- 군집별 행동이 실제로 다르고 실행 가능한가?
- 실루엣 점수뿐 아니라 후속 실험의 가치를 확인했는가?

### 이상치 감지

- 실제 문제를 얼마나 찾고 얼마나 놓쳤는가?
- 경보 중 조치 가치가 있는 비율은 얼마인가?
- 탐지 지연과 하루 조사량이 운영 가능한가?
- 정상 변화와 시스템 오류를 구분할 근거가 있는가?

## 3. 비즈니스 성과는 그로스·커머스 지표로 평가한다

분석 방법의 기술적 품질과 실제 사업 성과는 다르다. 반품 예측 모델의 Recall이 높아도 반품 안내가 고객 경험이나 실제 반품률을 개선하지 못하면 사업 효과는 제한적이다.

패션 온라인 비즈니스에서 자주 사용하는 지표는 다음과 같다.

| 지표 | 기본 계산 | 확인하려는 질문 |
|---|---|---|
| 클릭률 | 클릭 수 ÷ 노출 수 | 상품·콘텐츠가 관심을 만들었는가? |
| 상품상세 진입률 | 상세 진입 세션 ÷ 방문 세션 | 고객이 상품 탐색을 시작했는가? |
| 장바구니 전환율 | 장바구니 추가 세션 ÷ 상세 방문 세션 | 상품 정보가 구매 고려로 이어졌는가? |
| 결제 완료율 | 구매 세션 ÷ 결제 시작 세션 | 결제 과정에서 이탈이 발생하는가? |
| 구매 전환율 | 구매 고객·세션 ÷ 방문 고객·세션 | 방문이 실제 구매로 이어졌는가? |
| 재구매율 | 다시 구매한 고객 ÷ 기준 고객 | 고객이 정한 기간 안에 돌아왔는가? |
| 유지율·이탈률 | 유지·이탈 고객 ÷ 기준 고객 | 고객 관계가 지속되는가? |
| 평균 주문액 | 순매출 ÷ 주문 수 | 한 주문에서 얼마를 구매하는가? |
| 고객 획득비용 | 신규 획득비용 ÷ 신규 고객 수 | 고객 한 명을 확보하는 데 얼마가 드는가? |
| 광고수익률 | 광고 기여 매출 ÷ 광고비 | 광고비 대비 매출은 얼마인가? |
| 반품률 | 반품 주문상품 ÷ 구매 주문상품 | 구매 후 불일치가 얼마나 발생하는가? |
| 공헌이익 | 순매출에서 변동비 차감 | 매출이 실제 사업 가치로 남는가? |

### 전환율은 분모를 먼저 확인한다

\[
\text{구매 전환율}=\frac{\text{구매 고객 또는 구매 세션}}{\text{방문 고객 또는 전체 세션}}
\]

고객 기준과 세션 기준은 서로 다른 값을 만든다. 신규 방문만 포함할지, 앱과 웹을 합칠지, 구매를 결제 완료와 구매 확정 중 무엇으로 정의할지도 명시한다.

전환율이 높아져도 좋은 결과라고 단정할 수 없다. 과도한 할인으로 구매율이 증가하면서 공헌이익이 감소하거나, 자극적인 상세페이지로 구매가 늘면서 반품률·문의율이 높아질 수 있다. 구매 전환율을 **주 지표**로 삼더라도 반품률·공헌이익·페이지 속도·고객 불만을 **보호 지표**로 함께 본다.

## 4. 분류 평가는 Accuracy 하나로 끝나지 않는다

Accuracy는 가장 널리 알려지고 이해하기 쉬운 지표이지만 항상 가장 중요한 지표는 아니다. 먼저 예측과 실제 결과를 혼동행렬로 나눈다.

| 실제/예측 | 위험으로 예측 | 정상으로 예측 |
|---|---:|---:|
| 실제 위험 | TP: 올바르게 찾음 | FN: 놓침 |
| 실제 정상 | FP: 잘못 경보 | TN: 올바르게 통과 |

### Accuracy: 전체에서 맞힌 비율

\[
Accuracy=\frac{TP+TN}{TP+TN+FP+FN}
\]

주문 1,000건 중 부정 주문이 10건뿐일 때 모든 주문을 정상으로 예측해도 Accuracy는 99%다. 그러나 위험 주문을 하나도 찾지 못하므로 업무에는 쓸 수 없다.

### Precision: 경보 가운데 실제 위험의 비율

\[
Precision=\frac{TP}{TP+FP}
\]

Precision이 높으면 모델이 위험하다고 표시한 후보를 사람이 검토할 때 불필요한 조사가 적다. 정상 고객에게 경고·확인 절차를 요구하는 비용이 클수록 중요하다.

### Recall: 실제 위험 가운데 찾아낸 비율

\[
Recall=\frac{TP}{TP+FN}
\]

Recall이 높으면 실제 위험 주문을 덜 놓친다. 사기·안전 문제처럼 놓침의 손실이 클 때 중요하지만, 임곗값을 너무 낮추면 정상 주문 경보가 많아질 수 있다.

### 함께 볼 지표

- **F1-score**는 Precision과 Recall의 조화평균이다.
- **Specificity**는 실제 정상 가운데 정상으로 통과시킨 비율이다.
- **PR-AUC**는 희소한 위험 사례에서 Precision–Recall의 전반적 균형을 본다.
- **Calibration**은 70%로 예측한 사례가 실제로 약 70% 발생하는지 본다.

어떤 지표가 가장 중요한지는 오류 비용과 행동에 따라 달라진다. 반품 안내를 추가하는 일과 정상 주문을 자동 차단하는 일은 같은 임곗값을 사용할 수 없다.

```python
from sklearn.metrics import accuracy_score, precision_score, recall_score, f1_score

y_true = [0, 0, 0, 0, 1, 1, 0, 1, 0, 0]
y_pred = [0, 0, 0, 1, 1, 0, 0, 1, 0, 0]

print(f"Accuracy:  {accuracy_score(y_true, y_pred):.2f}")
print(f"Precision: {precision_score(y_true, y_pred):.2f}")
print(f"Recall:    {recall_score(y_true, y_pred):.2f}")
print(f"F1-score:  {f1_score(y_true, y_pred):.2f}")
```

```output
Accuracy:  0.80
Precision: 0.67
Recall:    0.67
F1-score:  0.67
```

## 5. 회귀 평가는 오차의 크기와 방향을 본다

판매량·주문액처럼 연속적인 수치를 예측할 때는 정답/오답이 자연스럽게 나뉘지 않는다.

### MAE: 평균적으로 얼마나 틀렸는가

\[
MAE=\frac{1}{n}\sum_{i=1}^{n}|y_i-\hat y_i|
\]

판매량 예측의 MAE가 7.4개라면 상품·기간 하나당 평균적으로 약 7.4개 차이가 났다는 뜻이다. 원래 단위로 표현되어 이해하기 쉽다.

### 함께 볼 회귀 지표

- **RMSE**는 큰 오류에 더 큰 벌점을 준다.
- **WAPE**는 전체 실제 규모에 대한 절대오차 비율을 본다.
- **MASE**는 단순 시계열 기준선보다 얼마나 나은지 비교한다.
- **Bias**는 계속 과대 또는 과소예측하는지 본다.
- **예측구간 포함률**은 실제 값이 제시한 불확실성 범위 안에 들어오는 비율이다.

### 연속 예측을 ‘정확도’처럼 설명할 때의 장점과 함정

현장에서는 “실제 판매량과 예측량의 차이가 ±10개 이내이면 정답”처럼 허용 기준을 정하고 **허용오차 내 적중률**을 제시하기도 한다.

\[
\text{허용오차 내 적중률}=\frac{|\hat y-y|\leq 10\text{인 예측 수}}{\text{전체 예측 수}}
\]

“예측의 78%가 ±10개 안에 들어왔다”는 표현은 MAE보다 직관적일 수 있다. 그러나 이것은 MAE를 Accuracy로 변환한 값이 아니라 **새 임곗값을 적용해 만든 별도의 지표**다.

- 오차 10개와 11개가 거의 비슷해도 정답과 오답으로 갈린다.
- 오차 11개와 100개가 모두 같은 오답이 되어 심각도가 사라진다.
- 하루 5개 판매 상품과 1,000개 판매 상품에 ±10개는 다른 의미다.
- 허용 범위를 넓히면 적중률을 쉽게 높일 수 있다.
- 과대예측과 과소예측의 재고 비용 차이가 감춰진다.

따라서 MAE·WAPE 또는 MASE·Bias·예측구간과 허용오차 내 적중률을 함께 보고, 허용 기준을 왜 그렇게 정했는지 재고·품절 비용으로 설명한다.

```python
import numpy as np

actual = np.array([40, 75, 120, 18, 210])
predicted = np.array([46, 61, 127, 25, 184])
error = predicted - actual

mae = np.abs(error).mean()
within_10 = (np.abs(error) <= 10).mean()
bias = error.mean()

print(f"MAE: {mae:.1f}개")
print(f"±10개 이내 적중률: {within_10:.0%}")
print(f"Bias: {bias:.1f}개")
```

```output
MAE: 12.0개
±10개 이내 적중률: 60%
Bias: -4.0개
```

## 6. 단순한 기준선과 먼저 비교한다

복잡한 분석은 단순 기준선보다 실질적으로 좋아야 한다.

- 판매량 예측: 지난주 값, 같은 요일 평균
- 분류: 가장 흔한 범주, 단순 업무 규칙
- 군집: 기존 RFM 세그먼트
- 이상치: 허용 범위 규칙과 이동 중앙값
- 추천 패턴: 인기 상품 순위

성능 차이가 작다면 개발·운영·설명·검증 비용까지 포함해 단순한 방법이 더 나을 수 있다.

## 7. 학습·검증·테스트·운영 데이터를 나눈다

- **학습 데이터**는 모델의 파라미터를 맞춘다.
- **검증 데이터**는 모델·특징·임곗값을 선택한다.
- **테스트 데이터**는 선택이 끝난 뒤 최종 성능을 확인한다.
- **운영 데이터**는 배포 후 실제 비용·지연·드리프트와 행동 결과를 본다.

패션 수요는 시간에 따라 변하므로 과거로 학습하고 이후 기간으로 검증하는 것이 자연스럽다. 같은 고객·상품이 학습과 테스트에 동시에 들어가면 실제 새 고객·상품보다 쉬운 평가가 될 수 있다.

테스트 결과를 보고 계속 모델을 수정하면 테스트 데이터도 사실상 검증 데이터가 된다. 최종 확인용 데이터를 다시 분리해야 한다.

## 8. 불확실성을 함께 보고한다

표본에서 계산한 차이와 모델 성능은 데이터가 달라지면 흔들린다. 점 하나만 보고하지 않는다.

- 효과 크기와 신뢰구간
- 표본 수와 발생 건수
- 기간·상품·고객군별 변화
- 회귀의 예측구간 또는 분위수
- 분류 확률의 보정 상태
- 전처리와 가정에 따른 민감도

p-value는 효과가 클 확률이나 결과가 우연일 확률이 아니다. 귀무가설과 분석 가정 아래 현재 이상으로 극단적인 데이터를 관찰할 확률이다. p-value가 작아도 효과가 너무 작으면 사업 가치가 없고, 크더라도 표본이 작아 구간이 넓다면 “효과 없음”으로 단정할 수 없다.

## 9. 관계와 인과효과를 구분한다

사이즈표를 본 고객의 반품률이 낮아도 사이즈표가 원인이라고 단정할 수 없다. 신중한 고객이 사이즈표도 더 많이 보고 원래 반품도 적게 했을 수 있다.

인과 질문은 **같은 조건에서 한 요소를 바꾸었을 때 결과가 얼마나 달라지는가**를 묻는다. 온라인에서는 무작위 A/B 테스트가 강력한 방법이다.

1. 가설과 최소 의미 효과를 미리 정한다.
2. 고객이나 세션을 무작위로 처리군과 대조군에 배정한다.
3. 한 요소만 다르게 적용한다.
4. 구매율 같은 주 지표와 반품·속도·문의 같은 보호 지표를 함께 본다.
5. 기간·표본·중단 규칙을 사전에 정한다.
6. 효과 크기·신뢰구간·비용으로 실행 여부를 판단한다.

실험할 수 없는 날씨·정책·경쟁사 행동은 자연실험, 시계열 비교와 회귀 조정을 검토할 수 있지만 측정하지 못한 교란 가능성을 명시한다.

## 10. Python으로 전환율 차이를 읽는다

```python
import math

purchase_a, visitor_a = 60, 1000
purchase_b, visitor_b = 56, 800

rate_a = purchase_a / visitor_a
rate_b = purchase_b / visitor_b
effect = rate_b - rate_a
se = math.sqrt(
    rate_a * (1 - rate_a) / visitor_a
    + rate_b * (1 - rate_b) / visitor_b
)

ci_low = effect - 1.96 * se
ci_high = effect + 1.96 * se

print(f"A 구매율: {rate_a:.1%}")
print(f"B 구매율: {rate_b:.1%}")
print(f"절대 차이: {effect * 100:.1f}%p")
print(f"95% 구간: [{ci_low * 100:.1f}, {ci_high * 100:.1f}]%p")
```

```output
A 구매율: 6.0%
B 구매율: 7.0%
절대 차이: 1.0%p
95% 구간: [-1.3, 3.3]%p
```

B가 1%포인트 높지만 구간에 0이 포함되고 불확실성이 크다. “B가 확실히 낫다”보다 현재 데이터와 필요한 추가 표본을 설명한다.

## 11. 편향과 빠진 대상을 점검한다

데이터는 현실 전체가 아니라 측정 파이프라인을 거친 기록이다.

- 앱 사용자만 포함되어 웹 고객이 빠지지 않았는가?
- 리뷰 작성자의 의견을 전체 구매자 의견으로 확대하지 않았는가?
- 구매 가능한 재고가 있던 상품만 성과가 관측되지 않았는가?
- 생존한 고객만 분석해 이탈 고객의 경험을 놓치지 않았는가?
- 모델 성능이 특정 사이즈·성별·지역에서 크게 낮지 않은가?

리뷰 작성자 50명 중 40명이 긍정이어도 구매자 100명 전체의 긍정률이 80%라고 말할 수 없다. 작성하지 않은 50명의 의견은 관측되지 않았다.

유리한 기간·집단·지표만 선택하는 체리피킹을 막기 위해 제외 규칙과 분석 변경 이력을 남긴다.

## 12. 재현성과 증거의 계보를 남긴다

다른 사람이 같은 원본과 코드로 같은 결과를 만들 수 있어야 한다.

- 원자료 출처·버전과 수집 기간
- 컬럼 정의, 시간대와 통화 단위
- 제외·결측·중복·이상값 처리 규칙
- 사용한 코드·패키지·모델 버전
- 무작위 시드와 데이터 분할 기준
- 분석 중 변경한 가설과 이유
- 결과를 승인한 사람과 날짜

생성형 AI가 만든 코드와 설명도 동일하게 검증한다. 실행된다는 사실은 계산과 해석이 옳다는 증거가 아니다.

## 13. 업무 가치·비용·보호 지표를 함께 본다

정확도가 높아도 사용할 가치가 없을 수 있다.

- 품절·재고·반품 비용이 실제로 줄었는가?
- 분석가의 정제·검토 시간과 API·컴퓨팅 비용은 얼마인가?
- 결과가 의사결정 시점 안에 도착하는가?
- 고객 경험·공정성·개인정보에 피해가 없는가?
- 사람이 검토할 수 있는 업무량인가?
- 잘못된 자동화가 발생하면 중단하고 되돌릴 수 있는가?

하나의 지표가 목표가 되면 그 지표만 좋아지도록 행동이 왜곡될 수 있다는 **Goodhart의 법칙**을 기억한다. 클릭률을 높이면서 구매 만족과 장기 신뢰를 낮추지 않도록 주 지표와 보호 지표를 함께 둔다.

## 분석 파트 종합 실습

패션 업무 질문 하나를 선택해 한 페이지 분석 평가서를 작성한다.

- 사용할 다섯 분석 방법 중 하나와 선택 이유
- 가설, 분석 단위와 전처리 규칙
- 단순 기준선과 평가 지표
- 표본 밖 일반화의 한계와 편향 후보
- 연관 또는 인과 중 주장 가능한 범위
- 실행할 행동, 보호 지표와 중단 조건

<div class="lesson-section-box lesson-activity-box"><strong>짧은 활동</strong></div>

분류·회귀·군집·이상치 감지 가운데 하나를 선택한다. 단순 기준선, 주 평가 지표, 효과 크기 또는 오차 범위, 확인할 편향, 보호 지표와 중단 조건을 여섯 줄로 작성한다. 결과가 좋아 보여도 적용하지 않을 조건을 최소 하나 포함한다.

<div class="lesson-section-box lesson-summary-box"><strong>이 장의 핵심</strong></div>

- 평가는 질문 적합성, 방법별 품질, 불확실성, 인과, 편향과 업무 가치를 함께 본다.
- 방법마다 좋은 결과를 판단하는 기준이 다르다.
- 전환율을 비롯한 그로스 지표는 분자·분모·기간과 보호 지표를 함께 정의한다.
- Accuracy는 이해하기 쉽지만 희소한 사건에서는 높아도 쓸모없을 수 있어 Precision·Recall과 함께 본다.
- 연속 예측은 MAE·규모 보정 오차·Bias와 허용오차 내 적중률을 함께 사용한다.
- 복잡한 방법은 단순 기준선보다 의미 있게 좋아야 한다.
- 학습·검증·테스트·운영 데이터를 목적에 따라 분리한다.
- 효과 크기와 구간을 보고 p-value만으로 판단하지 않는다.
- 연관·예측 결과와 인과효과를 구분한다.
- 재현성, 고객 영향, 총비용과 중단 조건까지 포함해야 분석이 의사결정 근거가 된다.

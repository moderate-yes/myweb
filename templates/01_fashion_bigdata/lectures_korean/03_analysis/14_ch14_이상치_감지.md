# Anomaly Detection

## 학습 목표

이상치 감지는 정상적인 범위나 주변 관측과 크게 다른 값을 찾는다. 패션 비즈니스에서는 판매 급증, 비정상 반품, 가격 오류, 중복 결제와 데이터 수집 장애를 빠르게 발견하는 데 사용할 수 있다. 이상치는 오류와 같은 말이 아니며, **평소와 다른 이유를 확인해야 하는 관측**이다.

이 장을 마치면 다음을 할 수 있다.

- 이상치·이벤트·오류를 구분한다.
- 목적과 분석 단위에 맞는 기준선을 만든다.
- 전역 통계(z-score·IQR·MAD), 이동 기준선, 시계열 분해 잔차, 변화점, 다변량 밀도 기반 방법의 원리를 설명한다.
- 각 방법이 어떤 이상치를 잡고 어떤 이상치를 놓치는지 비교한다.
- Python으로 일별 판매량과 주문 기록의 이상치를 단계별로 탐지한다.
- 경보의 정확도뿐 아니라 조사 비용과 놓침 비용을 평가한다.
- GA4와 Amplitude의 이상치 감지 기능이 내부적으로 어떤 방법을 쓰는지 이해한다.

## 1. 무엇이 이상한지는 맥락에 달려 있다

하루 판매량 30개가 신상품에는 정상일 수 있지만 평소 1개 팔리는 상품에는 큰 변화다. 겨울 패딩 판매 증가는 12월에는 정상이고 7월에는 확인이 필요하다.

이상치의 기준은 다음에 따라 달라진다.

- 상품·카테고리·매장·지역 등 비교 단위
- 요일·계절·시간대
- 가격·광고·재고·프로모션
- 신상품과 기존 상품의 수명주기
- 분석 목적과 잘못된 경보의 비용

전체 판매량 평균 하나보다 같은 상품의 과거, 비슷한 상품군과 동일 시즌을 기준으로 비교한다.

## 2. 이상치는 네 가지 원인 후보를 가진다

- **실제 변화**: 유행, 인플루언서 노출, 날씨와 입소문으로 수요가 변했을 수 있다.
- **계획된 운영 변화**: 광고·할인·재입고·기획전 때문에 예상된 변화일 수 있다.
- **거래 또는 고객 행동**: 단체 주문, 반복 반품, 자동 구매와 부정 결제일 수 있다.
- **데이터 오류**: 중복 수집, 통화 단위 오류, 시간대 변환, 누락 복구와 JOIN 증폭일 수 있다.

따라서 탐지 결과에는 판매·재고·광고·가격·시스템 로그를 함께 연결할 수 있어야 한다.

## 3. 이상치 감지 방법 한눈에 보기

| 방법 | 원리 | 잡는 이상치 | 놓치기 쉬운 것 |
|---|---|---|---|
| 규칙 기반 | 업무 규칙 위반을 조건문으로 검사 | 음수 수량, 허용 범위 밖 할인율 | 규칙에 없는 새로운 유형 |
| 전역 통계(z-score·IQR·MAD) | 전체 분포에서 멀리 떨어진 값 | 극단적인 하루 | 계절·추세 안의 국소적 이상 |
| 이동 기준선 | 최근 구간의 중앙값·분위수와 비교 | 평소 수준 대비 급증·급감 | 서서히 변하는 추세 |
| 시계열 분해 잔차(STL) | 추세·계절을 제거한 잔차의 크기 | 요일 패턴을 감안한 이상 | 분해 주기를 잘못 정하면 오경보 |
| 예측 잔차(Prophet·상태공간) | 예측 구간 밖의 실제값 | GA4·Amplitude가 쓰는 방식 | 학습 기간의 이상이 기준선을 오염 |
| 변화점 탐지(PELT) | 평균·분산이 지속적으로 바뀐 시점 | 채널 추가, 가격 정책 변경 | 하루짜리 급증 |
| 다변량 밀도(Isolation Forest·LOF) | 여러 변수 조합이 드문 관측 | 금액은 정상인데 수량·시간이 드문 주문 | 어떤 변수 때문인지 설명이 어려움 |
| 지도학습 분류 | 과거 확인된 이상 라벨로 학습 | 반복되는 부정 결제 유형 | 라벨이 없거나 새로운 유형 |

복잡한 모델이 항상 좋은 것은 아니다. 원인을 설명하고 대응해야 하는 업무에서는 단순 기준선이 더 유용할 수 있다. 실무에서는 규칙 → 통계 기준선 → 시계열 방법 → 다변량 방법 순으로 쌓는다.

## 4. 원리: 전역 통계 기준선

### z-score

\[
z=\frac{x-\mu}{\sigma}
\]

`|z|`가 3보다 크면 평균에서 표준편차 3배 이상 떨어진 값이다. 정규분포에 가까운 안정적 데이터에서는 이해하기 쉽지만, 평균과 표준편차 자체가 극단값에 끌려간다. 큰 이상치 하나가 표준편차를 키워 다른 이상치를 가리는 **masking**이 생긴다.

### IQR

\[
IQR=Q_3-Q_1
\]

`Q1 - 1.5×IQR`보다 작거나 `Q3 + 1.5×IQR`보다 큰 값을 후보로 표시한다. 분위수는 극단값의 영향을 덜 받는다. 1.5라는 값도 모든 업무의 정답은 아니다.

### MAD 기반 robust z-score

\[
MAD=\text{median}(|x_i-\text{median}(x)|),\qquad z_{robust}=\frac{0.6745\,(x-\text{median}(x))}{MAD}
\]

중앙값과 중앙절대편차(MAD)는 데이터의 절반이 오염될 때까지 버틴다. 0.6745는 정규분포에서 MAD를 표준편차 척도로 맞추는 상수이며, 보통 `|z_robust| > 3.5`를 기준으로 쓴다. 판매량처럼 0이 많고 한쪽으로 긴 분포에서는 z-score보다 MAD를 먼저 검토한다.

세 방법 모두 **전체 기간을 하나의 분포**로 보기 때문에 계절과 추세가 있는 데이터에서는 성수기 정상값을 이상치로, 비수기의 급증을 정상으로 판단할 수 있다.

## 5. 원리: 시간 데이터의 이동 기준선과 분해

### 이동 기준선

판매량은 추세와 계절성이 있으므로 최근 구간의 이동 중앙값과 이동 MAD를 기준선으로 쓴다. 오늘 값을 기준선 계산에서 제외(`shift(1)`)하지 않으면 큰 값이 스스로 기준선을 끌어올려 이상 정도가 작아진다.

### STL 분해

STL은 시계열을 **추세 + 계절 + 잔차**로 나눈다. 요일 주기(`period=7`)를 지정하면 주말 증가가 계절 성분으로 빠지고, 잔차에는 설명되지 않는 변동만 남는다. 잔차에 MAD 기준을 적용하면 "이번 토요일이 보통 토요일보다 얼마나 다른가"를 묻게 된다.

### 예측 잔차

Prophet, 상태공간 모형, 회귀 모형으로 예측값과 예측 구간을 만들고 실제값이 구간 밖이면 이상으로 본다. GA4의 이상치 감지는 베이지안 상태공간 시계열 모형의 신뢰구간을, Amplitude의 Anomaly + Forecast는 Prophet 기반 예측 구간을 사용한다. 두 도구 모두 학습 기간의 이상치가 예측을 오염시킬 수 있으므로 학습 기간 선택이 중요하다.

## 6. 원리: 변화점 탐지

하루짜리 급증과 달리 **수준 자체가 바뀐 시점**을 찾는 문제다. PELT 알고리즘은 시계열을 구간으로 나눌 때 구간별 비용(예: 평균과의 차이 제곱합)의 합에 구간 수에 따른 벌점을 더한 값을 최소화한다. 벌점이 작으면 변화점이 많아지고, 크면 큰 변화만 남는다. 새 판매 채널 입점, 가격 정책 변경, 트래킹 코드 교체 시점을 찾는 데 쓴다.

## 7. 원리: 다변량 이상치

### Isolation Forest

무작위로 변수와 분할값을 골라 데이터를 쪼개는 나무를 여러 개 만든다. 드문 관측은 몇 번만 쪼개도 혼자 남으므로 **분리에 필요한 평균 깊이가 짧다**. 깊이가 짧을수록 이상 점수가 높다. 변수가 많고 데이터가 클 때 빠르며 분포 가정이 없다.

### Local Outlier Factor(LOF)

각 관측의 주변 밀도를 k개 이웃의 밀도와 비교한다. 자기 밀도가 이웃보다 훨씬 낮으면(LOF ≫ 1) 국소적 이상치다. 고가 상품군 안에서는 정상인 금액이 저가 상품군 안에서는 이상일 수 있는 것처럼 **군집별로 밀도가 다른** 데이터에 적합하다.

### DBSCAN의 노이즈

앞 장의 DBSCAN·HDBSCAN이 `-1`로 남긴 관측은 어느 밀집 영역에도 속하지 않는 다변량 이상치 후보다.

거리와 밀도를 쓰는 방법은 모두 **척도**의 영향을 받는다. 시간(0~23)과 로그 금액(10~13)을 그대로 넣으면 시간이 거리를 지배하므로 표준화가 먼저다.

## 8. 단계별 실습: Python으로 이상치를 찾는다

정답을 아는 가상 데이터에 이상치를 심어 두고 각 방법이 무엇을 잡는지 비교한다. 실제 업무에서는 정답이 없으므로 이 비교가 방법을 고르는 근거가 된다.

### 1단계: 추세·요일·계절이 있는 일별 판매량에 이상치를 심는다

```python
import numpy as np
import pandas as pd

pd.set_option("display.width", 120)
pd.set_option("display.max_columns", 12)

rng = np.random.default_rng(14)
dates = pd.date_range("2025-01-01", "2025-12-31", freq="D")
n = len(dates)

trend = np.linspace(20, 32, n)
weekly = np.where(dates.dayofweek >= 5, 8, 0)          # 주말 증가
season = 10 * np.sin((dates.dayofyear - 300) / 365 * 2 * np.pi)  # 겨울 성수기
noise = rng.normal(0, 3, n)
sales = np.clip(trend + weekly + season + noise, 0, None).round()

daily = pd.DataFrame({"date": dates, "sales_qty": sales, "label": "normal"})

promo = daily["date"].between("2025-05-01", "2025-05-05")      # 기획전 5일
daily.loc[promo, "sales_qty"] = (daily.loc[promo, "sales_qty"] * 2.4).round()
daily.loc[promo, "label"] = "promo"

outage = daily["date"] == "2025-07-19"                           # 수집 장애로 0
daily.loc[outage, ["sales_qty", "label"]] = [0, "outage"]

duplicate = daily["date"] == "2025-08-23"                        # 중복 적재로 2배
daily.loc[duplicate, "sales_qty"] *= 2
daily.loc[duplicate, "label"] = "duplicate"

shift = daily["date"] >= "2025-10-01"                            # 입점 채널 추가로 수준 변화
daily.loc[shift, "sales_qty"] = (daily.loc[shift, "sales_qty"] * 1.35).round()
daily.loc[daily["date"] == "2025-10-01", "label"] = "level_shift"

print(daily["label"].value_counts())
```

```output
label
normal         357
promo            5
outage           1
duplicate        1
level_shift      1
Name: count, dtype: int64
```

### 2단계: z-score

```python
x = daily["sales_qty"]
daily["z"] = (x - x.mean()) / x.std()
daily["flag_z"] = daily["z"].abs() > 3
print(daily.loc[daily["flag_z"], ["date", "sales_qty", "z", "label"]].round(2))
```

```output
          date  sales_qty     z  label
122 2025-05-03       74.0  3.15  promo
123 2025-05-04       86.0  4.06  promo
```

### 3단계: IQR

```python
q1, q3 = x.quantile([0.25, 0.75])
iqr = q3 - q1
daily["flag_iqr"] = (x < q1 - 1.5 * iqr) | (x > q3 + 1.5 * iqr)
print(f"Q1={q1:.0f}, Q3={q3:.0f}, IQR={iqr:.0f}, 상한={q3 + 1.5 * iqr:.0f}")
print(daily.loc[daily["flag_iqr"], ["date", "sales_qty", "label"]])
```

```output
Q1=22, Q3=40, IQR=18, 상한=67
          date  sales_qty   label
122 2025-05-03       74.0   promo
123 2025-05-04       86.0   promo
346 2025-12-13       68.0  normal
```

### 4단계: MAD 기반 robust z-score

```python
median = x.median()
mad = (x - median).abs().median()
daily["robust_z"] = 0.6745 * (x - median) / mad
daily["flag_mad"] = daily["robust_z"].abs() > 3.5
print(f"중앙값={median:.0f}, MAD={mad:.0f}")
print(daily.loc[daily["flag_mad"], ["date", "sales_qty", "robust_z", "label"]].round(2))
```

```output
중앙값=29, MAD=8
          date  sales_qty  robust_z  label
122 2025-05-03       74.0      3.79  promo
123 2025-05-04       86.0      4.81  promo
```

세 전역 방법은 기획전 중 가장 큰 이틀만 잡았다. 수집 장애(0개)와 중복 적재는 전체 분포 안에서는 특별히 극단적이지 않고, IQR은 12월 성수기의 정상 판매를 이상으로 표시했다. 계절이 있는 데이터에서 전역 기준선의 한계다.

### 5단계: 이동 중앙값·이동 MAD 기준선

```python
past = x.shift(1)
daily["baseline"] = past.rolling(28, min_periods=14).median()
daily["baseline_mad"] = past.rolling(28, min_periods=14).apply(
    lambda s: np.median(np.abs(s - np.median(s))), raw=True
)
daily["rolling_score"] = 0.6745 * (x - daily["baseline"]) / daily["baseline_mad"].replace(0, np.nan)
daily["flag_rolling"] = daily["rolling_score"].abs() > 3.5
print(daily.loc[daily["flag_rolling"], ["date", "sales_qty", "baseline", "rolling_score", "label"]].round(1))
```

### 6단계: STL 분해 잔차

```python
from statsmodels.tsa.seasonal import STL

stl = STL(daily.set_index("date")["sales_qty"], period=7, robust=True).fit()
resid = stl.resid
resid_mad = (resid - resid.median()).abs().median()
daily["stl_score"] = (0.6745 * (resid - resid.median()) / resid_mad).values
daily["flag_stl"] = daily["stl_score"].abs() > 3.5
print(daily.loc[daily["flag_stl"], ["date", "sales_qty", "stl_score", "label"]].round(1))
```

### 8단계: 주문 단위 다변량 이상치

```python
m = 2000
orders = pd.DataFrame({
    "amount": rng.lognormal(np.log(120_000), 0.5, m).round(-3),
    "quantity": rng.choice([1, 1, 1, 2, 2, 3], m),
    "hour": rng.choice(range(24), m, p=np.r_[np.full(6, 0.01), np.full(18, (1 - 0.06) / 18)]),
    "discount_rate": rng.choice([0, 0.1, 0.2, 0.3], m, p=[0.5, 0.25, 0.15, 0.1]),
    "label": "normal",
})
injected = pd.DataFrame({
    "amount": [95_000, 4_800_000, 60_000, 130_000],
    "quantity": [40, 1, 1, 2],
    "hour": [3, 14, 4, 15],
    "discount_rate": [0, 0, 0.9, 0.3],
    "label": ["bulk_night", "price_error", "discount_error", "normal_like"],
})
orders = pd.concat([orders, injected], ignore_index=True)

from sklearn.preprocessing import StandardScaler
from sklearn.ensemble import IsolationForest
from sklearn.neighbors import LocalOutlierFactor

features = orders[["amount", "quantity", "hour", "discount_rate"]].copy()
features["amount"] = np.log1p(features["amount"])
scaled = StandardScaler().fit_transform(features)

iso = IsolationForest(contamination=0.005, random_state=0).fit(scaled)
orders["iso_score"] = -iso.score_samples(scaled)
orders["flag_iso"] = iso.predict(scaled) == -1

lof = LocalOutlierFactor(n_neighbors=30, contamination=0.005)
orders["flag_lof"] = lof.fit_predict(scaled) == -1
orders["lof_score"] = -lof.negative_outlier_factor_

orders["iso_rank"] = orders["iso_score"].rank(ascending=False).astype(int)
cols = ["amount", "quantity", "hour", "discount_rate", "iso_score", "iso_rank", "flag_iso", "flag_lof", "label"]
print(orders.sort_values("iso_score", ascending=False).head(6)[cols].round(2))
print(orders[orders["label"] != "normal"][cols].round(2))
```

두 방법의 결과가 다르다. LOF는 심어 둔 세 건(새벽 대량 주문, 가격 오류, 할인율 오류)을 모두 잡았고, Isolation Forest는 세 건을 상위 5% 안에 두었지만 0.5% 경보에는 넣지 않았다. 대신 Isolation Forest 상위에는 `할인 30%·수량 3·새벽`처럼 각 값은 정상이지만 조합이 드문 주문이 올라왔다. 2,000건 중 이런 조합은 2건 안팎이므로 통계적으로는 분명히 드물다. 다변량 방법이 찾는 것은 **드묾**이지 **문제**가 아니다. 어떤 드묾이 조사할 가치가 있는지는 사람이 정한다.

`contamination`은 "상위 몇 %를 경보로 볼 것인가"이며 데이터가 알려주는 값이 아니다. 하루에 조사할 수 있는 건수에서 거꾸로 정한다. 심어 둔 `normal_like` 주문은 정상 범위 안에 있으므로 두 방법 모두 잡지 않는 것이 맞다.

### 9단계: 방법별 경보 수와 적중률을 비교한다

```python
truth = daily["label"].isin(["promo", "outage", "duplicate"])
for name in ["flag_z", "flag_iqr", "flag_mad", "flag_rolling", "flag_stl"]:
    flagged = daily[name].fillna(False)
    tp = (flagged & truth).sum()
    precision = tp / flagged.sum() if flagged.sum() else 0
    recall = tp / truth.sum()
    print(f"{name:13s} 경보 {flagged.sum():3d}건  precision={precision:.2f}  recall={recall:.2f}")
```

같은 데이터에서도 방법에 따라 경보 수와 적중률이 크게 다르다. 실제 업무에서는 정답 라벨이 없으므로 과거에 확인된 사건 몇 개를 정답 삼아 이런 표를 만들고, 조사 가능한 경보 수 안에서 recall이 가장 높은 방법을 고른다.

## 10. 이상치 제거와 이상치 감지를 구분한다

모델 학습을 방해하는 오류를 제거하는 것은 전처리다. 비정상 사건을 찾아 대응하는 것은 분석 목적이다.

- 가격 입력 오류가 확인되면 수정하거나 제외한다.
- 실제 대량 주문이면 유지하고 별도 유형으로 표시한다.
- 판매 급증 탐지가 목적이면 큰 값을 미리 제거하지 않는다.
- 한 결과가 이상값 처리에 따라 크게 바뀌면 두 결과를 함께 보고한다.

극단값을 삭제하면 평균이 안정될 수 있지만 중요한 고객·상품·위험 신호도 사라질 수 있다.

## 11. 경보 시스템을 평가한다

경보는 많이 울리는 것이 목적이 아니다.

- 실제 문제 가운데 얼마나 찾았는가?(recall)
- 경보 가운데 실제로 조치할 가치가 있는 비율은 얼마인가?(precision)
- 하루에 사람이 검토할 수 있는 경보 수는 몇 개인가?
- 놓친 문제와 불필요한 조사 중 어느 비용이 더 큰가?
- 문제 발생부터 경보까지 지연시간은 얼마인가?
- 같은 원인으로 반복되는 경보를 묶을 수 있는가?

임곗값을 낮추면 더 많이 찾지만 조사 비용과 경보 피로가 커진다. 운영 가능한 조사량과 피해 비용을 기준으로 정한다.

## 12. 평균으로의 회귀를 주의한다

매우 높은 판매량 다음 날 값이 낮아지는 것은 특별한 조치를 해서가 아니라 우연한 극단값이 평소 수준으로 돌아오는 **평균으로의 회귀**일 수 있다. 급등 상품에 조치를 적용한 뒤 판매가 낮아졌다는 사실만으로 조치 효과를 단정하지 않는다. 비슷한 비교 상품이나 이전 패턴을 함께 본다.

- GA4와 Amplitude의 이상치 감지는 예측 구간 밖의 값을 표시하는 예측 잔차 방식이다.
- 경보의 품질은 탐지율뿐 아니라 조사 비용·지연·경보 피로로 평가한다.

# Cart and Wishlist Analysis

## 학습 목표

찜과 장바구니는 같은 관심 버튼이 아니라 구매 의도의 서로 다른 상태다. 두 이벤트를 같은 고객·상품·시간축에 놓으면 관심이 준비와 구매로 이동하는 과정을 분석할 수 있다.

이 장을 마치면 다음을 할 수 있다.

- 찜 이벤트의 스키마(상품·위치·시각·세션·고객)를 설계하고 장바구니와의 의도 차이를 설명한다.
- 찜 사용 세션과 미사용 세션의 결과를 비교하고 그 차이가 인과가 아닌 이유를 말한다.
- 찜 → 구매 전환율과 소요 시간 분포를 고객 단위로 계산한다.
- 찜은 많으나 구매가 적은 상품을 찾아 가격·재고·정보 문제로 나눈다.
- 찜 데이터를 퍼널·추천·트리거 알림·할인 후보에 연결하는 시스템을 그린다.

찜과 장바구니는 모두 구매 전 행동이지만 의도의 강도와 고객 기대가 다르다. 찜은 관심을 오래 저장하고 비교하려는 신호이고, 장바구니는 옵션·수량을 정해 구매에 더 가까이 간 신호다. 두 기능을 따로 최적화하면 찜을 장바구니처럼 재촉하거나 장바구니를 단순 관심 목록처럼 오해할 수 있다. 이 장은 두 데이터를 하나의 **의도 사다리**로 분석한다.


## 개념부터 시작하기

상태를 `조회→찜→장바구니→구매`로 두고 전이 확률 \(P(S_{t+1}=j\mid S_t=i)\)과 전환까지의 시간을 계산한다. 찜 수가 많은 상품은 인기도가 높을 수도 있고 가격·재고·핏 정보 때문에 구매가 막힌 상품일 수도 있다.

조회수와 인기순을 기준선으로 둔다. 찜과 장바구니 가중치는 미래 구매 예측으로 검증하고, 알림은 새 정보가 있을 때만 보내며 수신 거부·반복 발송·품절 노출을 가드레일로 관리한다.

## 문제 설정: 관심에서 구매 준비까지

장바구니는 "살 준비"이고 찜은 "관심"이다. 둘을 같은 흐름에서 비교하면 고객은 부담 없이 의도를 남기고, 쇼핑몰은 구매 준비의 강도를 구분할 수 있다. 찜 목록은 고객에게는 나중에 다시 찾는 도구, 쇼핑몰에게는 재입고·가격 인하·재방문 알림의 근거다. 31장의 퍼널 분석에서 상품 조회 → 장바구니 전환율이 가장 낮았다. 찜은 그 사이의 이탈을 붙잡는 장치다.

## 2. 모형과 계산 원리

### 찜과 장바구니를 같은 표에서 비교하기

| 구분 | 찜(Wishlist) | 장바구니(Cart) |
|---|---|---|
| 주된 의미 | 관심 저장·나중 비교 | 옵션·수량을 정한 구매 준비 |
| 시간 범위 | 여러 세션·수일~수개월 | 같은 세션 또는 짧은 기간 |
| 필요한 이벤트 | add/remove_wishlist | add/remove_cart, begin_checkout |
| 핵심 지표 | 30일 찜→구매, 재방문 | 장바구니→결제, 이탈률, 회복 구매 |
| 도움 되는 서비스 | 가격·재입고·신상품 알림 | 재고·배송비·쿠폰 오류·결제 복구 |
| 주의점 | 관심을 구매 의도로 과대평가 | 저장 용도로 쓰는 고객도 존재 |

분석 단위는 `customer_id × product_id`로 맞춘다. 고객이 찜한 뒤 장바구니에 담고 구매했는지, 장바구니에서 제거한 뒤 다시 찜했는지 시간순으로 연결하면 단순 전환율보다 풍부한 상태 이동을 볼 수 있다.

```text
View → Wishlist → Cart → Checkout → Purchase
          ↘ Remove / Price alert / Restock ↗
```

다음 네 집단은 서로 다른 대응이 필요하다.

1. **찜만 반복**: 비교 중이거나 가격·재고를 기다린다.
2. **찜→장바구니**: 의도가 강화됐다. 배송·사이즈 정보를 명확히 한다.
3. **장바구니 후 미구매**: 비용·결제·신뢰 마찰을 점검한다.
4. **구매 후 찜/장바구니 잔존**: 추천·알림에서 즉시 제외한다.

| 단계 | 분석 방법 | 이 과정의 장 |
|---|---|---|
| 찜 사용 세션 결과 | 차별화(관계) | 10장, 15장 9절 |
| 찜 → 구매 전환·소요 시간 | 특성화(순차 패턴, 시간 간격 분포) | 11장 12절 |
| 상품별 찜·구매 비율 | 차별화(상품 간 비교) | 10장 |
| 찜 후 미구매 세그먼트 | 규칙 세그먼트 → 트리거 | 21장 |

### 2단계: 세션 결과 비교

```python
sess = events.groupby("session_id").agg(
    wished=("event_type", lambda s: "wishlist_add" in set(s)), carted=("event_type", lambda s: "add_to_cart" in set(s)),
    purchased=("event_type", lambda s: "purchase" in set(s)), views=("event_type", lambda s: (s == "view_item").sum()))
sess = sess[sess["views"] > 0]
print((sess.groupby("wished")[["carted", "purchased"]].mean() * 100).round(1))
print("상품 조회 수 중앙값 — 찜 세션:", sess.loc[sess["wished"], "views"].median(), "/ 비찜 세션:", sess.loc[~sess["wished"], "views"].median())
```

### 3단계: 찜 → 구매 전환율과 소요 시간 (고객 단위)

찜은 세션을 넘어 작동한다. 찜한 고객이 그 상품을 이후 30일 안에 샀는지 주문 기록으로 확인한다.

```python
known_wish = wish[wish["customer_id"].notna()].sort_values("event_time").drop_duplicates(["customer_id", "product_id"])
completed = orders[orders["status"] == "completed"][["customer_id", "product_id", "order_time"]]
pairs = known_wish.merge(completed, on=["customer_id", "product_id"], how="left")
pairs["days_to_buy"] = (pairs["order_time"] - pairs["event_time"]).dt.days
pairs = pairs[(pairs["days_to_buy"].isna()) | (pairs["days_to_buy"] >= 0)]
first_buy = pairs.sort_values("days_to_buy").drop_duplicates(["customer_id", "product_id"])
first_buy["bought_30d"] = first_buy["days_to_buy"].between(0, 30)
print(f"식별된 찜 {len(first_buy)}건 중 30일 내 같은 상품 구매 {first_buy['bought_30d'].mean():.1%}")
print("구매까지 걸린 일수 분포(구매한 경우):")
print(first_buy.loc[first_buy["bought_30d"], "days_to_buy"].describe().round(1))
```

### 5단계: 찜 후 미구매 고객과 알림 트리거

```python
SNAPSHOT = pd.Timestamp("2026-07-01")
open_wish = first_buy[first_buy["days_to_buy"].isna() & (first_buy["event_time"] >= SNAPSHOT - pd.Timedelta(days=30))]
open_wish = open_wish.assign(days_since=(SNAPSHOT - open_wish["event_time"]).dt.days)
print("최근 30일 찜 후 미구매:", len(open_wish), "건 /", open_wish["customer_id"].nunique(), "명")
triggers = open_wish[open_wish["days_since"].between(7, 14)].join(products[["product_name", "list_price"]], on="product_id")
```

## 핵심 용어

- **찜(wishlist)**: 구매 의도가 아직 약한 관심 상품을 저장하는 기능·이벤트.
- **의도의 사다리(intent ladder)**: 조회 → 찜 → 장바구니 → 결제 → 구매로 강해지는 신호의 순서.
- **찜 → 구매 전환율**: 찜한 고객·상품 쌍 가운데 일정 기간 안에 구매된 비율. 예: 30일 내.
- **익명 병합(identity stitching)**: 로그인 전 세션의 이벤트를 로그인 뒤 계정에 합치는 규칙.
- **가격 저항(price resistance)**: 관심은 높으나 가격 때문에 구매하지 않는 상태의 신호.
- **재입고·가격 알림(restock/price alert)**: 찜 상품의 상태 변화를 알리는 트리거 메시지.

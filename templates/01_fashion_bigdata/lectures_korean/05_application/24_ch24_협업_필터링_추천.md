# Collaborative Filtering for Recommendation

## 학습 목표

협업 필터링은 상품 속성이 아니라 여러 고객의 행동 패턴으로 아직 관측되지 않은 선호를 추정한다. 핵심 데이터 구조는 고객과 상품을 두 축으로 둔 희소 행렬이다.

이 장을 마치면 다음을 할 수 있다.

- 주문 기록을 고객 × 상품 상호작용 행렬로 바꾸고 명시적·암묵적 피드백을 구분한다.
- 상품 기반 협업 필터링의 원리(함께 구매된 상품일수록 가깝다)를 설명하고 코사인 유사도로 구현한다.
- 인기순 추천을 기준선으로 두고 Hit rate@K·카탈로그 커버리지로 추천을 평가한다.
- 콜드 스타트(새 고객·새 상품)에 인기순·이미지 유사도를 어떻게 결합하는지 설명한다.
- 추천 결과를 배치로 만들어 API·위젯으로 제공하는 시스템을 그린다.


## 개념부터 시작하기

고객 \(u\), 상품 \(i\)의 암묵적 반응을 \(R_{ui}\)라 하자. 구매·장바구니·찜·조회에 서로 다른 가중치를 주면 빈칸이 많은 고객×상품 행렬 \(R\)을 얻는다. 상품 기반 방법은 행렬의 두 열이 같은 고객에게 얼마나 함께 나타나는지 비교한다.

전체 인기순을 반드시 기준선으로 둔다. 협업 필터링이 인기순보다 Recall@K를 높이는지 시간 순서로 나눈 평가셋에서 확인하고, 신규 고객·신상품의 빈칸 문제와 인기 편향은 콘텐츠 기반 추천과 탐색 슬롯으로 보완한다.

## 문제 설정: 함께 산 고객들이 산 상품

패션몰의 "이 상품을 산 고객이 함께 본 상품", "회원님을 위한 추천"은 협업 필터링으로 구현할 수 있다. 넷플릭스·아마존 같은 대규모 서비스는 개인별 잠재 선호, 이용 맥락, 실시간 반응을 함께 반영해 이 방식을 고도화한다. 소규모 쇼핑몰은 21장의 세그먼트 추천에서 출발하고, 구매 기록이 쌓이면 고객 개인 단위의 협업 필터링으로 확장할 수 있다.

<div class="concept-box">
  <b>개념 상자: 협업 필터링과 피드백의 종류</b>
  <p><strong>협업 필터링</strong>은 많은 고객의 행동을 "협업"시켜 한 고객의 선호를 추정하는 추천 방법이다. 상품의 속성(색·소재)은 쓰지 않고 누가 무엇을 샀는지만 쓴다. 두 갈래가 있다. <em>사용자 기반</em>은 나와 구매 이력이 비슷한 고객을 찾아 그들이 산 상품을 추천하고, <em>상품 기반</em>은 내가 산 상품과 함께 구매되는 상품을 추천한다. 상품 기반은 상품 수가 고객 수보다 적고 안정적이라 실무에서 먼저 쓴다.</p>
  <p>별점처럼 고객이 직접 남긴 평가는 <strong>명시적 피드백</strong>, 구매·조회·찜처럼 행동에서 추정한 선호는 <strong>암묵적 피드백</strong>이다. 패션몰은 대부분 암묵적 피드백만 있다. 암묵적 피드백에서 "0"은 싫어한다는 뜻이 아니라 아직 만나지 않았다는 뜻이므로, 평가할 때 "아직 안 산 상품 중 무엇을 살 것인가"로 질문을 바꾼다.</p>
  <p>11장의 장바구니 공출현(같은 주문에 담긴 상품)과 달리, 협업 필터링은 <em>같은 고객이 언젠가 산 상품</em>을 묶는다. 묶음의 경계가 주문에서 고객으로 넓어진 것이다.</p>
</div>

## 2. 모형과 계산 원리

| 단계 | 분석 방법 | 이 과정의 장 |
|---|---|---|
| 고객 × 상품 행렬 | 데이터 표현(행렬), 빈발 패턴의 확장 | 6장, 11장 |
| 상품 간 유사도 | 벡터 코사인 유사도 | 5장 7절 |
| 추천 점수 | 유사도 가중합(상품 기반 CF) | 개념 상자 |
| 평가 | Hit rate@K, 커버리지, 인기순 기준선과 비교 | 15장 6절 |

상품 기반 협업 필터링의 점수는 다음과 같다. 고객 \(u\)가 산 상품 집합을 \(I_u\), 상품 \(i\)와 \(j\)의 유사도를 \(s_{ij}\)라 하면, 아직 사지 않은 상품 \(j\)의 점수는

\[
\text{score}(u, j) = \sum_{i \in I_u} s_{ij}
\]

이며 점수가 높은 순으로 K개를 추천한다. \(s_{ij}\)는 두 상품의 구매 고객 벡터 사이의 코사인 유사도로 계산한다.

```python
def recommend(customer_id, k=10):
    bought = matrix.loc[customer_id]
    scores = item_sim.loc[bought[bought == 1].index].sum(axis=0)      # 구매 상품과의 유사도 합
```

### 5단계: 평가 — 인기순 기준선과 비교

6월에 실제로 산 상품(학습 기간에 사지 않았던 것)이 추천 10개 안에 있으면 적중이다.

```python
popular = train["product_id"].value_counts()

def hit_rate(recommender, k=10):
    hits, n = 0, 0
    for cust, group in test.groupby("customer_id"):
        if cust not in matrix.index:
            continue                                   # 6월에 처음 산 고객: 콜드 스타트
        new_items = set(group["product_id"]) - set(matrix.columns[matrix.loc[cust] == 1])
        if not new_items:
            continue
        n += 1
        hits += bool(new_items & set(recommender(cust, k)))
    return hits / n, n

def recommend_popular(customer_id, k=10):
    bought = matrix.loc[customer_id]
    return popular[[p for p in popular.index if bought[p] == 0]].head(k).index

hr_cf, n = hit_rate(lambda c, k: recommend(c, k).index)
hr_pop, _ = hit_rate(recommend_popular)
print(f"평가 고객 {n}명 / Hit rate@10: 상품 기반 CF {hr_cf:.3f}, 인기순 {hr_pop:.3f}")

coverage_cf = len(set().union(*[set(recommend(c).index) for c in matrix.index[:200]])) / len(products)
coverage_pop = len(set().union(*[set(recommend_popular(c)) for c in matrix.index[:200]])) / len(products)
print(f"카탈로그 커버리지(고객 200명 기준): CF {coverage_cf:.2f}, 인기순 {coverage_pop:.2f}")
```

```output
평가 고객 319명 / Hit rate@10: 상품 기반 CF 0.577, 인기순 0.555
카탈로그 커버리지(고객 200명 기준): CF 0.64, 인기순 0.50
```

두 숫자를 함께 본다. 인기순은 단순하지만 강력한 기준선이며, 협업 필터링이 이를 넘지 못하면 도입할 이유가 없다(15장 6절). 커버리지는 추천이 상품 카탈로그를 얼마나 넓게 쓰는지 보여준다. 인기순은 모든 고객에게 같은 상품을 보여주므로 커버리지가 낮다.

### 6단계: 조회·찜을 가중치로 더하기

구매만 쓰면 행렬이 너무 희소하다. 조회·찜을 낮은 가중치로 더하면 신호가 늘어난다.

```python
events = pd.read_csv(f"{DATA}/events.csv", parse_dates=["event_time"])
train_ev = events[(events["event_time"] < "2026-06-01") & events["customer_id"].notna()
                  & events["event_type"].isin(["view_item", "wishlist_add", "purchase"])]
weight = {"view_item": 0.2, "wishlist_add": 0.5, "purchase": 1.0}
train_ev = train_ev.assign(w=train_ev["event_type"].map(weight))
weighted = train_ev.pivot_table(index="customer_id", columns="product_id", values="w", aggfunc="sum", fill_value=0)
weighted = weighted.reindex(index=matrix.index, columns=products.index, fill_value=0).clip(upper=3)
sim_w = cosine_similarity(weighted.T)
np.fill_diagonal(sim_w, 0)
item_sim_w = pd.DataFrame(sim_w, index=products.index, columns=products.index)

def recommend_w(customer_id, k=10):
    seen = weighted.loc[customer_id]
    scores = item_sim_w.loc[seen[seen > 0].index].mul(seen[seen > 0], axis=0).sum(axis=0)
    scores = scores[matrix.loc[customer_id] == 0]
    return scores.sort_values(ascending=False).head(k).index

hr_w, _ = hit_rate(recommend_w)
print(f"조회·찜 가중 CF Hit rate@10: {hr_w:.3f}")
```


실습 데이터에서는 가중치를 더한 쪽이 오히려 조금 낮다. 조회는 구매보다 노이즈가 많아서 가중치가 크면 신호를 흐릴 수 있고, 실습 데이터의 조회는 구매 취향과 느슨하게만 연결되어 있다. 가중치는 고정된 정답이 아니라 데이터로 정하는 값이다. 실제 데이터에서는 조회·찜이 구매보다 훨씬 많아 보통 도움이 된다.

## 핵심 용어

- **협업 필터링(collaborative filtering)**: 여러 고객의 행동으로 한 고객의 선호를 추정하는 추천 방법. 예: 함께 구매된 상품 추천.
- **상호작용 행렬(interaction matrix)**: 고객을 행, 상품을 열로 한 구매·조회 기록 행렬. 예: 559 × 80 이진 행렬.
- **암묵적 피드백(implicit feedback)**: 구매·조회처럼 행동에서 추정한 선호. 예: 찜 0.5, 구매 1.0.
- **상품 기반 CF(item-based CF)**: 상품 간 유사도 합으로 점수를 매기는 방식. 예: 산 상품과 유사도가 높은 미구매 상품.
- **Hit rate@K**: 평가 기간에 실제 산 상품이 추천 K개 안에 든 고객의 비율.
- **커버리지(coverage)**: 추천 목록에 한 번이라도 등장한 상품의 비율.
- **콜드 스타트(cold start)**: 기록이 없는 새 고객·새 상품에 추천을 만들 수 없는 문제.

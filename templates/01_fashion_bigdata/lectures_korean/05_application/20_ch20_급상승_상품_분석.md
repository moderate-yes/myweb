# Trending Product Detection

## 학습 목표

급상승 상품 분석은 판매량이 큰 상품을 찾는 일이 아니라, 각 상품의 평소 수준에서 벗어난 변화를 찾는 문제다. 상품마다 판매 규모가 다르므로 동일한 절대 기준 대신 상품별 기준선을 만든다.

이 장을 마치면 다음을 할 수 있다.

- 주문 기록을 상품×날짜(또는 반나절·1시간) 판매량 표로 집계하고 집계 단위가 결과에 미치는 영향을 설명한다.
- 상품별 과거 평균과 표준편차로 기준선을 만들고 최근 판매량의 z 점수와 확률밀도를 계산한다.
- 3σ(6시그마 방식의 마지막 등분선) 기준으로 급상승·급하락을 분류하고, 낮은 판매량에서 이 기준이 놓치는 경우를 설명한다.
- 정답이 있는 사건 목록으로 탐지 결과의 precision·recall을 계산한다.
- 탐지 결과를 담당자 알림과 쇼핑몰 API 연동으로 보내는 시스템 구성을 그린다.
- 같은 방법을 고객·지역 기준으로 바꾸어 적용한다.


## 개념부터 시작하기

상품 \(i\)의 시점 \(t\) 판매량을 \(x_{i,t}\)라 하자. 과거 평균 \(\mu_i\)와 표준편차 \(\sigma_i\)를 이용하면 표준화 점수는 \(z_{i,t}=(x_{i,t}-\mu_i)/\sigma_i\)로 쓸 수 있다. 이 값은 판매량을 상품별 평소 변동 단위로 바꾼다.

기준선은 전주 대비 증감률이나 이동평균처럼 단순한 방법부터 시작한다. 계절·프로모션·재입고가 있는 상품에서는 평균과 표준편차가 안정적이지 않을 수 있으므로 경보를 원인으로 해석하지 않고 조사 후보로 사용한다.

## 문제 설정: 판매량이 튀는 날을 하루라도 빨리 알기

어느 상품의 일별 판매량이 4~6개 사이를 오가다가 9일째 10개가 팔리고 다음 날 다시 평소로 돌아왔다고 하자. 10일째 오전에 9일째의 급증을 알았다면 홈 화면 상단 노출이나 SNS 착용 사진 업로드, 포털 키워드 광고로 상승세를 조금이라도 더 끌고 갈 수 있었다. 급상승 상품 분석은 **판매량이 추세와 무관하게 오르거나 내리는 것을 가능한 한 빨리 알아채는 분석**이다. 최근에는 판매량뿐 아니라 클릭량에도 같은 방법을 쓴다.

이상 탐지는 특정 알고리즘 하나의 이름이 아니라 **평소와 다른 상태를 감지하는 접근법**이다. 스마트 팩토리의 카메라 불량 검출이나 차량의 비정상 소음 탐지처럼 산업마다 문제의 형태가 다르며, 6시그마 외에도 다양한 방법을 쓸 수 있다. 여기서는 가장 단순한 평균·표준편차 방법에서 출발해 그 한계까지 확인한다.

주문 기록은 **판매 날짜와 시간을 기준으로 한 줄씩 쌓이는 트랜잭션 표**다. 실제 데이터에는 구매자 ID·나이대·주소·상품 카테고리가 옆으로 길게 붙는다. 이 표를 그대로 분석하지 않고 "상품 × 기간" 판매량 표로 바꾸는 것이 첫 단계다. 하루 단위를 기본으로 하되, 판매량이 많은 쇼핑몰은 반나절·1시간 단위로 합산해 더 빨리 대응할 수 있다.

## 2. 모형과 계산 원리

이 장의 분석은 [7장](templates/01_fashion_bigdata/lectures_korean/03_analysis/07_ch7_분석_개괄.md)의 다섯 방법 가운데 두 가지를 잇는다.

1. **특성화**: 상품별 과거 판매량을 평균과 표준편차로 요약한다(10장).
2. **이상치 감지**: 요약한 분포에서 오늘 값이 얼마나 드문지 확률밀도로 판단한다(14장의 z-score 방식).

정규분포를 가정하면 평균 ± 1σ 안에 관측값의 약 68%, ± 2σ 안에 95%, ± 3σ 안에 99.7%가 들어간다. 강의의 "그래프를 6등분 혹은 3등분으로 나누고 마지막 등분선을 벗어나면 이상치"라는 설명은 평균에서 ±3σ 밖(양쪽 합쳐 0.3%)을 이상치로 보는 규칙이다. 판매량이 평균보다 높으면서 확률밀도가 낮으면 **급상승**, 평균보다 낮으면서 확률밀도가 낮으면 **급하락**이다.

### 3단계: 상품별 과거 평균·표준편차로 정규분포 만들기

강의 예시처럼 특정 상품(P042)의 최근 9일을 보고 평균과 표준편차를 계산한다. 기준일은 2026-06-10이며 "과거"는 그 전 28일이다.

```python
from scipy.stats import norm

target_day = pd.Timestamp("2026-06-10").date()
cols = list(daily.columns)
today_idx = cols.index(target_day)
past = daily.iloc[:, today_idx - 28:today_idx]      # 오늘을 제외한 28일
today = daily.iloc[:, today_idx]

mu = past.mean(axis=1)
sigma = past.std(axis=1, ddof=1)
print("P042 과거 28일 판매량:", past.loc["P042"].tolist())
print(f"평균 {mu['P042']:.2f}, 표준편차 {sigma['P042']:.2f}, 오늘 판매량 {today['P042']}")
print("평균±3σ 범위:", round(mu["P042"] - 3 * sigma["P042"], 1), "~", round(mu["P042"] + 3 * sigma["P042"], 1))
```


평균이 2.7개, 표준편차가 1.8개이면 "이 상품은 평소 0~8개 사이에서 움직인다"고 읽을 수 있다. 그 범위를 벗어나면 이상 징후로 추측한다. 정규분포 그래프에서 평균에 가까울수록 면적, 즉 출현 확률이 높다.

### 4단계: 최근 판매량의 확률밀도 계산과 급상승·급하락 분류

```python
z = (today - mu) / sigma.replace(0, np.nan)
pdf = norm.pdf(today, loc=mu, scale=sigma.replace(0, np.nan))

result = pd.DataFrame({"today": today, "mean_28d": mu.round(2), "std_28d": sigma.round(2),
                       "z": z.round(2), "pdf": pdf.round(4)})
result["signal"] = np.select(
    [(result["z"] > 3), (result["z"] < -3)],
    ["급상승", "급하락"], default="정상")
print(result.sort_values("z", ascending=False).head(5))
print(result["signal"].value_counts())
```

P042는 z 점수가 3을 크게 넘고 확률밀도가 사실상 0이다. 평균보다 높으면서 등장 확률이 낮으므로 **급상승**으로 분류된다. 즉, 확률밀도가 낮은 관측치 가운데 평균보다 높으면 급상승, 낮으면 급하락으로 분류하는 규칙이 그대로 코드가 된다.

표준편차가 0인 상품(과거 28일 판매가 모두 같은 값, 보통 모두 0)은 나눗셈이 되지 않아 `NaN`이 된다. 이런 상품은 별도 규칙(예: "과거 28일 판매 0인데 오늘 3개 이상")으로 다룬다.

### 5단계: 모든 날짜에 대해 매일 실행하기

운영에서는 매일 아침 어제 판매량을 그 전 28일과 비교한다. 이동 기준선으로 한 번에 계산한다.

```python
wide = daily.T.astype(float)                       # 날짜 × 상품
past_mean = wide.rolling(28).mean().shift(1)       # 오늘을 제외한 28일
past_std = wide.rolling(28).std(ddof=1).shift(1)
z_all = (wide - past_mean) / past_std.replace(0, np.nan)
print("z>3인 상품·날짜 수(모든 상품):", int((z_all > 3).sum().sum()))

z_all = z_all.where(past_mean >= 1)                # 평소 하루 1개 이상 팔리던 상품만
alerts = (z_all.stack().rename("z").reset_index()
          .rename(columns={"level_0": "date", "level_1": "product_id"}))
alerts["signal"] = np.select([alerts["z"] > 3, alerts["z"] < -3], ["급상승", "급하락"], default="정상")
alerts = alerts[alerts["signal"] != "정상"].merge(products[["product_id", "product_name"]], on="product_id")
print(len(alerts), "건 경보")
print(alerts.sort_values("date").tail(8))
```

### 6단계: 정답 사건과 비교해 평가하기

실습 데이터에는 네 가지 사건이 심어져 있다. 실제 업무에서는 "지난 분기에 확인된 사건" 목록이 이 역할을 한다.

```python
truth = pd.read_csv(f"{DATA}/injected_anomalies.csv", parse_dates=["date"])
truth["date"] = truth["date"].dt.date
print(truth.groupby(["product_id", "label"])["date"].agg(["min", "max", "count"]))

alerts["date"] = pd.to_datetime(alerts["date"]).dt.date
hit = alerts.merge(truth, on=["product_id", "date"], how="left")
tp = hit["label"].notna().sum()
precision = tp / len(alerts)
recall = truth.merge(alerts, on=["product_id", "date"]).shape[0] / len(truth)
print(f"경보 {len(alerts)}건 중 실제 사건 {tp}건 → precision {precision:.2f}")
print(f"사건 {len(truth)}건 중 탐지 {int(recall * len(truth))}건 → recall {recall:.2f}")
print(hit[hit["label"].notna()].groupby("label")["date"].count())
```

세 가지가 보인다. 첫째, 평균보다 훨씬 큰 값(프로모션, 인플루언서)은 3σ 규칙으로 잡힌다. 다만 프로모션 3일 중 첫날만 잡히고 둘째 날부터는 첫날 값이 기준선에 들어가 표준편차를 키운다. 둘째, 경보 40건 가운데 정답은 6건이라 precision이 낮다. 나머지는 주말이나 우연한 판매 증가이며, 실제 운영에서는 이런 경보를 담당자가 검토해 "조치 없음"으로 기록한다. 셋째, **급하락은 전혀 잡히지 않는다**. 하루 4개 팔리던 상품이 0개가 되어도 z 점수는 -2 근처에 머문다. 판매량처럼 작은 정수는 아래쪽으로 3σ만큼 떨어질 여지가 없기 때문이다. 6월의 점진적 상승(trend)도 하루하루는 3σ를 넘지 않아 놓친다.

급하락은 "연속 0일" 같은 규칙을 추가해 잡는다.

```python
def zero_run_length(s):
    """연속으로 0이 이어진 날 수 (0이 아니면 0)."""
    run_id = (s != s.shift()).cumsum()
    return (s == 0).astype(int).groupby(run_id).cumsum()

run_length = wide.apply(zero_run_length)
expected = past_mean.fillna(0)
drop = ((run_length >= 3) & (expected >= 2)).stack()
drop = drop[drop].reset_index().rename(columns={"level_0": "date", "level_1": "product_id"})
print(drop.groupby("product_id")["date"].agg(["min", "max", "count"]))
```

평소 하루 2개 이상 팔리던 상품이 3일 연속 0이면 품절·노출 오류를 의심할 수 있다. 규칙 하나가 정답은 아니다. 14장의 이동 중앙값·MAD, 변화점 탐지를 같은 표에 적용해 경보 수와 적중률을 비교하고, 하루에 검토할 수 있는 경보 수 안에서 recall이 높은 조합을 고른다.

### 7단계: 기준을 상품에서 고객·지역으로 바꾸기

## 5. 결과를 평가하는 법

- **경보의 질**: 확인된 사건 목록 대비 precision·recall(15장). 정답이 없으면 담당자가 경보를 검토한 뒤 "조치 가치 있음/없음"을 기록해 다음 달의 정답으로 쓴다.
- **지연**: 사건 발생일과 경보일의 차이. 하루 단위 집계는 최소 하루 지연이 생긴다.
- **운영 부담**: 하루 경보 수가 담당자가 볼 수 있는 수(예: 10건)를 넘으면 임곗값을 올리거나 상품군을 나눈다.
- **평균으로의 회귀**: 급증 다음 날 판매가 줄었다고 조치 효과로 해석하지 않는다(14장 12절).

- **상품 × 기간 표(product-by-period table)**: 주문 기록을 상품을 행, 기간을 열로 집계한 표. 예: 상품별 일별 판매량 pivot.
- **기준선(baseline)**: 평소 상태를 나타내는 통계량. 예: 오늘을 제외한 28일 이동 평균과 표준편차.
- **z 점수(z-score)**: 값이 평균에서 표준편차 몇 배 떨어져 있는지. 예: z=7이면 평균보다 7σ 높다.
- **확률밀도(probability density)**: 정규분포에서 어떤 값 근처가 나타날 상대적 가능성. 예: 평균에서 멀수록 밀도가 낮다.
- **3σ 규칙(three-sigma rule)**: 정규분포에서 평균 ± 3σ 밖의 값(약 0.3%)을 이상치로 보는 규칙. 강의의 "6등분의 마지막 등분선".
- **precision·recall**: 경보 가운데 실제 사건의 비율과 실제 사건 가운데 잡아낸 비율. 예: 경보 10건 중 6건이 사건이면 precision 0.6.

# Review-Driven Content

## 학습 목표

리뷰 기반 콘텐츠는 고객 문장을 그대로 많이 보여주는 기능이 아니라, 근거가 있는 요약과 조건부 사이즈 정보를 만드는 작업이다. 공식 사실, 고객 관찰과 모델 추정을 분리한다.

이 장을 마치면 다음을 할 수 있다.

- 리뷰의 체형·사이즈·핏 응답을 사이즈 제안 문제(분류)로 정의하고 모델을 만든다.
- 상품별 사이즈 × 핏 표와 "비슷한 체형 구매자" 요약을 계산한다.
- 홀드아웃 리뷰로 사이즈 제안의 정확도(정사이즈 확률)를 평가한다.
- 리뷰 요약·대표 리뷰·정렬 규칙을 설계하고 조작·권리·검수 원칙을 적용한다.
- 리뷰 → 모델 → 상품 페이지 위젯으로 이어지는 시스템을 그린다.


## 개념부터 시작하기

체형·구매 사이즈·상품·핏 응답을 특징 (x), 적절한 사이즈를 정답 (y)로 두면 사이즈 제안은 조건부 분류 문제다. 가장 단순한 기준선은 상품별 최빈 구매 사이즈이며, 모델은 이 기준보다 정확해야 한다.

시간 홀드아웃에서 정확도와 반품률을 평가하고 표본이 적은 체형에는 확신을 낮춘다. 리뷰 요약은 대표 근거 문장과 함께 제시하며, 동의 범위·삭제 요청·노출 편향을 운영 지표로 관리한다.

## 문제 설정: 반품 2위는 사이즈다

온라인 패션의 반품 사유 상위는 사이즈와 질감이다(13강 사례학습). 사이즈표는 상품의 치수이지 고객의 경험이 아니다. 리뷰에 남은 체형과 핏 응답은 "이 상품을 이 체형이 입으면 어떤가"라는 경험 데이터이며, 이것을 다음 고객에게 돌려주는 것이 리뷰 기반 콘텐츠다. 42장의 UGC(고객 생성 콘텐츠) 논의처럼 권리와 검수를 지켜야 한다.

## 1. 데이터를 표로 표현하기

| 데이터 | 파일 | 역할 | 데이터 특징 |
|---|---|---|---|
| 리뷰 | `reviews.csv` | 키·몸무게·구매 사이즈·핏 응답·본문·별점 | 비율(키·몸무게), 순서(사이즈·별점), 명목(핏), 텍스트 |
| 상품 마스터 | `products.csv` | 핏·카테고리 | 명목 |

키·몸무게는 고객이 **자발적으로** 리뷰에 입력한 값이며 민감할 수 있다. 수집 시 선택 항목으로 두고, 화면에는 개인이 아니라 집계로만 보여준다.

<div class="concept-box">
  <b>개념 상자: 핏 응답과 사이즈 제안</b>
  <p>리뷰의 핏 응답은 보통 "작아요 / 정사이즈 / 커요"의 세 값이다. 사이즈 제안 문제는 "이 체형의 고객이 어느 사이즈를 고르면 정사이즈라고 답할 확률이 가장 높은가"이다. 방법은 두 갈래다. <strong>집계 방식</strong>은 비슷한 체형(키·몸무게 구간)의 구매자들이 고른 사이즈와 핏 응답을 그대로 보여준다. 설명이 쉽고 데이터가 적어도 된다. <strong>모델 방식</strong>은 키·몸무게·상품 속성·사이즈를 입력으로 핏 응답을 예측하는 분류기를 만들고, 사이즈마다 정사이즈 확률을 계산해 가장 높은 사이즈를 제안한다. 상품이 많고 리뷰가 상품마다 적을 때 모델 방식이 유리하다.</p>
</div>

### 3단계: 모델식 사이즈 제안

```python
from sklearn.linear_model import LogisticRegression
from sklearn.preprocessing import OneHotEncoder, StandardScaler
from sklearn.compose import ColumnTransformer
from sklearn.pipeline import make_pipeline

SIZE_ORDER = {"S": 0, "M": 1, "L": 2, "XL": 3}
sized["size_idx"] = sized["size_purchased"].map(SIZE_ORDER)
sized = sized.sort_values("created_at")
split = int(len(sized) * 0.75)
train, test = sized.iloc[:split], sized.iloc[split:]

features = ["height_cm", "weight_kg", "size_idx", "fit_col"]
prep = ColumnTransformer([("num", StandardScaler(), ["height_cm", "weight_kg", "size_idx"]),
                          ("cat", OneHotEncoder(handle_unknown="ignore"), ["fit_col"])])
model = make_pipeline(prep, LogisticRegression(max_iter=2000))
model.fit(train[features], train["fit"])
print("클래스:", list(model.classes_))
print("평가 리뷰 핏 예측 정확도:", round((model.predict(test[features]) == test["fit"]).mean(), 3),
      "/ 다수 클래스 기준선:", round((test["fit"] == train["fit"].mode()[0]).mean(), 3))
```

```output
클래스: ['large', 'small', 'true_to_size']
평가 리뷰 핏 예측 정확도: 0.823 / 다수 클래스 기준선: 0.435
```

핏을 맞히는 정확도는 중간 단계다. 목표는 "어느 사이즈를 제안해야 정사이즈 확률이 가장 높은가"이므로, 고객마다 네 사이즈를 모두 넣어 보고 정사이즈 확률이 가장 높은 사이즈를 고른다.

```python
def recommend_size(height, weight, fit_col):
    rows = pd.DataFrame({"height_cm": height, "weight_kg": weight, "size_idx": list(SIZE_ORDER.values()), "fit_col": fit_col})
    proba = model.predict_proba(rows)[:, list(model.classes_).index("true_to_size")]
    best = int(np.argmax(proba))
    return list(SIZE_ORDER)[best], proba.round(2)

for h, w, f in [(160, 52, "슬림핏"), (160, 52, "오버핏"), (178, 80, "슬림핏")]:
    size, proba = recommend_size(h, w, f)
    print(f"키 {h} 몸무게 {w} {f} → 추천 {size} (S/M/L/XL 정사이즈 확률 {proba})")
```

### 4단계: 홀드아웃으로 제안 정확도 평가

평가 리뷰마다 모델이 제안했을 사이즈와 실제 구매 사이즈·핏 응답을 비교한다. 제안 사이즈가 실제 구매 사이즈와 같고 응답이 정사이즈였으면 "맞았다", 실제 구매가 작았다고 답했는데 제안이 한 치수 컸으면 "고쳤을 가능성"으로 본다.

```python
rec = test.apply(lambda r: recommend_size(r["height_cm"], r["weight_kg"], r["fit_col"])[0], axis=1)
test = test.assign(rec_size=rec, rec_idx=rec.map(SIZE_ORDER))
same = test["rec_idx"] == test["size_idx"]
outcome = np.select(
    [same & (test["fit"] == "true_to_size"), same & (test["fit"] != "true_to_size"),
     (test["rec_idx"] > test["size_idx"]) & (test["fit"] == "small"), (test["rec_idx"] < test["size_idx"]) & (test["fit"] == "large")],
    ["같은 사이즈·정사이즈", "같은 사이즈·불만", "한 치수 위 제안·실제 작았음", "한 치수 아래 제안·실제 컸음"], default="다른 제안·판단 불가")
print(pd.Series(outcome).value_counts())
baseline_true = (test["fit"] == "true_to_size").mean()
model_true = (same & (test["fit"] == "true_to_size")).sum() / same.sum()
print(f"실제 구매의 정사이즈 비율 {baseline_true:.1%} / 제안과 같은 사이즈를 산 고객의 정사이즈 비율 {model_true:.1%}")
```

### 5단계: 리뷰 요약 콘텐츠와 대표 리뷰

29장의 주제 라벨을 그대로 쓴다. 요약은 분모(리뷰 수)와 함께, 대표 리뷰는 규칙으로 고른다.

```python
labels = reviews["aspect_labels"].str.split(";").explode()
per_product = labels.groupby(reviews.loc[labels.index, "product_id"]).value_counts().unstack(fill_value=0)
n_reviews = reviews.groupby("product_id").size()
summary_widget = pd.DataFrame({
    "reviews": n_reviews,
    "size_true_%": (sized.groupby("product_id")["fit"].apply(lambda s: (s == "true_to_size").mean()) * 100).round(0),
    "material_pos_%": (per_product.get("material:pos", 0) / (per_product.get("material:pos", 0) + per_product.get("material:neg", 0)).replace(0, np.nan) * 100).round(0),
    "delivery_neg": per_product.get("delivery:neg", 0),
})
print(summary_widget.loc[[pid]].to_string())

def representative(df, k=2):
    df = df.assign(n_aspects=df["aspect_labels"].str.count(";") + 1, length=df["text"].str.len())
    df = df[df["rating"].between(2, 5) & (df["length"] >= 15)]                      # 극단·너무 짧은 리뷰 제외
    return df.sort_values(["n_aspects", "length"], ascending=False).head(k)[["rating", "size_purchased", "fit", "text"]]
print("\n대표 리뷰:\n", representative(reviews[reviews["product_id"] == pid]).to_string(index=False))
```

## 7. 다른 데이터로 확장하기

핏 응답이 있는 공개 데이터로 **ModCloth**와 **RentTheRunway** 데이터셋(Misra et al., 2018)이 있다. 사용자 체형(키·몸무게·가슴 둘레 등), 구매 사이즈, 핏 응답(small/fit/large), 리뷰 본문이 함께 있어 이 장의 2~4단계를 그대로 반복할 수 있다. 19장의 **Women's E-Commerce Clothing Reviews**는 핏 응답은 없지만 본문에서 사이즈 언급을 29장 방식으로 추출해 쓸 수 있다.

```python
# skip-run: RentTheRunway 핏 데이터로 같은 모델 만들기
import gzip, json
rows = [json.loads(l) for l in gzip.open("renttherunway_final_data.json.gz", "rt")]
rtr = pd.DataFrame(rows)[["fit", "height", "weight", "size", "category", "review_text"]].dropna()
rtr["height_cm"] = rtr["height"].str.extract(r"(\d+)' (\d+)").astype(float).pipe(lambda d: d[0] * 30.48 + d[1] * 2.54)
rtr["weight_kg"] = rtr["weight"].str.replace("lbs", "").astype(float) * 0.4536
# fit ∈ {small, fit, large}; size는 정수 → 3단계의 파이프라인에 size_idx=size, fit_col=category로 넣는다
```

<div class="lesson-section-box lesson-activity-box"><strong>짧은 활동</strong></div>

1. 2단계의 체형 구간을 더 잘게(5cm·4kg) 나누면 각 칸의 구매자 수가 얼마나 줄어드는지 보고, 집계식 제안의 한계를 설명한다.
2. 3단계의 모델에 상품의 소재(`material`)를 특징으로 추가하고 정확도가 달라지는지 확인한다.
3. 5단계의 대표 리뷰 규칙을 "도움됨 수" 기준으로 바꾸려면 어떤 데이터가 더 필요한지 쓴다.

<div class="lesson-section-box lesson-summary-box"><strong>이 장의 핵심</strong></div>

- 리뷰의 체형·사이즈·핏 응답은 경험 데이터이며, 집계식(비슷한 체형 구매자)과 모델식(정사이즈 확률) 사이즈 제안의 재료다.
- 제안 정확도는 홀드아웃의 정사이즈 비율과 배포 뒤 반품률 실험으로 평가한다.
- 리뷰 요약은 분모와 규칙을 공개하고 부정 리뷰를 숨기지 않으며, 체형 정보는 집계로만 노출한다.
- 리뷰가 적은 상품은 상품군 집계로 대체하고, 리뷰 요청에 체형·핏 항목을 넣어 커버리지를 높인다.

## 학습 점검

1. 사이즈표와 리뷰 기반 사이즈 제안의 차이는 무엇인가?
2. 집계식 제안과 모델식 제안은 각각 언제 유리한가?
3. 핏 예측 정확도가 아니라 "정사이즈 확률이 가장 높은 사이즈"를 목표로 삼는 이유는 무엇인가?
4. 대표 리뷰를 고를 때 지켜야 할 원칙을 두 가지 쓰시오.
5. 키·몸무게를 화면에 보여줄 때의 원칙은 무엇인가?

<details>
<summary>정답과 해설 보기</summary>

1. 사이즈표는 상품 치수이고, 리뷰 기반 제안은 특정 체형의 고객이 실제로 입어 본 경험의 집계다.
2. 집계식은 리뷰가 많고 설명이 필요할 때, 모델식은 상품이 많고 상품당 리뷰가 적을 때 유리하다.
3. 서비스의 목적이 핏을 맞히는 것이 아니라 고객이 정사이즈를 고르게 하는 것이기 때문이다.
4. 규칙을 공개하고, 좋은 리뷰만 고르지 않으며(별점 범위·주제 다양성), 검수를 거친다.
5. 개별 값이 아니라 구간 집계로만 보여주고, 개별 리뷰의 체형은 고객이 공개를 선택한 경우에만 표시한다.

## 핵심 용어

- **핏 응답(fit feedback)**: 구매자가 남긴 "작아요/정사이즈/커요" 응답.
- **사이즈 제안(size recommendation)**: 체형·상품 정보로 정사이즈 확률이 가장 높은 사이즈를 고르는 것.
- **집계식 제안**: 비슷한 체형 구매자의 선택과 응답을 그대로 보여주는 방식.
- **모델식 제안**: 핏 응답을 예측하는 분류기로 사이즈별 확률을 계산하는 방식.
- **대표 리뷰(representative review)**: 공개된 규칙(주제 수·길이·별점 범위)으로 고른 리뷰.
- **커버리지(coverage)**: 체형 정보가 있는 리뷰 비율과 상품별 리뷰 수.

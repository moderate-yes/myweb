# Fast Product Discovery and Shopping Experience

## 학습 목표

상품 탐색의 목표는 필터 수를 늘리는 것이 아니라 고객의 표현을 상품 속성과 연결해 유의미한 후보를 빨리 보여주는 것이다. 검색·정렬·필터·추천·결과 없음 화면을 하나의 탐색 시스템으로 본다.

이 장을 마치면 다음을 할 수 있다.

- 필터 키·값의 사용 빈도와 필터 사용 세션의 전환을 계산하고 해석의 한계를 말한다.
- 결과 0건 검색어를 모아 "고객이 찾지만 우리가 표현하지 못하는 속성"을 찾는다.
- 상품 마스터의 속성 채움 비율로 필터를 만들 수 있는지(커버리지)를 판단한다.
- 수요·사용·커버리지를 합친 필터 세분화 후보 표를 만들고 선택 과부하를 고려해 우선순위를 정한다.
- 속성 태깅 파이프라인과 패싯 검색 인덱스, 실험으로 이어지는 시스템을 그린다.
- 첫 유의미 상품 노출 시간과 검색 수정 횟수로 탐색 속도와 쇼핑 경험을 평가한다.


## 개념부터 시작하기

검색 세션 (s)에서 첫 유의미 상품 클릭까지 걸린 시간을 (T_s), 결과 0건 여부를 (Z_s)라 하자. 중앙 (T_s), (P(Z_s=1)), 검색 수정 횟수와 상품 발견률을 함께 보면 빠른 성공과 빠른 포기를 구분할 수 있다.

키워드 포함 검색을 기준선으로 두고 동의어·속성 필터·랭킹을 차례로 추가한다. 필터 사용 고객의 높은 전환율은 원래 의도가 강한 고객 때문일 수 있으므로 인과로 해석하지 않으며, 속성 커버리지와 잘못된 필터 해제율을 함께 본다.

## 문제 설정: "77사이즈 원피스"를 검색했는데 결과가 없다

고객이 "77사이즈 원피스"나 "빅사이즈 팬츠"를 검색했는데 결과가 0건이면 두 가지 중 하나다. 그런 상품이 정말 없거나, 있는데 사이즈 속성이 그렇게 표현되어 있지 않다. 후자라면 필터와 속성 정비로 해결할 수 있는 이탈이다. 31장의 퍼널 분석에서 세션 시작 → 상품 조회 이탈의 일부가 결과 0건 검색이었다. 빠른 탐색 설계는 그 병목의 해결책 후보다.

### 탐색 경험을 보는 핵심 지표

| 지표 | 계산 | 고객 경험 질문 |
|---|---|---|
| 첫 유의미 상품 노출 시간 | 검색 시작→첫 상품 클릭 시간 | 원하는 후보를 얼마나 빨리 찾는가? |
| 결과 0건 비율 | 결과 0건 검색 ÷ 전체 검색 | 고객 언어를 상품 속성이 이해하는가? |
| 검색 수정 횟수 | 세션당 검색어·필터 변경 수 | 고객이 과도하게 시행착오를 겪는가? |
| 상품 발견률 | 검색 세션 중 상세 조회 발생 비율 | 후보 상품을 하나라도 찾았는가? |
| 탐색 후 전환율 | 검색·필터 세션의 장바구니·구매율 | 빠른 탐색이 구매 고려로 이어지는가? |
| 되돌아감·필터 해제율 | 적용 직후 해제·목록 복귀 비율 | 필터 이름과 결과가 기대와 맞는가? |

전환율만 보면 빠르게 포기한 고객과 충분히 탐색한 고객을 구분하기 어렵다. 탐색 시간도 짧을수록 무조건 좋은 것은 아니다. 원하는 상품을 첫 화면에서 찾아 짧아진 것인지, 결과가 나빠 즉시 떠난 것인지 상품 발견률과 함께 읽는다.

## 4. Python으로 확인하기

### 1단계: 데이터 확인

```python
import numpy as np
import pandas as pd

pd.set_option("display.width", 120)
DATA = "templates/01_fashion_bigdata/data/fashion_mall"
events = pd.read_csv(f"{DATA}/events.csv", parse_dates=["event_time"])
products = pd.read_csv(f"{DATA}/products.csv")

filters = events[events["event_type"] == "apply_filter"].copy()
filters[["key", "value"]] = filters["detail"].str.split("=", expand=True)
searches = events[events["event_type"] == "search"].copy()
searches[["query", "results"]] = searches["detail"].str.split("|", expand=True)
searches["results"] = searches["results"].astype(int)
print("필터 적용 이벤트:", len(filters), "/ 검색 이벤트:", len(searches))
print(filters["key"].value_counts().to_dict())
print("상품 속성:", [c for c in products.columns if c not in ("product_id", "product_name", "list_price", "cost_price", "launch_date", "image_file")])
```

### 4단계: 속성 커버리지 — 필터를 만들 수 있는가

```python
coverage = products[["category", "subcategory", "color", "material", "fit"]].notna().mean().round(3) * 100
print("속성 채움 비율(%):", coverage.to_dict())
print("\n속성별 값의 수:", {c: products[c].nunique() for c in ["category", "subcategory", "color", "material", "fit"]})

# 새로 필요한 속성은 아직 없다. 상품명·설명에서 규칙으로 얼마나 채울 수 있는지 시험한다

products["sleeve"] = products["product_name"].apply(lambda n: next((v for k, v in SLEEVE.items() if k in n), np.nan))
print("소매 길이를 상품명 규칙으로 채운 비율:", f"{products['sleeve'].notna().mean():.1%}")
```

### 5단계: 필터 값 조합과 세분화 후보 표

         .apply(lambda ks: list(zip(ks, ks[1:]))).explode().dropna())

    {"filter": "sleeve_length", "demand_signal": int(demand.loc[demand.index.str.contains("반팔"), "zero_result_searches"].sum()),

    {"filter": "material", "demand_signal": int(searches["query"].str.contains("린넨|시어서커").sum()),

## 5. 결과를 평가하는 법

- **결과 0건 비율**: 속성 정비·동의어 사전 도입 전후의 결과 0건 검색 비율.
- **필터 사용률과 전환**: 새 필터의 사용 세션 비율과, 필터 노출 유무를 나눈 [31장](templates/01_fashion_bigdata/lectures_korean/05_application/31_ch31_AB_테스트.md) 실험의 조회 → 장바구니 전환.
- **선택 과부하**: 필터가 많아지면 오히려 사용률이 떨어질 수 있다. 상위 노출 필터 수를 제한하고 나머지는 "더 보기"로 둔다.
- **태깅 품질**: 새 속성의 값 분포와 표본 검수 정확도. 잘못 채워진 속성은 없는 것보다 나쁘다.

## 핵심 용어

- **패싯(facet)**: 상품을 좁혀 가는 속성 축. 예: 색상, 소재, 핏.
- **속성 태깅(attribute tagging)**: 상품마다 속성 값을 채우는 작업. 예: 소매 길이 = 반팔.
- **커버리지(coverage)**: 속성이 채워진 상품의 비율. 예: 소재 100%.
- **결과 0건 검색(zero-result search)**: 결과가 없는 검색. 채워지지 않은 수요의 신호.
- **동의어 사전(synonym dictionary)**: 검색어와 속성 값을 잇는 표. 예: 77 → XL.
- **선택 과부하(choice overload)**: 선택지가 너무 많아 결정이 어려워지는 현상.

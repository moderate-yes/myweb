## 개념부터 시작하기

분석의 기본 단위는 **질문–데이터–변환–평가–결정**이다. 같은 파일과 코드를 다시 실행했을 때 같은 표가 나와야 하며, 도구가 바뀌어도 이 다섯 요소는 유지되어야 한다.

가장 단순한 기준선은 사람이 작은 표본을 직접 계산한 결과다. 자동 생성된 코드의 행 수·합계·제외 규칙을 이 값과 비교하면 실행 성공과 계산 타당성을 구분할 수 있다. 공개 데이터셋은 정답이 아니라 방법을 비교하는 공통 시험장으로 사용한다.

## 4. 코랩의 AI 도구: Gemini

코랩에는 Gemini 모델이 통합되어 있다. 구글은 2025년 5월 코랩을 "AI-first"로 재구성했다고 발표했고, 이후 기능이 계속 추가되고 있다. 만 18세 이상 계정, 지원 지역에서 기본으로 켜져 있으며 무료 사용자도 쓸 수 있다(사용량 한도는 요금제에 따라 다르다).

| 기능 | 하는 일 | 쓰기 좋은 순간 |
|---|---|---|
| Generate(셀 프롬프트) | 셀 위치에서 "월별 순매출을 그려줘"처럼 요청하면 코드를 생성한다 | 반복적인 pandas·matplotlib 코드 |
| Gemini 사이드 패널 | 노트 전체를 맥락으로 대화한다. 라이브러리 사용법 질문, 여러 셀에 걸친 코드 변경 제안 | "이 노트에서 반품 정의를 완료 주문 기준으로 바꿔 줘" |
| 오류 수정 제안 | 오류가 나면 원인을 설명하고 고친 코드를 **diff(변경 전후 비교)**로 보여 준다. 승인해야 반영된다 | KeyError, dtype 오류, 결합 후 행 수 증가 |
| Data Science Agent | 데이터 파일을 올리고 목표를 적으면 데이터 로드·탐색·시각화·모델까지 담긴 노트 전체를 만든다 | 새 데이터셋을 처음 훑을 때 |
| Learn Mode(2026년 4월) | 답을 대신 써 주지 않고 단계별 힌트로 안내하는 튜터 모드 | 처음 배우는 문법·함수 |
| Custom Instructions | 노트에 저장되는 지시문. 공유하면 함께 전달된다 | "이 과정의 공통 스키마와 순매출 정의를 따를 것" |
| `google.colab.ai` 라이브러리 | 노트 코드 안에서 Gemini·Gemma 모델을 호출한다. 무료 사용자 포함 | 상품명 분류·요약 같은 소규모 텍스트 작업 |

### Data Science Agent 사용 순서

1. 빈 노트를 열고 왼쪽 파일 패널 또는 Gemini 패널의 **Add files**로 데이터(CSV 등)를 올린다.
2. Gemini 패널에 목표를 한국어나 영어로 적는다. 예:

```text
orders.csv와 products.csv를 product_id로 연결해서,
status가 completed인 주문만으로 카테고리별 순매출과 주문 수를 집계하고 막대그래프로 그려 줘.
취소·반품 주문은 별도 표로 개수만 보여 줘.
```

3. 에이전트가 계획(데이터 확인 → 결합 → 집계 → 시각화)을 제시하고 셀을 생성한다. **Accept** 또는 **Accept and run**을 누르면 노트에 반영된다.
4. 생성된 셀을 그대로 믿지 말고 9장의 전처리 점검 순서로 확인한다: 결합 전후 행 수, Key 중복, 결측, 상태값 정의, 기간.

### 노트 안에서 모델 호출하기

```python
# 코랩 안에서만 동작한다
from google.colab import ai

prompt = "다음 상품명을 outer/top/bottom/shoes/accessory 중 하나로 분류해 JSON으로 답해: 남색 오버사이즈 코트"
print(ai.generate_text(prompt))
```

12장에서 본 LLM 분류와 같은 원리다. 결과는 정답표가 있는 작은 평가셋으로 정확도를 재고, 확신이 낮은 사례만 사람이 검토한다.

### AI 도구를 쓸 때의 규칙

- **개인정보를 올리지 않는다.** 고객 연락처·주소가 있는 원본은 가명 ID와 필요한 컬럼만 남긴 사본으로 바꾼 뒤 올린다(18장).
- **생성된 코드는 읽고 실행한다.** 특히 파일 삭제, 드라이브 쓰기, 외부 요청이 있는지 본다.
- **정의를 프롬프트에 적는다.** "순매출 = 완료 주문의 수량×단가"처럼 분모·기간·제외 규칙을 명시하지 않으면 AI가 임의로 정한다.
- **검증 셀을 붙인다.** 결합 전후 행 수, 합계 대조, 표본 원문 확인 셀을 AI가 만든 셀 뒤에 둔다.
- **재현 조건을 기록한다.** 사용한 모델 이름과 날짜, 프롬프트를 텍스트 셀에 남긴다. 같은 프롬프트도 모델이 바뀌면 결과가 달라진다.

## 5. 벤치마크 데이터셋이란

**벤치마크 데이터셋**은 많은 사람이 같은 조건에서 방법을 비교하려고 공개해 둔 데이터다. 데이터 분석 학습에서 벤치마크가 필요한 이유는 세 가지다.

1. **재현**: 교재·논문·블로그의 결과를 같은 데이터로 따라 하며 자기 코드를 검증한다.
2. **비교**: 두 방법(예: 규칙 기반 RFM과 k-평균)을 같은 데이터에서 비교해야 차이가 방법 때문인지 알 수 있다.
3. **연습**: 회사 데이터를 반출할 수 없을 때 같은 구조의 공개 데이터로 파이프라인을 먼저 만든다.

데이터셋을 고를 때는 다음을 확인한다.

- **질문과 분석 단위가 맞는가**: 고객별 RFM에는 고객 ID가 있는 거래 기록이, 퍼널 분석에는 세션·이벤트 기록이 필요하다.
- **라이선스**: CC BY(출처 표기), CC BY-NC(비상업), 대회 규정(연구·교육 한정) 등을 확인한다. 회사 보고서나 서비스에 쓰려면 비상업 조건을 지킬 수 있는지 본다.
- **크기**: 코랩 무료 런타임에서 pandas로 다룰 수 있는 크기는 대략 수백 MB까지다. 큰 데이터는 일부 기간·카테고리만 읽는다.

```python
orders = pd.read_csv("data/olist_orders_dataset.csv", parse_dates=["order_purchase_timestamp"])
items = pd.read_csv("data/olist_order_items_dataset.csv")

course_orders = (
    orders.merge(items, on="order_id")
    .rename(columns={
        "order_purchase_timestamp": "order_date",
        "order_status": "status",
        "price": "unit_price",
    })
    .assign(quantity=1)
    [["order_id", "order_date", "customer_id", "product_id", "quantity", "unit_price", "status"]]
)
print(course_orders.head())
print(course_orders["status"].value_counts())
```

이름을 맞춘 뒤에도 **정의**는 다르다. Olist의 `delivered`와 이 과정의 `completed`가 같은 뜻인지, 취소·반품이 어떻게 표시되는지 데이터 사전에서 확인하고 텍스트 셀에 기록한다.

## 8. 공식 내보내기, API, 공개 데이터셋, 웹 수집의 순서

실무에서 데이터를 구하는 순서는 다음과 같다.

1. **자사 운영 DB와 관리자 화면의 공식 내보내기**: 정의가 문서화되어 있고 권한이 명확하다.
2. **공식 API**: GA4·Amplitude·쇼핑 플랫폼 API. 이용 한도와 약관을 따른다.
3. **공개 데이터셋**: 이 장의 목록처럼 라이선스가 명시된 데이터.
4. **웹 수집(크롤링·스크래핑)**: 위 세 가지로 구할 수 없을 때만, 다음을 확인한 뒤 제한적으로 수행한다.

웹 수집 전 확인 사항은 다음과 같다.

- 사이트 이용약관이 자동 수집을 금지하는가?
- `robots.txt`가 내 자동 클라이언트에 허용하는 경로는 무엇인가?
- 로그인 뒤에만 보이는 정보나 개인정보가 포함되는가?
- 필요한 최소 항목·기간만 가져오는가? 요청 빈도가 서비스에 부담을 주지 않는가?
- 가져온 데이터의 보관 기간과 삭제 시점을 정했는가?

노코드 수집 도구(리스틀리 등)를 쓰더라도 이 확인은 사람이 해야 한다. 추출 성공 메시지는 데이터가 완전하고 정확하다는 뜻이 아니므로 원본 화면과 표를 대조한다.

## 핵심 용어

- **코랩(Colab)**: 브라우저에서 Jupyter 노트북과 관리형 계산 자원을 사용하는 구글 서비스.
- **노트북(notebook)**: 설명, 코드와 실행 결과를 셀 단위로 함께 기록하는 문서. `.ipynb` 파일.
- **런타임(runtime)**: 노트의 코드를 실행하는 임시 가상 머신. 변수와 `/content`의 파일은 런타임과 함께 사라진다.
- **Data Science Agent**: 데이터 파일과 목표 문장을 주면 로드·탐색·시각화·모델 셀이 담긴 노트를 생성하는 코랩의 Gemini 기능.
- **Learn Mode**: 답 대신 단계별 힌트를 주는 코랩 Gemini의 튜터 모드.
- **벤치마크 데이터셋(benchmark dataset)**: 같은 조건에서 방법을 비교·재현하려고 공개된 데이터.

# Personalized Message Channel Selection

## 학습 목표

개인화 메시지 채널 선택은 반응 확률이 가장 높은 채널을 무조건 고르는 문제가 아니다. 도달 가능성, 동의, 비용, 피로도와 기대 가치를 함께 계산하는 제한된 의사결정 문제다.

이 장을 마치면 다음을 할 수 있다.

- 푸시·인앱 팝업·카카오 알림톡·이메일·SMS의 도달 조건, 비용, 동의 요건을 구분한다.
- 캠페인 발송 기록에 고객 마스터와 최근 행동을 결합해 채널별 반응률 표를 만든다.
- 세그먼트 × 채널 교차표로 반응률 차이를 읽고, 분류 모델로 고객·채널별 열람 확률을 추정한다.
- 고객별 최적 채널을 고르고 기존 배정과 기대 열람률·비용을 비교한다.
- 채널 선택표를 CRM 도구에 연결하고 동의·수신 거부를 지키는 시스템을 그린다.


## 개념부터 시작하기

고객 \(u\), 채널 \(c\)의 열람 확률을 \(p_{uc}\), 열람 뒤 기대 가치를 \(v_{uc}\), 발송 비용을 \(k_c\)라 하면 단순 기대효용은 \(p_{uc}v_{uc}-k_c\)로 쓸 수 있다. 동의하지 않은 채널과 설치되지 않은 앱은 후보에서 먼저 제외한다.

고객별 과거 최다 반응 채널을 기준선으로 사용한다. 모델 점수는 선택 결과이지 인과효과가 아니므로 채널 정책의 증분 효과는 무작위 홀드아웃으로 확인하고, 수신 거부와 발송 빈도를 가드레일로 둔다.

## 문제 설정: 닿지 않는 메시지는 없는 메시지다

캠페인 열람률이 20%라면 80%의 고객에게 메시지는 없는 것과 같다. 앱 미설치 고객에게 푸시는 갈 수 없고, 이메일을 확인하지 않는 20대에게 이메일은 낭비이며, SMS는 건당 비용이 가장 비싸다. 강의가 소개한 CRM 자동화 도구(빅인 등)는 행동 데이터로 고객을 분류한 뒤 이메일·카톡·문자를 보내는데, **어느 채널로 보낼지**는 도구가 아니라 데이터로 정해야 한다.

### 2단계: 발송 건에 고객 특성과 발송 전 행동을 결합

```python
app_sessions = events[(events["event_type"] == "session_start") & (events["device"] == "app")
                      & events["customer_id"].notna()][["customer_id", "event_time"]]

def sessions_before(row, days=30):
    s = app_sessions[app_sessions["customer_id"] == row["customer_id"]]["event_time"]
    return int(((s < row["sent_date"]) & (s >= row["sent_date"] - pd.Timedelta(days=days))).sum())
```

### 4단계: 채널별 열람 확률 모델

교차표는 조건을 두 개까지만 보여준다. 여러 조건을 한꺼번에 반영하려면 열람 여부를 예측하는 분류 모델을 만든다. 채널마다 열람에 영향을 주는 조건이 다르므로 **채널마다 모델을 하나씩** 만든다. 2~4월 캠페인으로 학습하고 5~6월 캠페인으로 평가한다.

```python
from sklearn.linear_model import LogisticRegression
from sklearn.preprocessing import OneHotEncoder
from sklearn.compose import ColumnTransformer
from sklearn.pipeline import make_pipeline
from sklearn.metrics import roc_auc_score

features = ["segment", "age_band", "app_installed", "push_opt_in", "app_sessions_30d"]
train = data[data["sent_date"] < "2026-05-01"]
test = data[data["sent_date"] >= "2026-05-01"]

def make_model():
    prep = ColumnTransformer([("cat", OneHotEncoder(handle_unknown="ignore"), ["segment", "age_band"])],
                             remainder="passthrough")
    return make_pipeline(prep, LogisticRegression(max_iter=1000))

models, rows = {}, []
for ch in ["push", "kakao", "email", "sms"]:
    tr, te = train[train["channel"] == ch], test[test["channel"] == ch]
    models[ch] = make_model().fit(tr[features], tr["opened"])
    auc = roc_auc_score(te["opened"], models[ch].predict_proba(te[features])[:, 1])
    rows.append({"channel": ch, "train_n": len(tr), "test_n": len(te), "train_open_rate": round(tr["opened"].mean(), 2), "test_AUC": round(auc, 3)})
print(pd.DataFrame(rows).to_string(index=False))
```

```output

  kakao      201     174             0.53     0.550
  email      221     176             0.22     0.611
    sms      232     177             0.24     0.496
```

AUC는 열람할 고객과 하지 않을 고객을 얼마나 잘 구분하는지 나타낸다. 채널 안에서 모두에게 같은 확률을 주면 0.5다. 푸시는 최근 앱 세션 수라는 강한 신호가 있어 AUC가 높고, 이메일은 연령대로 어느 정도 구분되며, 카카오와 SMS는 누구에게 보내든 열람률이 비슷하다. 이 차이 자체가 정보다. 구분이 안 되는 채널은 고객을 고를 필요 없이 비용만 보면 된다.

### 5단계: 고객별 최적 채널 선택

발송 가능한 채널은 고객마다 다르다. 푸시는 앱 설치와 알림 허용이 있어야 하고, 모든 채널은 마케팅 동의가 있어야 한다. 채널마다 열람 확률을 예측한 뒤, **열람 1건의 가치 − 채널 비용**이 가장 큰 채널을 고른다.

```python
COST = {"push": 0, "kakao": 15, "email": 1, "sms": 20}          # 건당 발송 비용(원, 예시)
VALUE_PER_OPEN = 400                                            # 열람 1건의 기대 가치(원, 예시)
snapshot = pd.Timestamp("2026-07-01")
eligible = customers[customers["marketing_consent"]].copy()
seg_map = data.drop_duplicates("customer_id").set_index("customer_id")["segment"]
eligible["segment"] = eligible["customer_id"].map(seg_map).fillna("new")
eligible["sent_date"] = snapshot
eligible["app_sessions_30d"] = eligible.apply(sessions_before, axis=1)

rows = []
for ch, cost in COST.items():
    cand = eligible.copy()
    if ch == "push":
        cand = cand[cand["app_installed"] & cand["push_opt_in"]]
    cand["channel"] = ch
    cand["p_open"] = models[ch].predict_proba(cand[features])[:, 1]
    cand["net_value"] = cand["p_open"] * VALUE_PER_OPEN - cost
    rows.append(cand[["customer_id", "channel", "p_open", "net_value", "app_sessions_30d", "age_band"]])
choice = pd.concat(rows).sort_values("net_value", ascending=False).drop_duplicates("customer_id")
print(choice["channel"].value_counts())
print(choice.groupby("channel")[["p_open", "app_sessions_30d"]].mean().round(2))
print(pd.crosstab(choice["age_band"], choice["channel"]))
```

```python
test_choice = test.merge(choice[["customer_id", "channel", "p_open"]].rename(
    columns={"channel": "best_channel", "p_open": "p_best"}), on="customer_id", how="inner")
test_choice["p_actual"] = [models[ch].predict_proba(row.to_frame().T[features])[0, 1]
                           for ch, (_, row) in zip(test_choice["channel"], test_choice.iterrows())]
summary = pd.DataFrame({
    "실제 배정 채널 열람률(관측)": [test_choice["opened"].mean()],
    "실제 배정 채널 기대 열람률(모델)": [test_choice["p_actual"].mean()],
    "최적 채널 기대 열람률(모델)": [test_choice["p_best"].mean()],
    "채널이 바뀌는 고객 비율": [(test_choice["channel"] != test_choice["best_channel"]).mean()],
}).T.round(3)
print(summary)
```

## 5. 결과를 평가하는 법

- **모델 평가**: 홀드아웃 캠페인의 AUC를 채널 평균 기준선과 비교한다. 모델이 기준선을 넘지 못하면 교차표 규칙으로 충분하다.
- **효과 평가**: 6단계의 기대 열람률은 모델의 추정일 뿐이다. 실제 효과는 고객을 무작위로 나누어 한쪽은 기존 채널, 한쪽은 선택 채널로 보내는 [31장 A/B 테스트](templates/01_fashion_bigdata/lectures_korean/05_application/31_ch31_AB_테스트.md)로 확인한다.
- **비용**: 열람률이 높아도 SMS·카카오 비용이 열람 가치를 넘으면 안 된다. `VALUE_PER_OPEN`은 캠페인 목적(구매 유도·재방문)에 따라 다시 정한다.
- **피로도**: 한 고객에게 여러 채널을 동시에 보내지 않도록 채널당 주간 발송 상한을 둔다.

## 핵심 용어

- **메시지 채널(message channel)**: 고객에게 메시지가 전달되는 경로. 예: 푸시, 인앱 팝업, 카카오 알림톡, 이메일, SMS.
- **열람률(open rate)**: 발송 건 가운데 열람된 비율. 예: 카카오 45%.
- **옵트인(opt-in)**: 특정 채널 수신을 고객이 허용한 상태. 예: 푸시 알림 허용.
- **AUC**: 분류 모델이 양성과 음성을 구분하는 정도(0.5 무작위, 1 완벽).
- **기대 순가치(expected net value)**: 열람 확률 × 열람 가치 − 채널 비용. 예: 0.4 × 400 − 15 = 145원.
- **발송 상한(frequency cap)**: 한 고객에게 일정 기간 보낼 수 있는 최대 메시지 수.

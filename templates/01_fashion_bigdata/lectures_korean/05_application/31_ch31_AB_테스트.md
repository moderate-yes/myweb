# Customer Experience Analysis: A/B Test, Heatmap, Funnel, and Cohort

## 학습 목표

고객 경험 분석은 관찰 도구와 인과 검증 도구를 구분하는 데서 시작한다. 히트맵·퍼널·코호트는 문제가 나타나는 위치와 집단을 찾고, A/B 테스트는 한 가지 변경의 효과를 추정한다.

이 장을 마치면 다음을 할 수 있다.

- 실험 단위(세션·고객), 주 지표, 가드레일 지표, 기간을 실험 설계서로 적는다.
- 배정 균형(SRM)을 점검하고 배정이 깨진 실험을 해석하지 않는 이유를 설명한다.
- 두 비율의 차이, 신뢰구간, p-value를 계산하고 "유의하지 않음"과 "효과 없음"을 구분한다.
- MDE와 검정력으로 실험 전에 필요한 표본 크기를 계산한다.
- 중간에 결과를 훔쳐보는 문제(peeking)와 세그먼트 분해의 함정을 설명하고 실험 등록부·결정 규칙을 만든다.

이 장은 고객 경험을 한 가지 지표로 판단하지 않고 **히트맵→퍼널→코호트→A/B 테스트**로 연결한다. 히트맵은 어디에서 문제가 보이는지, 퍼널은 어느 단계에서 이탈하는지, 코호트는 문제가 특정 시기·유입 집단에 집중되는지 보여준다. A/B 테스트는 그 관찰에서 만든 개선안이 실제 원인인지 검증한다.


## 개념부터 시작하기

A안과 B안의 전환율을 \(p_A,p_B\)라 하면 관심 대상은 차이 \(\Delta=p_B-p_A\)다. 점추정치만으로 결정하지 않고 표준오차와 신뢰구간을 함께 제시한다. 실험 단위, 주 지표, MDE, 기간과 가드레일은 데이터를 보기 전에 정한다.

현재 화면을 그대로 유지하는 A안을 기준선으로 둔다. 히트맵의 진한 색이나 퍼널의 이탈은 원인이 아니라 가설 생성 신호다. SRM, 중간 엿보기, 다중 비교와 장기 반품 지연을 점검한 뒤 실험 등록부에 성공과 실패를 모두 남긴다.

## 문제 설정: 관찰에서 실험까지

"계속" 버튼을 "회원가입 없이 구매"로 바꿔 연 3억 달러 매출을 늘렸다는 유명한 이야기가 있다. 그러나 이런 숫자를 인과효과로 해석하려면 무작위로 나눈 두 집단, 같은 기간, 같은 조건이 필요하다. Booking.com은 실험 내역을 검색 가능한 저장소에 공개하고(투명성), 팀원들이 서로의 실험을 검토하며(동료 리뷰), 실패를 학습으로 인정하고(실패 허용), 기존 판단이 틀릴 수 있음을 받아들이는 문화를 강조한다(열린 사고). 계산 자체는 단순해도 이러한 실험 문화가 없으면 지속적으로 운영하기 어렵다.

## 1. 데이터를 표로 표현하기

| 데이터 | 파일 | 역할 | 데이터 특징 |
|---|---|---|---|
| 행동 로그 | `events.csv` | 5월 세션의 `variant`(A/B)와 결제·구매 이벤트 | 이벤트 시퀀스, 세션 단위 배정 |

실습 데이터의 실험은 2026년 5월 한 달, 세션 단위로 A(기존 결제 화면)와 B(입력 항목을 줄인 결제 화면)에 배정되었다. 결제를 시작한 세션(`begin_checkout`)이 구매(`purchase`)로 이어지는 비율이 주 지표다.

<div class="concept-box">
  <b>개념 상자: 실험 단위, MDE, SRM</b>
  <p><strong>실험 단위</strong>는 무작위 배정의 단위다. 세션 단위면 같은 고객이 방문마다 다른 화면을 볼 수 있고, 고객 단위면 일관되지만 표본이 줄어든다. 결제 화면처럼 한 방문 안에서 끝나는 경험은 세션, 추천처럼 여러 방문에 걸친 경험은 고객 단위가 맞다.</p>
  <p><strong>MDE(minimum detectable effect)</strong>는 실험이 잡아낼 수 있는 최소 효과 크기다. 전환율 55%에서 3%포인트 차이를 80% 확률로 찾으려면 몇 세션이 필요한지 실험 <em>전에</em> 계산한다. 표본이 부족한 실험은 효과가 있어도 "유의하지 않음"이 나온다.</p>
  <p><strong>SRM(sample ratio mismatch)</strong>은 50:50으로 배정했는데 실제 비율이 통계적으로 크게 다른 상태다. 배정 코드 오류, 봇, 한쪽만 오류로 이탈 같은 원인이 있으며, SRM이 있으면 결과를 해석하지 않는다.</p>
</div>

## 2. 모형과 계산 원리

| 단계 | 분석 방법 | 이 과정의 장 |
|---|---|---|
| 세션별 전환 | 특성화(비율) | 10장 |
| A vs B 차이 | 차별화(두 비율 비교) + 무작위 배정 → 인과 | 15장 9·10절 |
| 불확실성 | 신뢰구간, p-value | 15장 8절 |
| 표본 크기 | 검정력 분석 | 개념 상자 |
| 세그먼트 분해 | 차별화(기기별), 다중 비교 주의 | 10장 12절(Simpson) |

두 비율 \(p_A, p_B\)의 차이에 대한 근사 신뢰구간은

\[
(p_B - p_A) \pm z \sqrt{\frac{p_A(1-p_A)}{n_A} + \frac{p_B(1-p_B)}{n_B}}
\]

이며 95% 구간에서 \(z = 1.96\)이다.

| 항목 | 내용 |

### 2단계: 세션 표와 배정 균형

```python
import numpy as np
import pandas as pd
from scipy import stats

pd.set_option("display.width", 120)
DATA = "templates/01_fashion_bigdata/data/fashion_mall"
events = pd.read_csv(f"{DATA}/events.csv", parse_dates=["event_time"])

exp = events[events["variant"].isin(["A", "B"])]
sessions = exp.groupby("session_id").agg(
    variant=("variant", "first"), device=("device", "first"),
    cart=("event_type", lambda s: "add_to_cart" in set(s)),
    checkout=("event_type", lambda s: "begin_checkout" in set(s)),
    purchase=("event_type", lambda s: "purchase" in set(s)),
)
sessions["revenue"] = exp[exp["event_type"] == "purchase"].groupby("session_id")["detail"].first().astype(float)
sessions["revenue"] = sessions["revenue"].fillna(0)

counts = sessions["variant"].value_counts()
chi2, p_srm = stats.chisquare(counts.values, f_exp=[counts.sum() / 2] * 2)
print("배정 세션 수:", counts.to_dict(), f"/ SRM 검정 p = {p_srm:.3f}")
```

```output
배정 세션 수: {'B': 844, 'A': 843} / SRM 검정 p = 0.981
```

SRM 검정의 p 값이 0.001보다 작으면 배정이 깨진 것으로 보고 원인을 찾는다. 여기서는 균형이 맞다.

### 3단계: 주 지표의 차이와 불확실성

```python
started = sessions[sessions["checkout"]]
summary = started.groupby("variant").agg(n=("purchase", "size"), conversions=("purchase", "sum"))
summary["rate"] = summary["conversions"] / summary["n"]
print(summary.round(3))

pA, pB = summary.loc["A", "rate"], summary.loc["B", "rate"]
nA, nB = summary.loc["A", "n"], summary.loc["B", "n"]
diff = pB - pA
se = np.sqrt(pA * (1 - pA) / nA + pB * (1 - pB) / nB)
ci = (diff - 1.96 * se, diff + 1.96 * se)
p_pool = (summary["conversions"].sum()) / (nA + nB)
z = diff / np.sqrt(p_pool * (1 - p_pool) * (1 / nA + 1 / nB))
p_value = 2 * (1 - stats.norm.cdf(abs(z)))
print(f"차이 {diff:+.3f} ({diff / pA:+.1%} 상대), 95% CI [{ci[0]:+.3f}, {ci[1]:+.3f}], z = {z:.2f}, p = {p_value:.4f}")
```

```output
           n  conversions   rate
variant                         
A        164           94  0.573
B        154          100  0.649
차이 +0.076 (+13.3% 상대), 95% CI [-0.031, +0.183], z = 1.39, p = 0.1639
```

신뢰구간이 0을 포함하지 않으면 사전 결정 규칙에 따라 B를 채택할 수 있다. 신뢰구간이 0을 포함하면 "효과가 없다"가 아니라 **"이 표본으로는 이 크기의 효과를 확인하지 못했다"**이다. 구간의 폭이 곧 실험이 알려 주는 정보의 양이다.

### 5단계: 실험 전에 필요한 표본 크기

이 실험이 5월 한 달로 충분했는지 거꾸로 확인한다.

```python
from statsmodels.stats.power import NormalIndPower
from statsmodels.stats.proportion import proportion_effectsize

baseline = pA
for mde in [0.02, 0.03, 0.05, 0.08]:
    effect = proportion_effectsize(baseline + mde, baseline)
    n_needed = NormalIndPower().solve_power(effect_size=effect, alpha=0.05, power=0.8, ratio=1)
    print(f"MDE {mde:.2f} ({mde / baseline:.0%} 상대) → 집단당 {n_needed:,.0f} 세션 필요 (현재 집단당 약 {min(nA, nB)})")
```

```output
MDE 0.02 (3% 상대) → 집단당 9,538 세션 필요 (현재 집단당 약 154)
MDE 0.03 (5% 상대) → 집단당 4,223 세션 필요 (현재 집단당 약 154)
MDE 0.05 (9% 상대) → 집단당 1,508 세션 필요 (현재 집단당 약 154)
MDE 0.08 (14% 상대) → 집단당 580 세션 필요 (현재 집단당 약 154)
```

작은 효과를 확인하려면 훨씬 많은 세션이 필요하다. 실습 데이터 규모로는 몇 %포인트 차이만 확인할 수 있으며, 실제 쇼핑몰은 하루 세션 수로 필요한 기간을 역산해 실험 기간을 정한다.

## 5. 히트맵: 화면의 관심과 마찰을 찾는다

히트맵은 클릭·스크롤·마우스 이동을 화면 좌표에 겹쳐 보여주는 **관찰 도구**다. 색이 진한 곳은 행동이 많았다는 뜻이지 만족도나 구매 의도를 직접 뜻하지 않는다. 모바일과 데스크톱의 화면 폭이 다르므로 기기별로 분리하고, 페이지 버전이 바뀌면 좌표도 함께 기록한다.

| 신호 | 발견할 수 있는 문제 | 단독으로 말할 수 없는 것 |
|---|---|---|
| CTA 주변 클릭 부족 | 버튼이 잘 안 보일 가능성 | 버튼이 매출을 떨어뜨린 원인 |
| 이미지의 비링크 클릭 | 확대·상세 기대 가능성 | 확대 기능이 구매를 늘린다는 인과 |
| 사이즈표 전 이탈 | 정보 위치·로딩 문제 후보 | 고객이 사이즈 때문에 떠났다는 단정 |
| 낮은 스크롤 도달 | 긴 설명·첫 화면 문제 후보 | 아래 콘텐츠가 불필요하다는 결론 |

히트맵 결과는 분석 가설을 만드는 데 사용한다. 예를 들어 “모바일에서 사이즈표 도달률이 낮다”는 관찰은 “사이즈 안내를 상품 옵션 가까이 옮기면 장바구니 전환율이 오른다”라는 실험 가설로 바뀐다.

## 6. 퍼널: 어디에서 얼마나 이탈하는가

퍼널은 고객이 목표에 도달하기까지의 순서를 단계별로 집계한다.

```text
상품 목록 → 상품 상세 → 사이즈 선택 → 장바구니 → 결제 시작 → 구매
 100%        62%          38%          24%        15%       11%
```

단계 전환율과 전체 전환율을 구분한다. 상세→장바구니 전환율은 장바구니 고객 수를 상세 고객 수로 나누고, 전체 구매 전환율은 구매 고객 수를 퍼널 시작 고객 수로 나눈다. 이벤트 이름만 맞추는 것으로 충분하지 않다. 고객 단위인지 세션 단위인지, 순서를 강제하는지, 몇 시간 안의 행동을 한 퍼널로 보는지 먼저 정한다.

### 세그먼트 퍼널

전체 평균 뒤에 가려진 문제를 찾기 위해 다음 기준으로 나눈다.

- 모바일 / 데스크톱
- 신규 / 재방문
- 광고 / 검색 / 직접 방문
- 카테고리·가격대·재고 상태
- 앱 버전·페이지 버전

세그먼트를 지나치게 많이 나누면 우연한 차이가 커진다. 사전에 중요한 분할 기준을 정하고 표본 수와 신뢰구간을 함께 본다.

## 7. 코호트: 변화가 누구에게 언제 생겼는가

코호트는 같은 시작점이나 경험을 가진 고객 집단이다. 첫 구매월, 가입 주, 캠페인 유입일, 새 상세페이지를 처음 본 주처럼 기준을 정한다. 각 코호트에서 D1·D7·D30 재방문이나 30일 재구매를 비교하면 평균이 지운 시간의 변화를 볼 수 있다.

| 코호트 | D1 재방문 | D7 재방문 | D30 구매 | 해석 후보 |
|---|---:|---:|---:|---|
| 기존 상세페이지 | 31% | 18% | 9% | 기준선 |
| 새 상세페이지 | 35% | 22% | 10% | 탐색 개선 가능성 |
| 할인 캠페인 유입 | 42% | 14% | 6% | 단기 방문은 높고 장기 품질은 낮음 |

코호트 차이는 인과가 아니다. 계절·상품 구성·광고 타깃이 함께 변했을 수 있다. 그래서 코호트는 장기 영향과 이질성을 발견하고, 핵심 변경의 인과효과는 무작위 실험으로 확인한다.

## 8. 네 분석법을 동시에 사용하는 플레이북

사례: 모바일 코트 상세페이지의 구매율이 하락했다.

1. **퍼널**에서 상세→사이즈 선택 구간의 이탈이 커졌음을 확인한다.
2. **히트맵**에서 고객이 옵션 아래의 사이즈표까지 잘 도달하지 못함을 관찰한다.
3. **코호트**에서 새 페이지 배포 이후 첫 방문 고객에게 하락이 집중됐는지 본다.
4. **A/B 테스트**로 사이즈표 위치만 위로 옮긴 B안을 무작위 배정한다.
5. 구매율을 주지표로, 반품률·페이지 속도·문의율을 가드레일로 평가한다.
6. 효과가 확인되면 전체 적용 후 코호트와 관리 지표로 유지 여부를 본다.

이 순서가 항상 고정되는 것은 아니다. 명확한 가설이 있으면 곧바로 실험할 수 있고, 실험 결과가 특정 집단에서만 나타나면 다시 코호트·퍼널 분석으로 돌아간다. 중요한 것은 관찰과 인과 검증을 섞지 않는 것이다.

## 9. 함께 사용되는 보조 분석법

- **세그먼트 비교**: 기기·유입·고객 가치에 따라 효과가 다른지 본다.
- **이상치 감지**: 이벤트 급감, 로딩 오류, 캠페인 봇 유입을 찾는다.
- **회귀 분석**: 기기·가격·재고 같은 공변량을 통제해 효과의 안정성을 점검한다.
- **순차 분석**: 실험을 매일 훔쳐보다 조기 종료하는 오류를 피하도록 중간 점검 규칙을 정한다.
- **정성 분석**: 고객 문의·사용성 테스트로 숫자만으로 알 수 없는 이유를 보완한다.
- **6-Sigma DMAIC**: 발견된 마찰을 정의·측정·분석하고 개선 실험 후 관리 단계로 연결한다.

## 10. 평가 기준

- **사전 결정 규칙**: 실험 전에 적은 규칙(신뢰구간·가드레일·기간)대로 결정했는가. 결과를 보고 규칙을 바꾸지 않는다.
- **peeking 금지**: 정해진 기간·표본에 도달한 뒤 한 번 분석한다. 중간에 보려면 순차 검정 방법을 쓴다.
- **외부 요인**: 실험 기간에 프로모션·장애·시즌 변화가 있었는지 기록한다. 무작위 배정은 두 집단에 같은 영향을 주지만 결과의 일반화 범위를 좁힌다.
- **재현**: 큰 효과가 나오면 다른 기간에 한 번 더 실험한다. 한 번의 실험은 한 번의 관찰이다.

## 12. 벤치마크 데이터셋으로 확장하기

실험 로그 공개 데이터로는 Kaggle의 **Mobile Games A/B Testing (Cookie Cats)**(게이트 위치 변경, 9만 명, 1일·7일 리텐션)과 **Marketing A/B Testing**(광고 노출 vs PSA, 전환)이 널리 쓰인다. 19장의 **GA4 샘플 데이터셋**에는 실험 배정이 없지만, `event_params`에 실험 ID를 넣는 실제 형식을 확인할 수 있다.

```python
# skip-run: Cookie Cats 데이터로 같은 분석 반복하기
cc = pd.read_csv("cookie_cats.csv")                # userid, version(gate_30/gate_40), sum_gamerounds, retention_1, retention_7
s = cc.groupby("version").agg(n=("retention_7", "size"), conversions=("retention_7", "sum"))
s["rate"] = s["conversions"] / s["n"]
# 이후 3단계의 diff·CI·p-value 코드를 그대로 적용한다 (실험 단위는 사용자)
```

<div class="lesson-section-box lesson-activity-box"><strong>짧은 활동</strong></div>

1. 3단계를 "구매 세션 비율(전체 세션 기준)"로 바꾸어 계산하고, 분모가 달라지면 차이와 신뢰구간이 어떻게 달라지는지 비교한다.
2. 5단계에서 검정력을 90%로 올리면 필요한 세션 수가 얼마나 늘어나는지 확인한다.
3. 여러분의 쇼핑몰(또는 자주 쓰는 앱)에서 A/B 테스트할 만한 변경 하나를 골라 1단계의 설계서를 채운다.

<div class="lesson-section-box lesson-summary-box"><strong>이 장의 핵심</strong></div>

- A/B 테스트는 무작위 배정으로 두 화면의 인과효과를 추정하는 유일한 방법이며, 설계서(가설·단위·지표·가드레일·기간·결정 규칙)를 먼저 쓴다.
- 배정 균형(SRM)을 먼저 점검하고, 주 지표의 차이는 신뢰구간과 함께 보고한다. "유의하지 않음"은 "효과 없음"이 아니다.
- 표본 크기는 MDE와 검정력으로 실험 전에 정하고, 중간에 훔쳐보지 않는다.
- 세그먼트 분해는 새 가설이며, 결과는 성공·실패 모두 등록부에 공개한다. 실험 문화가 방법보다 중요하다.

## 핵심 용어

- **A/B 테스트(A/B test)**: 무작위로 나눈 두 집단에 다른 처리를 주어 지표 차이를 비교하는 실험. 예: 결제 화면 A vs B.
- **실험 단위(unit of randomization)**: 배정의 단위. 예: 세션, 고객.
- **주 지표(primary metric)**: 실험의 성패를 판단하는 지표. 예: 결제 시작 → 구매 전환율.
- **가드레일 지표(guardrail metric)**: 나빠지면 안 되는 지표. 예: 구매당 매출.
- **SRM(sample ratio mismatch)**: 배정 비율이 계획과 통계적으로 다른 상태.
- **MDE(minimum detectable effect)**: 정해진 표본과 검정력으로 찾아낼 수 있는 최소 효과 크기.
- **peeking**: 계획된 종료 전에 결과를 보고 멈추는 행동. 오경보를 늘린다.

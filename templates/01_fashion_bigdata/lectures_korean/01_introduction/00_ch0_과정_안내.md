# Course Guide

> **데이터를 이해하는 힘에서 검증 가능한 AI 활용까지**  
> 패션 비즈니스에서 데이터가 어떻게 만들어지는지 이해하고, 분석 결과를 의사결정·콘텐츠·자동화로 연결하는 전 과정을 배운다.

## 하나의 45장 과정으로 구성한 이유

기존의 `패션 빅데이터 1`은 데이터의 의미·구조·비교·인과와 증거 판단을, `패션 빅데이터 2`는 수집·분석·생성형 AI 실습을 담당했다. 그러나 실제 업무에서는 개념과 실습이 분리되지 않는다. 무엇을 측정했는지 모르면 코드를 실행해도 결과를 해석할 수 없고, 분석을 직접 만들어 보지 않으면 데이터의 한계를 구체적으로 판단하기 어렵다.

따라서 두 과정을 **「패션 데이터 분석과 AI 활용」**이라는 하나의 과정으로 통합했다. 앞부분에서 데이터와 증거를 읽는 기준을 만들고, 뒷부분에서 같은 기준을 실제 패션 데이터 분석과 생성형 AI 프로젝트에 적용한다.

## 권장 학습 순서

1~18장은 코딩 경험이 없어도 학습할 수 있다. 표의 행과 열, 평균과 비율을 읽을 수 있으면 충분하다. 7장에서 다섯 분석 방법을 개괄하고, 8장에서 분석 대상과 가설, 9장에서 전처리를 배운다. 10~14장은 특성화·차별화, 빈발 패턴, 분류·회귀, 군집, 이상치 감지를 각각 자세히 다루며 15장에서 결과를 종합 평가한다. 이어서 16~18장에서 분석 시스템을 데이터가 있는 곳(저장·이동), 도입 전 비용 산정, 도입 후 운영·보안의 순서로 이해한다. 코드를 처음 다룬다면 [Python Basic](templates/02_python_basic/lectures_korean/00_ch0_과정_안내.md)을 먼저 학습하고 19장으로 돌아오는 것을 권장한다.

19~45장은 Python과 pandas 코드를 직접 실행하는 적용 과정이다. 19장에서 도구(코랩)와 실습 데이터를 준비한 뒤, 20~39장에서는 판매·고객·추천·시장·고객 경험 사례를 직접 분석한다. 통합된 장은 관련 방법을 한 흐름에서 함께 다룬다. 각 실습 장은 **사용 데이터와 데이터 특징 → 분석 방법 → 단계별 절차 → 단계별 실습 → 평가 기준 → 서비스 연동과 시스템 구성 → 벤치마크 데이터셋으로 확장**이라는 공통 구조를 따르므로, 한 장을 익히면 나머지 장도 같은 방식으로 읽을 수 있다. 41~45장은 콘텐츠·생성형 AI·자동화와 최종 프로젝트로 과정을 마무리한다.

각 장의 목표는 단순히 코드를 완성하는 것이 아니라, 질문·분모·기간·식별자·비교 기준과 오류 가능성을 기록하면서 결과를 검증하는 것이다. 분석 결과를 어떤 화면·알림·API로 내보낼지(서비스 연동)와 그 조치를 자동화해도 되는지까지가 한 장의 범위다.

## 강의에서 만나는 법칙과 원칙을 읽는 방법

이 과정에는 여러 분야에서 오래 사용된 법칙·정리·효과를 관련 장에 배치했다. 이름에 모두 ‘법칙’이 붙더라도 성격은 다르다.

- **수학적 결과**는 정해진 가정 안에서 성립한다. Amdahl의 법칙과 No Free Lunch 정리가 여기에 가깝다.
- **경험적 일반화**는 여러 시장이나 데이터에서 반복 관찰된 패턴이다. 더블 제퍼디와 침투율 법칙은 새로운 시장 데이터에서도 직접 확인해야 한다.
- **실무 원칙과 휴리스틱**은 질문을 만들고 오류를 점검하는 출발점이다. Pareto의 80/20은 항상 정확히 80과 20으로 나뉜다는 자연법칙이 아니다.

| 원칙 | 연결 장 | 이 과정에서 사용하는 질문 |
|---|---:|---|
| Garbage In, Garbage Out | 2 | 운영 기록의 품질이 분석 결과를 제한하는가? |
| Double Jeopardy·침투율 법칙 | 10 | 작은 브랜드의 구매자 수와 재구매를 어떻게 비교할까? |
| Simpson의 역설 | 10 | 전체와 세부 집단에서 관계의 방향이 달라지는가? |
| 평균으로의 회귀 | 14 | 극단적인 판매량이 다음 시점에 평소로 돌아오는가? |
| Goodhart의 법칙 | 15·41 | 지표가 목표가 될 때 행동이 지표를 왜곡하는가? |
| Moore의 법칙·기회비용·수확 체감 | 17 | 견적에 미래 가격 하락을 넣어도 되는가? 추가 비용이 다른 선택을 밀어내는가? |
| Amdahl의 법칙 | 18 | 병렬화가 전체 작업 시간을 얼마나 줄이는가? |
| Zipf의 법칙 | 23 | 소수의 단어와 많은 희귀 단어를 어떻게 해석할까? |
| 기저율과 평균으로의 회귀 | 20 | 드문 경보와 극단값을 왜 다시 확인해야 하는가? |
| Pareto 원칙 | 21·27 | 고객·상품 가치가 실제로 얼마나 집중되어 있는가? |
| 차원의 저주 | 22 | 고차원에서 거리만 믿어도 되는가? |
| Long Tail | 36·39 | 낮은 빈도의 구체적 검색·추천 수요를 합치면 의미가 있는가? |
| No Free Lunch | 45 | 모든 패션 업무에 가장 좋은 모델이 하나뿐인가? |

각 원칙은 정답으로 암기하기보다 **정의 → 패션 사례 → 적용 조건 → 직접 확인할 지표** 순서로 사용한다.

## 과정 전체의 학습 원칙

- 데이터가 많다는 이유로 대표성·정확성·인과가 자동으로 확보된다고 가정하지 않는다.
- 값의 의미, 관측 범위, 제외 규칙, 비교 기준과 JOIN 결과를 먼저 확인한다.
- 실행되는 코드와 믿을 수 있는 분석을 구분한다.
- 생성형 AI가 만든 설명·코드·이미지도 원자료, 공식 출처와 작은 평가셋으로 검증한다.
- 모델 성능뿐 아니라 비용·지연·프라이버시·편향·사람의 승인과 중단 조건을 함께 평가한다.

## 완료 기준

45장에서 하나의 패션 업무를 골라 입력 데이터, 근거, 처리 규칙, 평가 사례, 사람의 승인 범위, 자동 중단과 되돌리기를 포함한 최종 프로젝트를 완성한다. 결과가 바뀌면 판단도 바꿀 수 있도록 가정과 한계를 함께 기록해야 이 과정을 완료한 것이다.

<div class="lesson-section-box lesson-activity-box"><strong>짧은 활동</strong></div>

관심 있는 패션 업무 하나를 고르고 `결정 / 필요한 데이터 / 분석 방법 / 결과를 확인할 지표 / 사람이 승인할 지점`을 한 줄씩 적는다. 과정이 끝난 뒤 같은 표를 다시 작성해 무엇이 구체화되었는지 비교한다.

<div class="lesson-section-box lesson-summary-box"><strong>이 장의 핵심</strong></div>

- 과정은 데이터의 생성과 구조, 분석, 시스템, 적용의 흐름으로 진행된다.
- 분석 방법은 질문의 답 형태에 따라 선택하며, 여러 방법이 한 의사결정에 함께 쓰일 수 있다.
- 생성형 AI의 결과도 원자료·공식 근거·평가셋과 사람의 승인으로 검증한다.
- 최종 결과물은 보기 좋은 분석이 아니라 행동·평가·중단 조건이 포함된 의사결정 설계다.

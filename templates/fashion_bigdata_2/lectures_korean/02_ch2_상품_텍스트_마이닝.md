# 상품 텍스트에서 신호 찾기: 정제·분류·검증

상품명에는 카테고리, 실루엣, 소재, 색상과 프로모션 문구가 함께 들어 있다. 이 장에서는 상품 텍스트를 정제한 뒤 단순 빈도, 규칙 기반 속성 분류, 임베딩과 생성형 AI 보조 분류를 비교한다. **어떤 방법을 쓰든 원문 표본과 분류 오류를 사람이 검증하는 것**이 중심이다.

## 생각해 보기: 많이 보인 단어는 곧 유행일까?

> “요즘 잘 팔리는 상품 이름에는 공통점이 있을까?”

180개 랭킹 상품명에서 `오버`가 38번 나왔다면 적어도 **이 표본의 상품명에서 자주 노출된 표현**이라고 말할 수 있다. 그러나 이것만으로 소비자가 오버핏을 더 많이 구매했다거나 시장 전체에서 유행이 커졌다고 단정할 수는 없다.

| 관찰한 데이터 | 바로 말할 수 있는 것 | 아직 말할 수 없는 것 |
|---|---|---|
| 특정 시점의 랭킹 상품명 180개 | 이 표본에서 어떤 표현이 많이 노출되었는가 | 시장 전체의 장기 트렌드 |
| 상품별 판매량이 포함된 데이터 | 어떤 표현을 가진 상품의 판매량이 높은가 | 그 표현이 판매의 원인인가 |
| 여러 시점에 같은 방식으로 수집한 데이터 | 표현의 비중이 증가·감소했는가 | 앞으로도 계속 증가할 것인가 |

> **핵심 관찰**
> 한 시점의 빈도는 **현재 구성의 스냅샷**이다. 트렌드라고 부르려면 같은 조건으로 여러 시점을 비교해야 한다.

## 학습 목표

이 장을 마치면 다음을 할 수 있다.

- pandas로 여러 엑셀 파일의 컬럼 이름을 통일하고 하나의 표로 합칠 수 있다.
- 결측값, 중복, 가격 문자열을 점검하고 분석 가능한 값으로 정제할 수 있다.
- 공백 분리와 한국어 형태소 분석의 차이를 설명할 수 있다.
- 불용어와 도메인 사전을 적용하기 전후의 빈도를 비교할 수 있다.
- 단어 빈도, 규칙 기반 라벨, 임베딩과 생성형 AI 분류의 역할을 구분할 수 있다.
- 구조화된 AI 라벨을 원문 표본과 평가셋으로 검증할 수 있다.
- 막대그래프와 상자그림을 우선하고 워드클라우드는 보조 표현으로 구분할 수 있다.
- 한 시점의 노출 구성과 여러 시점의 트렌드를 구분해 해석할 수 있다.

## 핵심 용어

- **토큰(token)**: 분석을 위해 나눈 최소 단위. 이 장에서는 주로 상품명의 단어를 뜻한다.
- **토큰화(tokenization)**: 문장을 토큰의 목록으로 바꾸는 과정.
- **형태소 분석(morphological analysis)**: 문장을 의미를 가진 단위로 나누고 품사를 판별하는 과정.
- **불용어(stopword)**: 분석 목적과 관계가 작아 제외하기로 정한 단어나 기호.
- **정규화(normalization)**: `크루 넥`, `크루넥`처럼 같은 뜻의 여러 표기를 하나로 통일하는 과정.
- **빈도(frequency)**: 특정 토큰이 등장한 횟수. 판매량이나 소비자 수와는 다른 값이다.

> **읽기 안내**
> 이 장의 핵심 경로는 질문 고정 → 파일 합치기 → 정제 → 빈도와 의미 분류 → 원문 표본 검증 → 행동 연결이다. 워드클라우드와 상세 형태소 도구 문법은 선택 참고다.

## 1. 분석 질문을 먼저 고정하기

같은 상품명도 질문에 따라 세는 방법이 달라진다.

| 질문 | 분석 단위 | 필요한 처리 | 결과 예시 |
|---|---|---|---|
| 어떤 단어가 많이 쓰였는가? | 단어 등장 횟수 | 토큰화·불용어 제거 | `오버` 38회 |
| 몇 개 상품이 `오버`를 포함하는가? | 상품 수 | 상품별 중복 토큰 제거 | 180개 중 34개 |
| `오버` 상품이 더 많이 팔렸는가? | 상품별 판매량 | 상품명과 거래 데이터 연결 | 평균 판매량 차이 |
| `오버`의 비중이 커지는가? | 시점별 상품 비율 | 반복 수집·표본 조건 통일 | 월별 포함률 변화 |

이 장의 기본 질문은 첫 번째인 **“랭킹 상품명에서 어떤 표현이 자주 등장하는가?”**이다. 판매 원인을 찾는 분석이 아니라 탐색 단계의 신호 찾기다.

## 3. 두 엑셀 파일을 같은 구조로 합치기

먼저 구글 드라이브의 두 크롤링 결과를 불러온다. [`pandas.read_excel`](https://pandas.pydata.org/docs/reference/api/pandas.read_excel.html)은 엑셀 파일을 표 형태의 DataFrame으로 읽는 공식 함수다.

```python
from google.colab import drive
drive.mount('/content/drive')

import pandas as pd

df_1 = pd.read_excel('/content/drive/MyDrive/musinsa_1.xlsx')
df_2 = pd.read_excel('/content/drive/MyDrive/musinsa_2.xlsx')
```

리스틀리로 수집한 원본은 `LABEL-8`, `LABEL-9`처럼 컬럼 이름이 자동으로 붙을 수 있다. 각 파일에서 상품명과 가격 컬럼을 고르고 같은 이름으로 바꾼다.

```python
df_1_clean = (
    df_1[["LABEL-8", "LABEL-9"]]
    .rename(columns={"LABEL-8": "product_name", "LABEL-9": "price"})
)

df_2_clean = (
    df_2[["LABEL-7", "LABEL-8"]]
    .rename(columns={"LABEL-7": "product_name", "LABEL-8": "price"})
)

df = pd.concat([df_1_clean, df_2_clean], ignore_index=True)
```

[`pandas.concat`](https://pandas.pydata.org/docs/reference/api/pandas.concat.html)은 같은 의미의 컬럼을 가진 표를 행 방향으로 이어 붙인다. `ignore_index=True`는 합친 뒤 행 번호를 0부터 다시 매긴다.

### 합친 직후 품질 점검

```python
print("행 수:", len(df))
print("결측값 수:\n", df.isna().sum())
print("완전히 같은 행 수:", df.duplicated().sum())

df = df.dropna(subset=["product_name"])
df = df.drop_duplicates(subset=["product_name", "price"])
```

| 점검 항목 | 확인 이유 | 발견했을 때의 선택 |
|---|---|---|
| 합치기 전·후 행 수 | 일부 페이지가 빠지거나 이중 수집되었는지 확인 | 원본 페이지와 수집 범위 재확인 |
| 상품명 결측 | 토큰화할 텍스트가 없음 | 분석에서 제외하고 제외 수 기록 |
| 완전 중복 | 같은 상품이 두 번 세어질 수 있음 | 상품 ID가 있으면 ID 기준 제거 |
| 컬럼 의미 | 파일마다 `LABEL-8`의 뜻이 다를 수 있음 | 원본 화면과 샘플 5행 대조 |

> **즉시 해석**
> `len(df) == 180`은 180명의 소비자나 180건의 구매를 뜻하지 않는다. 현재 표에 남은 **상품 행이 180개**라는 뜻이다.

## 4. 가격 문자열을 숫자로 바꾸기

가격 컬럼에는 `49,000원\n39,800원`처럼 정상가와 할인가가 함께 들어올 수 있다. 무엇을 가격으로 사용할지 먼저 정해야 한다. 아래 코드는 **처음 나타나는 원화 금액을 정상가로 간주**하는 예시다.

```python
price_text = df["price"].astype("string")

df["price_origin"] = pd.to_numeric(
    price_text
        .str.extract(r"([0-9][0-9,]*)\s*원", expand=False)
        .str.replace(",", "", regex=False),
    errors="coerce"
)
```

[`pandas.to_numeric`](https://pandas.pydata.org/docs/reference/api/pandas.to_numeric.html)의 `errors="coerce"`는 숫자로 바꿀 수 없는 값을 오류로 멈추는 대신 결측값 `NaN`으로 표시한다. 그 뒤 실패한 원문을 확인한다.

```python
failed = df.loc[df["price_origin"].isna(), ["product_name", "price"]]
display(failed.head())
```

| 원문 | 단순 분리의 위험 | 사전 규칙 |
|---|---|---|
| `49,000원\n39,800원` | 첫 값만 남지만 의미가 정상가인지 불명확 | 정상가와 판매가를 별도 컬럼으로 저장 |
| `쿠폰가 35,820원` | 쿠폰 조건이 사라짐 | 조건부 가격 여부를 따로 표시 |
| `품절` | 정수 변환 오류 | 결측 처리 후 원문 보존 |
| `39,800` | `원`이 없어 추출 실패 | 허용 형식을 문서화하고 예외 처리 |

가격 정제는 문자열 기술보다 **어떤 금액을 비교할 것인지 정의하는 일**이 먼저다.

## 5. 상품명을 토큰으로 바꾸기

상품명 `워셔블 하프 집업 카라넥 하찌 니트`를 공백으로만 나누면 빠르게 시작할 수 있지만, 한국어 품사와 붙여 쓴 단어를 충분히 처리하지 못한다. 이 실습에서는 [KoNLPy의 `Okt`](https://konlpy.org/ko/latest/api/konlpy.tag/#okt-class)를 사용해 명사를 추출한다.

```python
!pip install konlpy
from konlpy.tag import Okt

okt = Okt()
df["name_noun_raw"] = df["product_name"].apply(
    lambda text: okt.nouns(str(text))
)
```

형태소 분석기의 출력도 정답 그 자체는 아니다. 패션 도메인에서는 `크루넥`이 `크루`, `넥`으로 갈리거나 영문 브랜드명이 빠질 수 있다.

| 방식 | 예시 출력 | 장점 | 한계 |
|---|---|---|---|
| 공백 분리 | `['크루넥', '오버핏', '니트']` | 빠르고 원문 보존 | 기호·조사·붙여쓰기에 약함 |
| Okt 명사 추출 | `['크루', '넥', '오버', '핏', '니트']` | 한국어 품사 활용 | 패션 복합어가 분리될 수 있음 |
| 도메인 정규화 | `['크루넥', '오버핏']` | 질문에 맞는 표현 통일 | 사전을 사람이 만들고 관리해야 함 |

### 불용어와 표기 통일 적용하기

먼저 원본 토큰을 보존한 뒤, 분석용 토큰을 별도 컬럼으로 만든다.

```python
stop_words = {"니트", "배송", "무료", "단독", "특가"}
normalize_map = {
    "오버": "오버핏",
    "오버사이즈": "오버핏",
    "라운드": "크루넥",
    "크루": "크루넥"
}

def clean_tokens(tokens):
    normalized = [normalize_map.get(word, word) for word in tokens]
    return [
        word for word in normalized
        if len(word) > 1 and word not in stop_words
    ]

df["name_noun"] = df["name_noun_raw"].apply(clean_tokens)
```

`니트`를 불용어로 뺀 것은 니트 카테고리 안에서 **세부 특징**을 보려는 이번 질문에 맞춘 선택이다. 전체 의류 카테고리를 비교한다면 `니트`는 중요한 토큰이므로 빼면 안 된다.

> **즉시 해석**
> 불용어 목록과 정규화 사전은 중립적인 청소 도구가 아니다. 무엇을 중요한 신호로 볼지 정하는 분석 규칙이므로 결과와 함께 공개해야 한다.

## 6. 단어 빈도 세기

파이썬 표준 라이브러리의 [`collections.Counter`](https://docs.python.org/3/library/collections.html#collections.Counter)는 항목별 등장 횟수를 센다.

```python
from collections import Counter

raw_result = Counter(
    word
    for tokens in df["name_noun_raw"]
    for word in tokens
)

clean_result = Counter(
    word
    for tokens in df["name_noun"]
    for word in tokens
)

print("원본:", raw_result.most_common(10))
print("정제 후:", clean_result.most_common(10))
```

실제 강의의 원본 토큰 상위 10개는 다음과 같았다.

| 순위 | 원본 단어 | 등장 횟수 | 바로 확인할 질문 |
|---:|---|---:|---|
| 1 | 니트 | 142 | 카테고리명이라 당연히 많은가? |
| 2 | 넥 | 49 | `크루넥`, `브이넥`이 분리된 결과인가? |
| 3 | 오버 | 38 | `오버핏`과 같은 뜻으로 묶을 것인가? |
| 4 | 크루 | 36 | `크루넥` 복합어를 복원해야 하는가? |
| 5 | 블랙 | 29 | 실제 색상인가, 상품명 문구인가? |
| 6 | 집업 | 27 | 형태 특징으로 해석 가능한가? |
| 7 | 카라 | 23 | `카라넥`과 중복되는가? |
| 8 | 라운드 | 21 | `크루넥`과 같은 그룹인가? |
| 9 | 하프 | 19 | 길이인가, `하프집업`의 일부인가? |
| 10 | 배송 | 18 | 상품 특징이 아닌 운영 문구인가? |

`배송`이 상위에 있다는 사실은 실패가 아니라 유용한 진단이다. 화면의 배지나 프로모션 문구가 상품명과 함께 수집되었거나, 불용어 규칙이 필요하다는 뜻이다.

## 7. 빈도 너머의 의미를 분류하고 검증한다

빈도는 같은 문자열을 세는 데 강하지만 `크루넥`, `라운드넥`, `crew neck`이 같은 속성인지 자동으로 알지 못한다. 분석 목적에 따라 세 접근을 선택할 수 있다.

| 접근 | 적합한 상황 | 장점 | 반드시 확인할 한계 |
|---|---|---|---|
| 규칙·사전 | 소재·색·실루엣 용어가 비교적 명확함 | 기준을 설명하고 재현하기 쉬움 | 신조어·문맥·중의어 누락 |
| 임베딩·유사도 | 표현이 달라도 의미가 가까운 문장을 묶음 | 동의어와 문맥을 일부 반영 | 가까움이 정확한 속성 라벨은 아님 |
| 생성형 AI 분류 | 여러 문맥을 정해진 스키마로 초안 분류 | 초기 라벨링과 예외 후보 탐색이 빠름 | 추측·일관성·모델 버전·개인정보 위험 |

### 구조화된 분류 계약

생성형 AI에 상품명을 분류시킬 때는 자유로운 설명보다 허용된 필드와 값을 먼저 정한다.

```json
{
  "product_id": "P501",
  "category": "outer",
  "silhouette": "oversized",
  "material_claim": "wool blend",
  "evidence_text": "오버사이즈 울 블렌드 코트",
  "needs_review": false
}
```

- 원문에 없는 소재·기능을 추측하지 않는다.
- 허용값 밖이면 임의의 새 라벨 대신 `other` 또는 `needs_review`를 사용한다.
- `evidence_text`에 판단 근거가 된 실제 구절을 남긴다.
- 개인 식별정보나 비공개 상품 정보를 외부 모델에 보내기 전에 사용 조건을 확인한다.

### 작은 평가셋으로 품질 확인

전체 자동 분류 전에 정상 사례, 모호한 사례와 중요한 오류 사례를 30~50개 정도 사람이 먼저 라벨링한다. 방법별 결과를 같은 표에서 비교한다.

| 평가 항목 | 질문 |
|---|---|
| 정확성 | 소재·색·실루엣 라벨이 사람 기준과 일치하는가? |
| 누락 | 원문에 있는 핵심 속성을 놓쳤는가? |
| 환각 | 원문에 없는 기능·소재를 만들었는가? |
| 일관성 | 같은 표현을 반복 실행하거나 다른 배치에서도 같은 기준으로 처리하는가? |
| 검토 비용 | 사람이 수정해야 하는 비율과 시간은 얼마인가? |

정확도가 낮은 라벨을 대량으로 만드는 것보다 `needs_review`로 보내는 조건을 명확히 하는 편이 안전하다. 모델이나 프롬프트를 바꾸면 같은 평가셋으로 다시 측정한다.

## 9. 가격 분포는 상자그림으로 확인하기

결측 가격을 제외하고 상자그림을 그린다.

```python
price_values = df["price_origin"].dropna()

ax.boxplot(price_values)

plt.show()
```

[Matplotlib의 `boxplot`](https://matplotlib.org/stable/api/_as_gen/matplotlib.pyplot.boxplot.html)은 기본적으로 다음 정보를 보여준다.

| 요소 | 의미 |
|---|---|
| 상자 아래·위 | 제1사분위수(Q1)와 제3사분위수(Q3) |
| 상자 안의 선 | 중앙값 |
| 상자 높이 | 사분위 범위 `IQR = Q3 - Q1` |
| 수염 | 기본 설정에서 `Q1 - 1.5×IQR`과 `Q3 + 1.5×IQR` 안의 가장 먼 관측값까지 |
| 수염 밖 점 | 통계적으로 별도 확인할 후보인 이상값 |

수염은 항상 최솟값과 최댓값을 뜻하지 않는다. 수염 밖의 고가 상품도 데이터 오류일 수도 있고 실제 프리미엄 상품일 수도 있으므로 원문을 확인해야 한다.

## 10. 스냅샷에서 트렌드 비교로 확장하기

1월과 2월에 같은 카테고리, 같은 랭킹 범위, 같은 수집 방식으로 각각 상품명을 모았다고 하자. 표본 수가 다르면 단순 횟수보다 **상품 100개당 포함 상품 수**를 비교한다.

\[
\text{용어 포함률}_{t}(w)
=\frac{\text{시점 }t\text{에서 용어 }w\text{를 포함한 상품 수}}
{\text{시점 }t\text{의 전체 상품 수}}
\times 100
\]

| 용어 | 1월 포함률 | 2월 포함률 | 관찰 | 대안 설명 |
|---|---:|---:|---|---|
| 오버핏 | 18% | 27% | 표본 내 노출 비중 증가 | 랭킹 정책·브랜드 구성 변화 |
| 집업 | 14% | 13% | 거의 변화 없음 | 표본 오차·계절 영향 |
| 배송 | 8% | 21% | 운영 문구 증가 | 수집 선택자나 화면 UI 변경 |

시계열 비교에서도 “판매 원인”이라는 표현은 피한다. 증가한 용어가 실제 판매량, 검색량, 클릭률과 함께 움직이는지 추가로 확인해야 한다.

## 이 장의 핵심

- 분석 질문에 따라 단어 등장 횟수, 포함 상품 수, 판매량과 시점별 비중은 서로 다른 지표가 된다.
- `read_excel`로 읽은 표는 컬럼 이름을 통일하고 결측·중복·행 수를 점검한 뒤 `concat`으로 합친다.
- 가격 문자열은 의미를 먼저 정한 뒤 숫자로 바꾸고, 변환 실패 원문을 확인한다.
- Okt의 결과도 완전한 정답이 아니므로 패션 복합어 정규화와 불용어 규칙을 검토한다.
- 원본 빈도와 정제 후 빈도를 함께 제시해야 분석자의 판단이 결과를 어떻게 바꾸었는지 알 수 있다.
- 규칙, 임베딩과 생성형 AI 분류는 서로 다른 장단점이 있으며, 구조화된 라벨도 원문 근거와 사람이 만든 작은 평가셋으로 검증한다.
- 막대그래프는 정확한 비교, 상자그림은 중앙값·IQR·이상값 후보 확인에 알맞고 워드클라우드는 선택 보조 자료다.
- 한 시점의 상품명 빈도는 노출 구성의 스냅샷이다. 트렌드는 반복 수집한 동일 조건의 비율로 확인한다.

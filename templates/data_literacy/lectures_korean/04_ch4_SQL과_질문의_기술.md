# SQL과 질문의 기술

데이터가 아무리 잘 쌓여 있어도 원하는 답을 꺼내지 못하면 소용이 없다. 이 장에서는 “잘 나가는 스타일이 뭘까?”라는 막연한 궁금증을 컴퓨터가 실제로 답할 수 있는 정확한 질문으로 바꾸는 방법을 다룬다. 그 도구가 바로 **SQL(Structured Query Language)**이다.

## 학습 목표

- 모호한 질문을 기간·분석 단위·지표·비교 기준으로 구체화한다.
- SELECT, FROM, WHERE, GROUP BY의 역할을 설명한다.
- 쿼리 결과가 답하지 못하는 범위를 함께 기록한다.

## 실무자가 SQL을 알아야 하는 이유

SQL을 배운다고 해서 개발자가 될 필요는 없다. 기획, 마케팅, MD 업무에서 SQL이 중요한 이유는 코드를 짜는 기술 자체보다 **자신의 가설을 정확한 데이터 요청으로 번역하는 능력** 때문이다.

“요즘 뭐가 잘 팔려요?”라는 질문을 데이터팀에 그대로 전달하면, 데이터팀은 기간, 기준(판매량인지 매출인지), 비교 대상(전체인지 카테고리별인지)을 다시 되물어야 한다. 이 왕복이 반복되면 의사결정 속도가 느려진다. SQL의 문법을 이해하고 있으면 질문을 처음부터 명확한 조건으로 정리할 수 있고, 데이터팀과의 협업 속도가 크게 빨라진다.

## 데이터 추출의 논리

SQL의 핵심 문법은 질문의 구조와 그대로 대응한다.

- **SELECT**: 무엇을 보고 싶은가 (상품명, 판매량, 매출)
- **FROM**: 어떤 데이터에서 찾을 것인가 (판매 이력 표)
- **WHERE**: 어떤 조건으로 좁힐 것인가 (특정 시즌, 특정 카테고리)
- **GROUP BY**: 무엇을 기준으로 묶어서 볼 것인가 (스타일별, 사이즈별, 매장별)

예를 들어 “이번 여름 시즌 원피스 카테고리에서 사이즈별 판매량을 보고 싶다”는 요청은 판매 이력 표에서(FROM) 원피스이면서 여름 시즌인 조건으로(WHERE) 사이즈별로 묶어(GROUP BY) 판매량을 집계하는(SELECT) 문장으로 바뀐다. 문법을 몰라도 이 네 가지 질문에 스스로 답할 수 있다면 이미 데이터 요청의 절반은 끝난 것이다.

| SQL 키워드 | 질문 형태 | 이번 예시 |
| --- | --- | --- |
| SELECT | 무엇을 보고 싶은가 | 사이즈, 판매량 |
| FROM | 어떤 데이터에서 찾을 것인가 | 판매 이력 표 |
| WHERE | 어떤 조건으로 좁힐 것인가 | 카테고리 = 원피스, 시즌 = 여름 |
| GROUP BY | 무엇을 기준으로 묶을 것인가 | 사이즈별 |

```sql
SELECT size, SUM(quantity) AS total_sold
FROM sales_history
WHERE category = '원피스' AND season = '여름'
GROUP BY size
ORDER BY total_sold DESC;
```

## 모호한 요청을 구체화하기

“잘 나가는 스타일이 뭐예요?”라는 문장은 편하게 말할 수 있지만 데이터로는 답할 수 없다. 다음 항목이 정해지지 않았기 때문이다.

- **기간**: 최근 1주일인가, 이번 시즌 전체인가?
- **기준 지표**: 판매 수량인가, 매출인가, 재고 대비 판매 속도인가?
- **비교 집단**: 전체 상품 대비인가, 같은 카테고리 대비인가, 같은 가격대 대비인가?

이 세 가지를 정하지 않은 채 데이터를 요청하면 담당자마다 다른 답을 만들게 되고, 같은 질문에 서로 다른 숫자가 나와 신뢰가 떨어진다. 협업은 모호한 요청을 구체적인 조건으로 바꾸는 순간부터 시작된다. “잘 나가는 스타일”을 “최근 2주간 재고 대비 판매 속도 상위 10개 스타일”처럼 바꾸면 누가 추출해도 같은 답이 나온다.

## 데이터 실습: 베스트셀러와 스타일별 판매 기여도

패션 거래 데이터에서 베스트셀러를 뽑는 과정을 단계별로 생각해 보자.

1. 판매 이력 표에서 분석 기간을 조건으로 좁힌다(WHERE).
2. 스타일 단위로 판매 수량과 매출을 합산한다(GROUP BY, SELECT).
3. 합산된 결과를 매출이 큰 순서로 정렬한다(ORDER BY).
4. 상위 몇 개를 베스트셀러로 선정할지 기준을 정한다(LIMIT).

여기에 한 걸음 더 나아가면 “스타일별 판매 기여도”를 구할 수 있다. 각 스타일의 매출을 전체 카테고리 매출로 나누면 하나의 스타일이 전체 실적에서 차지하는 비중이 드러난다. 이 비중이 특정 스타일에 지나치게 쏠려 있다면, 그 스타일이 품절되었을 때의 리스크도 함께 검토해야 한다는 신호다.

| 스타일 | 매출(만 원) | 카테고리 내 비중 |
| --- | --- | --- |
| 린넨 셔츠 원피스 | 3,200 | 32% |
| 플리츠 미디 원피스 | 2,100 | 21% |
| 그 외 8개 스타일 합계 | 4,700 | 47% |

## 이 장의 핵심

- SQL의 가치는 코딩 실력이 아니라 가설을 정확한 질문으로 번역하는 능력에 있다.
- SELECT-FROM-WHERE-GROUP BY는 무엇을, 어디서, 어떤 조건으로, 어떻게 묶어 볼지를 나타낸다.
- “잘 나가는 스타일”처럼 모호한 요청은 기간, 지표, 비교 집단을 정해야 데이터로 답할 수 있다.
- 조건을 명확히 정의하면 누가 데이터를 추출해도 같은 결과가 나와 협업의 신뢰가 높아진다.
- 베스트셀러 분석은 단순 판매량을 넘어 전체 대비 기여도와 쏠림 리스크까지 함께 봐야 한다.

## 알아볼 것: 생성형 AI로 풀어보는 과제

1. **자연어를 SQL로 변환하기**: “이번 여름 시즌 원피스 카테고리에서 사이즈별 판매량을 매출 순으로 보여줘”처럼 이 장에서 다룬 모호한 질문을 직접 만들고, 생성형 AI에게 표 구조(판매 이력 표에 어떤 컬럼이 있는지)를 알려준 뒤 SQL 쿼리를 작성해달라고 요청한다. AI가 만든 SELECT-FROM-WHERE-GROUP BY 구조가 질문의 조건을 빠짐없이 반영했는지 하나씩 대조한다.
2. **모호한 요청 구체화 연습**: 생성형 AI에게 “‘잘 나가는 스타일이 뭐야?’라는 모호한 질문을 데이터로 답할 수 있는 구체적인 질문 3가지로 바꿔줘”라고 요청하고, 각 질문에 필요한 기간·지표·비교 집단이 명확한지 점검한다.
3. **쿼리 결과 해석 검증**: 생성형 AI가 만들어준 베스트셀러 추출 쿼리 결과(가상 데이터로 실행하거나 AI가 만든 예시 결과)를 놓고, “이 결과에서 특정 스타일에 매출이 지나치게 쏠려 있는지 판단해줘”라고 요청한 뒤, AI의 해석 근거가 타당한지 직접 계산해 검증한다.

## 학습 점검

3. 매출 상위 상품 표만으로 수요가 증가한 원인을 알 수 없는 이유는 무엇인가?

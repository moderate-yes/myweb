# Chapter 3: Identifiers and Fashion Master Data

If there are two products with the same name, a computer cannot tell which one is meant. Humans distinguish between them using context, but a system cannot do that. This chapter covers what kind of **addressing system** — that is, identifiers — a fashion business uses to accurately link products and inventory.

## Why SKUs Are Needed, Not Just Product Names

The name "white shirt" can point to different products depending on the season or the store. Names are given in a way that is familiar to people, for marketing and search purposes, but they are not suited to determining whether something is exactly the same product. Even with the same name, the fabric might have changed, and even with a changed name, it might be the same product.

A **SKU (Stock Keeping Unit)** is a unique identifier meant to prevent this kind of confusion. If one SKU is assigned per combination of brand, season, product, color, and size, then no matter how similar the names look, the system can point to exactly the same piece of inventory. Think of the name as an expression for people, and the SKU as an address for the system.

## Designing Keys for Fashion Entities

When designing identifiers, you must decide what unit counts as a single entity. Fashion products are divided into several layers.

- **Style**: The higher-level unit referring to the design itself. Different colors and sizes can still be the same style.
- **Colorway**: The unit distinguished by color within the same style.
- **SKU**: The smallest unit that combines a colorway with a size, allowing actual inventory to be counted.

Getting this hierarchy wrong causes problems. If inventory is managed only at the style level, ignoring color, you cannot tell whether a specific color is out of stock; conversely, if it is broken down too finely, the system becomes complex and management costs grow. Which attributes to include as part of the key — brand, season, category, color, size — should be decided based on the minimum unit needed for actual inventory management and sales analysis.

| Layer | Example | Distinguishing criterion |
| --- | --- | --- |
| Style | Oversized round-neck knit | The design itself |
| Colorway | Oversized round-neck knit · Ivory | Style + color |
| SKU | Oversized round-neck knit · Ivory · M | Colorway + size (smallest unit of inventory) |

## Separating Identifiers from Actual Data

An important principle in identifier design is to **look up with a lightweight key first, and only load heavy detailed information when it is actually needed**. A SKU itself is a short value made of letters and numbers, but the product it points to carries much heavier data attached to it, such as images, fabric information, detailed descriptions, and reviews.

Frequently repeated tasks like search or inventory lookup are processed quickly using just the SKU, and heavy data such as images and descriptions is loaded together only at the moment a detail page is opened. Designing it this way saves speed and cost across the entire system. It is much like how, in a library, instead of searching through every book title, you first find the location using a call number, and only pull the actually needed book off the shelf.

## Fast Archive Search

As seasons accumulate, a brand's design archive can grow to tens or hundreds of thousands of entries. Trying to find "last spring collection's pastel-tone knits" in this vast amount of data by looking at every product one by one is not feasible.

Building an **index** in advance from identifiers and tags narrows the search scope and allows the desired style to be found quickly. This works by first narrowing the broad range using season code, category code, and color code, and then filtering further within that range using detailed attributes. A well-designed identifier system is not just a management tool, but also a search infrastructure that turns an archive into an actually usable asset.

## Fashion Business Case: Inventory Mismatch Between Planning and Logistics

It is a common problem for the inventory quantity seen by a planning MD to differ from the actual inventory in a logistics warehouse. Tracing the cause often reveals that inventory was aggregated only at the product-name or upper-style level, without going down to the SKU level by color and size.

For example, if "basic round-neck knit" is registered as a single product in the planning system, but the logistics warehouse manages it as 12 SKUs split across 3 colors and 4 sizes, the two systems are referencing different units altogether. In this case, no matter how frequently the data is synchronized, the underlying mismatch will not be resolved. Unifying the identifier system across systems is the starting point for resolving data consistency problems.

## Real-World Case: Zara's Adoption of RFID Identifiers

Inditex (Zara's parent company) began experimenting with RFID tags starting in 2007, and rolled out an RFID-based inventory management system across all stores between 2014 and 2016. A notable feature is that they chose to embed the RFID chip inside the security tag already attached to each garment, allowing item-level identifiers to be read in real time without any additional attachment.

As a result, store staff could grasp store inventory in a matter of minutes using a wireless scanner, without counting garments one by one, and inventory accuracy improved significantly compared to before adoption. Industry sources report that after adopting this system, Zara achieved both a reduction in stockout rate and an increase in sales, leading to substantial annual cost savings. This is a case that shows how combining a logical identifier like a SKU with a physical identifier like RFID can structurally eliminate the cost of manual counting altogether.

## Chapter Summary

- A product name is an expression for people, while a SKU is a unique identifier for the system to reference accurately.
- How the hierarchy of style-colorway-SKU is designed determines the precision of inventory management.
- It is efficient to look up with a lightweight identifier first and load heavy detailed data only when needed.
- An index built from identifiers and tags makes a vast archive actually usable.
- Inventory mismatches between departments commonly occur when the identifier system is not unified.

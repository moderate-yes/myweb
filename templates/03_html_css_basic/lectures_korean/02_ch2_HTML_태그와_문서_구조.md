# Structuring an Analysis Document with HTML Tags

## 학습 목표

HTML 태그는 글자를 꾸미는 도구가 아니라 제목·문단·출처 같은 의미를 컴퓨터에게 알리는 표시다. 이 장은 분석 문서에 필요한 최소한의 구조를 올바른 태그로 표현하는 법을 다룬다.

이 장을 마치면 다음을 할 수 있다.

- 요소, 태그, 내용과 속성의 관계를 설명한다.
- 제목·문단·목록·링크에 맞는 태그를 선택한다.
- 부모·자식 관계와 올바른 중첩을 확인한다.
- class와 id의 용도를 구분한다.

## 1. 태그는 글자를 꾸미는 괄호가 아니라 의미 표식이다

```html
<p class="finding">반품률은 7.4%입니다.</p>
```

이 한 줄은 다음 네 부분으로 읽는다.

| 부분 | 예 | 역할 |
|---|---|---|
| 여는 태그 | `<p>` | 문단의 시작 |
| 속성 | `class="finding"` | 요소에 재사용 가능한 이름 부여 |
| 내용 | `반품률은 7.4%입니다.` | 사용자가 읽는 정보 |
| 닫는 태그 | `</p>` | 문단의 끝 |

`class`는 여러 요소에 같은 이름을 붙여 CSS로 함께 선택할 때 적합하다. `id`는 한 문서 안에서 고유한 위치나 요소를 가리킬 때 사용한다. 반복되는 분석 카드마다 같은 `id`를 복사하지 않는다.

## 2. 분석 문서에서 먼저 익힐 태그

| 목적 | 권장 태그 | 분석 문서 예 |
|---|---|---|
| 가장 큰 제목 | `<h1>` | 보고서 제목 |
| 하위 제목 | `<h2>`~`<h6>` | 데이터·방법·결과·한계 |
| 문단 | `<p>` | 결과 해석 |
| 순서 없는 목록 | `<ul>` + `<li>` | 주의점·가정 |
| 순서 있는 목록 | `<ol>` + `<li>` | 분석 절차 |
| 링크 | `<a>` | 원자료·방법론 출처 |
| 독립된 주제 영역 | `<section>` | 결과 한 묶음 |
| 독립적으로 재사용 가능한 내용 | `<article>` | 분석 카드·게시물 |

제목은 글자 크기를 만들기 위해 고르지 않는다. 문서의 계층에 맞춰 선택하고 모양은 CSS로 바꾼다. `h1` 다음에 단지 작게 보이게 하려고 `h4`로 뛰어넘으면 문서 구조를 파악하기 어려워진다.

## 3. 단순 예: 분석 결과와 출처 묶기

```html
<article class="analysis-card">
  <h2>신규 고객의 30일 재구매</h2>
  <p>8월 신규 고객의 30일 재구매율은 18.2%였습니다.</p>
  <h3>해석할 때 주의할 점</h3>
  <ul>
    <li>취소 주문은 제외했습니다.</li>
    <li>비회원 구매는 고객 단위로 연결하지 못했습니다.</li>
  </ul>
  <p>
    <a href="analysis-definition.html">지표 정의 확인</a>
  </p>
</article>
```

`<article>` 안에 제목과 관련 문단·목록·링크가 함께 들어 있다. 들여쓰기는 브라우저 결과를 직접 바꾸지 않을 수 있지만 부모와 자식 관계를 사람이 읽기 쉽게 만든다.

## 4. 속성은 요소에 필요한 추가 정보를 준다

링크에서 `href`는 목적지를 정한다.

```html
<a href="https://example.com/report">8월 분석 보고서</a>
```

`여기를 클릭`보다 `8월 분석 보고서`처럼 목적을 설명하는 링크 문구가 낫다. 새 창을 열기 위해 `target="_blank"`를 쓴다면 외부 페이지임을 사용자에게 알리고 프로젝트의 보안 기준도 확인한다.

분석용 메모를 CSS나 간단한 스크립트에서 구분해야 한다면 의미 있는 class를 붙인다.

```html
<p class="data-warning">비회원 주문은 고객 분석에서 제외했습니다.</p>
```

`red-text`, `left-box`처럼 현재 모양만 나타내는 이름보다 `data-warning`, `method-note`처럼 역할을 나타내는 이름이 나중에 디자인이 바뀌어도 이해하기 쉽다.

## 5. 문제 발생: 태그가 잘못 겹친다

다음 코드는 먼저 연 태그를 먼저 닫아 구조가 교차한다.

```html
<p><strong>주의: 비회원 주문 제외</p></strong>
```

안쪽에서 연 태그부터 닫아야 한다.

```html
<p><strong>주의: 비회원 주문 제외</strong></p>
```

브라우저가 일부 오류를 보정해 화면이 그럴듯하게 보여도 DOM이 예상과 달라지고 CSS 선택이 엉뚱한 요소에 적용될 수 있다. 들여쓰기를 맞추고 검사 도구에서 부모·자식 구조를 확인한다.

## 짧은 활동

다음 텍스트를 의미에 맞는 HTML로 표시한다.

- 보고서 제목: 8월 상품 성과
- 하위 제목: 핵심 발견
- 설명: 린넨 셔츠의 조회 대비 구매율이 가장 높았다.
- 주의점 두 개: 광고 유입 포함, 품절일 제외
- 링크: 지표 정의 보기

완성 뒤 모든 여는 태그에 대응하는 닫는 태그가 있는지 확인한다.

## 이 장의 핵심

- HTML 요소는 여는 태그, 속성, 내용과 닫는 태그로 구성된다.
- 태그는 보이는 모양보다 콘텐츠의 의미에 따라 선택한다.
- class는 여러 요소에 재사용하고 id는 문서 안의 고유한 대상을 가리킨다.
- 올바른 중첩과 제목 계층은 유지보수와 접근성을 함께 높인다.

## 학습 점검

1. 글자를 크게 만들기 위해 제목 태그를 고르면 안 되는 이유는 무엇인가?
2. `class="warning"`과 `id="warning"`은 어떤 상황에서 각각 적절한가?
3. 링크 문구를 `여기`보다 구체적으로 써야 하는 이유는 무엇인가?

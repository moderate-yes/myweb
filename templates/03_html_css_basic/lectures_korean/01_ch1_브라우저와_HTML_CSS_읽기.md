# Finding HTML and CSS in the Browser

## 학습 목표

분석 결과를 웹 페이지로 공유하려면 화면이 HTML 구조와 CSS 규칙으로 그려진다는 점을 알아야 한다. 이 장은 브라우저 개발자 도구로 실제 페이지에서 그 둘을 찾아보는 데서 출발한다.

이 장을 마치면 다음을 할 수 있다.

- HTML, CSS와 DOM의 역할을 구분한다.
- 브라우저 검사 도구에서 화면 요소와 적용된 스타일을 찾는다.
- 검사 도구의 임시 수정과 원본 파일 수정을 구분한다.

## 1. 하나의 화면에는 서로 다른 역할이 겹쳐 있다

다음 분석 요약에서 HTML은 무엇이 제목이고 문단인지 알려 주고, CSS는 그 요약 상자의 모양을 정한다.

```html
<section class="analysis-summary">
  <h2>8월 판매 요약</h2>
  <p>아우터 매출은 전월보다 12% 증가했습니다.</p>
</section>
```

```css
.analysis-summary {
  padding: 16px;
  border: 1px solid #c8c8c8;
  background: #f5f5f3;
}
```

`<h2>`를 `<p>`로 바꾸면 **구조와 의미**가 달라진다. `background`를 바꾸면 의미는 그대로이고 **표현**만 달라진다. 이 차이를 구분하면 AI에게도 “제목 구조는 유지하고 배경색만 바꿔 줘”처럼 정확히 요청할 수 있다.

## 2. 파일의 코드와 화면의 DOM은 완전히 같지 않을 수 있다

브라우저는 HTML을 읽어 DOM을 만들고 CSS 규칙을 계산해 화면을 그린다. 잘못 닫힌 태그는 브라우저가 보정할 수 있고, JavaScript가 실행되면 처음 파일에 없던 요소가 추가될 수도 있다. 따라서 다음 세 대상을 구분한다.

| 확인 대상 | 알 수 있는 것 | 주의점 |
|---|---|---|
| HTML 원본 파일 | 저장된 구조와 내용 | 실행 뒤 추가된 요소는 없을 수 있음 |
| Elements/Inspector 패널 | 현재 DOM과 선택된 요소 | 여기서 고친 내용은 새로고침하면 사라짐 |
| Styles/Computed 패널 | 적용된 CSS와 최종 계산값 | 여러 규칙 중 이긴 값이 표시됨 |

## 3. 검사 도구로 바꿀 위치 찾기

Chrome·Edge·Firefox에서 화면의 요소를 마우스 오른쪽 버튼으로 누르고 **검사**를 선택한다. 이후 다음 순서로 본다.

1. Elements 또는 Inspector에서 선택된 태그 이름과 `class`를 확인한다.
2. Styles에서 어떤 규칙이 색·간격·글꼴을 만들었는지 확인한다.
3. 속성 왼쪽 체크를 껐다 켜며 어느 규칙이 화면에 영향을 주는지 본다.
4. 파일 이름과 줄 번호를 확인한 뒤 원본 파일에서 같은 선택자를 찾는다.

검사 도구에서 다음 값을 임시로 바꿔 보는 것은 안전한 실험이다.

```css
.analysis-summary {
  padding: 24px;
}
```

새로고침하면 원래대로 돌아온다. 실제 수정은 해당 HTML 또는 CSS 파일에 저장해야 한다.

## 4. 문제 발생: 보이는 글자를 검색했는데 파일에 없다

가능한 이유는 여러 가지다.

- Markdown이나 템플릿에서 HTML이 생성되었다.
- JavaScript가 데이터를 읽어 요소를 만들었다.
- 번역 파일이나 외부 데이터에서 문자열을 가져왔다.
- 브라우저 확장 프로그램이 화면을 바꿨다.

이때 무작정 모든 파일을 수정하지 않는다. 검사 도구에서 요소의 class와 주변 구조를 확인하고, 프로젝트 전체에서 그 class 또는 고유한 문장을 검색한다. 생성된 파일을 직접 고치면 다음 빌드에서 사라질 수 있으므로 **원본(source)**이 무엇인지 먼저 확인한다.

## 짧은 활동

현재 강의 페이지에서 제목 하나를 검사한다.

1. 태그 이름과 class를 기록한다.
2. 글자색을 만든 CSS 속성을 찾는다.
3. 검사 도구에서만 색을 임시 변경한다.
4. 새로고침 뒤 원래대로 돌아오는지 확인한다.

## 이 장의 핵심

- HTML은 구조와 의미, CSS는 표현을 담당한다.
- 브라우저는 HTML로 DOM을 만들며 원본과 현재 DOM은 다를 수 있다.
- 검사 도구의 수정은 원인을 찾는 임시 실험이다.
- 실제 변경 전에는 원본 파일과 영향 범위를 확인한다.

## 학습 점검

1. 제목의 색만 바꿀 때 HTML 태그를 바꾸는 것이 적절하지 않은 이유는 무엇인가?
2. 검사 도구에서 바꾼 값이 새로고침 뒤 사라지는 이유는 무엇인가?
3. 화면에는 있지만 HTML 파일에서 찾을 수 없는 요소가 생기는 이유를 두 가지 쓰시오.

## 핵심 용어

- **HTML**: 제목·문단·표·그림처럼 콘텐츠의 구조와 의미를 표시하는 마크업 언어.

- **DOM**: 브라우저가 HTML을 읽어 메모리에 만든 문서 구조.
- **개발자 도구**: 현재 화면의 요소, 스타일과 오류를 조사하는 브라우저 도구.

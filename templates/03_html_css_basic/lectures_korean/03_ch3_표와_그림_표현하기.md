# Presenting Results with Tables, Figures, and Links

## 학습 목표

표와 그래프는 분석 결과의 핵심이지만 그냥 붙여 넣으면 무엇을 보여 주는지 전달되지 않는다. 이 장은 제목·설명·출처가 붙은 표와 그림을 HTML로 표현하는 법을 다룬다.

이 장을 마치면 다음을 할 수 있다.

- 데이터 표에 `caption`, 열 머리글과 본문 구조를 적용한다.
- 그래프를 `figure`, `img`, `figcaption`으로 묶는다.
- 이미지 대체 텍스트와 캡션의 역할을 구분한다.
- 긴 보충 설명을 `details`와 `summary`로 정리한다.

## 1. 데이터 표에는 제목과 머리글이 필요하다

```html
<table class="result-table">
  <caption>2026년 8월 카테고리별 순매출</caption>
  <thead>
    <tr>
      <th scope="col">카테고리</th>
      <th scope="col">주문 수</th>
      <th scope="col">순매출</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <th scope="row">아우터</th>
      <td>428</td>
      <td>58,420,000원</td>
    </tr>
    <tr>
      <th scope="row">상의</th>
      <td>615</td>
      <td>41,870,000원</td>
    </tr>
  </tbody>
</table>
```

`<caption>`은 표가 무엇인지 설명한다. `<thead>`와 `<tbody>`는 머리글과 데이터 영역을 구분한다. `<th scope="col">`은 열 머리글, `<th scope="row">`은 행 머리글임을 알려 준다. 병합 셀이 많은 복잡한 표보다 분석 단위가 분명한 단순한 표가 읽고 재사용하기 쉽다.

표는 **행과 열 사이의 관계가 중요한 데이터**에 사용한다. 단순히 두 요소를 좌우로 배치하려고 table을 쓰지 않는다. 배치는 CSS의 역할이다.

## 2. 그래프는 이미지와 설명을 한 묶음으로 만든다

```html
<figure class="analysis-figure">
  <img
    src="images/category_sales.png"
    alt="아우터 5,842만 원, 상의 4,187만 원으로 아우터가 더 높은 막대그래프"
  >
  <figcaption>
    그림 1. 2026년 8월 카테고리별 순매출. 취소와 전액 반품 주문은 제외했다.
  </figcaption>
</figure>
```

`alt`는 이미지를 보지 못할 때 필요한 핵심 정보를 전달한다. `figcaption`은 그림 번호, 기간, 단위, 제외 조건과 출처처럼 본문에서 그림을 해석하는 데 필요한 맥락을 제공한다. 둘은 완전히 같은 문장을 반복하기보다 역할을 나눈다.

장식용 이미지는 의미를 추가하지 않으므로 빈 대체 텍스트 `alt=""`를 사용할 수 있다. 반면 그래프의 `alt`를 `매출 그래프`라고만 쓰면 핵심 비교 결과를 알 수 없다.

## 3. 링크는 출처와 분석 근거를 연결한다

```html
<p class="source-note">
  출처:
  <a href="https://example.com/data-definition">
    주문 데이터 정의서 — 순매출 산식
  </a>
</p>
```

출처 링크에는 기관·문서명·확인 대상이 드러나게 쓴다. 주소 전체를 본문에 그대로 노출하거나 `클릭`이라고만 쓰지 않는다. 외부 자료의 표나 그림을 사용할 때는 링크만 붙이는 것으로 충분한지 라이선스와 이용 조건도 확인한다.

## 4. 보충 설명은 필요할 때 펼치게 할 수 있다

```html
<details>
  <summary>순매출 계산 기준 보기</summary>
  <p>결제금액에서 취소액과 확정 반품액을 차감했습니다.</p>
</details>
```

`details`와 `summary`는 긴 산식, 제외 기준이나 정답 해설처럼 본문 흐름을 끊지 않으면서 필요할 때 확인할 내용을 담는 데 유용하다. 그러나 핵심 결론과 반드시 알아야 할 위험을 접힌 영역에만 숨기지 않는다.

## 5. 문제 발생: 표와 그래프의 숫자가 다르다

HTML이 올바르더라도 내용이 올바르다는 뜻은 아니다. 표에는 순매출, 그래프에는 결제액이 들어갔거나 생성 시점이 다르면 숫자가 어긋날 수 있다. 다음 항목을 함께 기록한다.

- 분석 기간과 시간대
- 집계 단위와 통화
- 취소·반품·결측치 제외 규칙
- 그래프를 만든 원본 파일 또는 코드
- 데이터 갱신 시점

표와 그래프를 수정한 뒤에는 보이는 숫자뿐 아니라 원자료와 정의가 같은지 확인한다.

## 짧은 활동

Python에서 만든 `segment_sales.png`와 고객군별 주문 수 세 행을 웹 문서에 넣는다고 가정한다.

1. 표에 `caption`, `thead`, `tbody`와 열 머리글을 추가한다.
2. 이미지를 `figure`로 묶고 결과를 요약하는 `alt`를 쓴다.
3. 기간·제외 조건·출처를 `figcaption` 또는 인접 문단에 기록한다.
4. 모바일에서 표가 잘릴 경우 숫자를 삭제하지 말고 4장에서 다룰 가로 스크롤 영역을 계획한다.

## 이 장의 핵심

- 데이터 표는 caption, 머리글과 본문을 구조적으로 구분한다.
- 그래프는 figure 안에 이미지와 캡션을 함께 둔다.
- alt는 대체 정보, figcaption은 해석 맥락을 제공한다.
- 표와 그래프의 정확성은 HTML이 아니라 데이터 정의와 갱신 시점까지 검증해야 확보된다.

## 학습 점검

1. 표의 첫 행을 모두 `td`로 만들면 어떤 정보가 사라지는가?
2. 그래프의 alt와 figcaption은 어떻게 다른가?
3. `details` 안에 넣지 말아야 할 정보는 무엇인가?

<details><summary>정답과 해설 보기</summary>

1. 어떤 셀이 각 열의 머리글인지 기계적으로 구분할 정보가 사라진다.
2. alt는 이미지를 볼 수 없을 때 핵심 시각 정보를 대신하고, figcaption은 기간·단위·출처·해석 같은 문서 맥락을 설명한다.
3. 반드시 알아야 할 핵심 결론과 안전·오류 경고를 접힌 영역에만 두면 안 된다.

# Chapter 2: Data Jobs and the Analysis Workflow in Fashion

The fashion industry draws unusually strong interest from the big-data and AI field, more than most other industries. Simply running an online store generates data on its own, and even a single product accumulates text (name, description), several kinds of images (flat-lay shots, model shots, customer photos on social media), and numeric data (sales volume, click-through rate) all at once. This chapter looks at what a data role actually does with this material, and at the real workflow that runs from data collection to a finished service.

## Key Terms

- **Pivot**: Reshaping data listed in rows into a row-and-column table organized by a criterion such as date or product.
- **Join**: Combining two different datasets (for example, sales data and temperature data) into one table using a shared key.
- **Spiral model**: A way of working in which the process from data collection to service is never finished in one pass — details are added and earlier stages are revisited repeatedly.

## Why the Fashion Industry Is Close to Data

Four traits explain why the fashion industry draws so much attention from the big-data and AI field.

| Trait | Description |
|---|---|
| Natural data generation | Simply running the business — operating a store, shooting a lookbook — generates data as a byproduct |
| Multiple image forms | The same product exists as a flat-lay shot, a model shot, and ordinary customers' social-media photos |
| Diverse data types | Text (product name, description) accumulates alongside numeric data (sales, click-through rate) |
| Low access barriers | Unlike factory data, which only specific people can see, anyone can observe data simply by browsing an online store |

Because these four traits overlap, an online store becomes a massive data hub in its own right. A single representative image of a product comes bundled with text and numeric data, and that data is relatively easy for anyone to access.

## What a Data Role Actually Is

In one sentence, a data role means **identifying patterns in data**. The patterns found are then used to deliver market insight as a report, or to build a service that automatically responds to similar situations going forward.

For example, suppose analysis of Store A's sales data reveals that "male office workers in their 30s living in Gangnam most often buy navy oversized coats priced between 200,000 and 250,000 won." This pattern can be used in two ways. One is passing it to the merchandising team as a report that informs an ad concept. The other is connecting it to the store's system so that every new customer who fits the profile automatically receives an email recommending a navy oversized coat at 9 a.m. each morning. The first turns the pattern into a report; the second turns it into a service.

## The Workflow: From Collection to Service

The real work of finding a pattern generally passes through five stages.

**1) Data collection.** The first step is understanding how the client's and your own data infrastructure is set up. If a store runs on a platform like Cafe24, data can be pulled through an API; if security concerns block API access, files are sometimes delivered by email or USB. Data you cannot get through the client's cooperation — a competitor's new arrivals, or weather data — is gathered by building a crawler, and data that doesn't exist yet — reactions to a new campaign — is generated fresh through methods like A/B testing.

**2) Building data for analysis.** Raw collected data is rarely usable for analysis as-is. Consider sales records accumulated over time like this:

| Timestamp | Product | Quantity |
|---|---|---|
| 2022-01-02 19:35 | A | 1 |
| 2022-01-02 14:20 | B | 2 |
| 2022-01-01 14:55 | A | 1 |

To compare daily sales volume by product, this needs to become a **pivot** table with dates as columns and product names as the index.

| | 12/31 | 01/01 | 01/02 | Total |
|---|---|---|---|---|
| A | 3 | 1 | 3 | 7 |
| B | 2 | 2 | 2 | 6 |

If you also want to see sales alongside that day's temperature, you **join** the sales data and the temperature data on the date key into a single table. Pivot and join are the two preprocessing techniques used most often in practice, so if they're unfamiliar, they are worth learning separately and deliberately.

**3) Analysis and evaluation.** An appropriate analysis model is chosen, developed, and applied for the target goal, then evaluated. If the evaluation is unsatisfactory, the process often goes back to the data-building stage.

**4) Service.** Depending on the case, the results may be submitted as a report based on the pattern found, exposed as an API so a client's system can respond automatically to similar situations, written directly into a client's database, or delivered as the raw data-collection code itself.

## The Spiral Model: Why It Never Finishes in One Pass

Collection → building → analysis → evaluation → service looks like a process that completes in a single pass, but real work spirals through these stages repeatedly. As details are added to each stage one at a time, going back to start over is the norm rather than the exception. The repetition itself can feel inefficient, but **the ability to take on repeated work without resentment is what separates a strong analyst from a weak one.**

## Case Study: A Career Switch Into Data Science

Career changes into data roles without a computer science background are far from rare in the fashion retail industry. One fashion major went from a liberal-arts high school and a clothing and textiles degree into a brand sales job, then encountered data analysis in a graduate fashion retail and service lab and self-taught programming to switch into a data scientist role. It reportedly took about 19 months from starting to code to landing the job — with the first stretch limited to two or three days a week of study while writing a thesis, followed by six months of full-time study at a coding bootcamp.

This case makes two points worth remembering. First, Python is recommended because it is a general-purpose language that carries a project all the way from collection to cleaning to analysis to building the service, in one language. Second, analytical knowledge acquired before ever touching code — familiarity with group-by and pivot-table concepts, or experience running regressions in SPSS — has a large effect on how fast the learning goes. For those unwilling to learn to program at all, alternatives exist — web scrapers, RapidMiner, TEXTOM, Google Analytics — but the conclusion of this account is that learning all of them separately takes about as long as learning Python alone.

## Chapter Summary

- The fashion industry draws big-data and AI interest thanks to four traits: natural data generation, multiple image forms, diverse data types, and low access barriers.
- A data role, in short, means identifying patterns in data and turning them into a report or an automated service.
- The real workflow runs: data collection → building data for analysis (pivot, join) → analysis and evaluation → service.
- This process is never finished in one pass — it spirals, and the willingness to accept that repetition is what defines analyst skill.
- Someone without a technical background can still enter a data role through focused self-study and sufficient time investment.

# Chapter 3: The Shape of Data — Attributes and Representation

Before learning analysis techniques, an analyst needs to understand **what shape data actually takes inside a computer**. A person can tell apart the name "One" and the quantity "1" purely from context, but a computer cannot compute anything about that difference unless it is told explicitly. This chapter looks at the basic structure of numeric data, six attribute types, and how text and image data ultimately get turned into numbers.

> **Something to think about**
> A customer name that happens to be "One" and a purchase quantity of "1" could both appear on screen as the digit "1." What goes wrong if a computer can't tell these two apart?

## Learning Objectives

By the end of this unit, you will be able to:

- Describe numeric data using the structure of index, column, value, and attribute.
- Distinguish nominal, binary, ordinal, numeric, date, and time-series attributes with examples.
- Explain how many dimensions of numbers represent text data and image data, respectively.
- Explain how these representation choices connect to services like sentiment analysis, recommendation, and object recognition.

## Key Terms

- **Attribute**: The hidden character behind a value that determines what operations and comparisons make sense on it.
- **Nominal attribute**: An attribute representing a label or name for something, where order and arithmetic are meaningless.
- **Ordinal attribute**: An attribute with a meaningful rank, but no way to measure the distance between values.
- **Time-series attribute**: An attribute where the passage of time is assumed to affect how values are arranged.

## The Structure of Numeric Data: Index, Column, Value, Attribute

Numeric data consists of an index and columns, and each column is really a combination of value and attribute. For example, if customer "One" is a 22-year-old male who bought one item on the 22nd, that becomes a single row (index 1) like this:

| Index | name | age | gender | date | amount |
|---|---|---|---|---|---|
| 1 | One | 22 | M | 22 | 1 |
| 2 | Minsu | 19 | F | 21 | 2 |

Here, name, age, gender, date, and amount are columns, and whatever fills each cell is the value. The problem is that the table alone doesn't reveal the **attribute**. A person can tell from context that "One" in the name column is a label that can't be added or subtracted, while "1" in the amount column is a quantity that can be. A computer needs this told to it explicitly. Since data analysis ultimately runs through a computer, an analyst has to understand attributes and be able to communicate them to the machine.

## Six Attributes of Data

| Attribute | Definition | Characteristics |
|---|---|---|
| Nominal | A label or name for something | No meaningful order, no arithmetic. Encoding it as numbers and adding them produces nonsense. Can be used to compute a mode |
| Binary | Two categories, often expressed as True/False | Commonly used to represent whether a condition is met. In reality, though, cases that split cleanly into exactly two categories are rarer than they seem |
| Ordinal | A meaningful rank as its value | You can't measure the "distance" between VVIP and VIP, but you can compare their rank. Also used to bucket a continuous value into a finite number of ranked categories |
| Numeric | A measurable quantity expressed as an integer or real number | You can compare the difference between values, and there is a zero point to reference |
| Date | Year, month, day, time, day of week as its value | Arithmetic works differently from numeric attributes (Jan 31 + 1 day = Feb 1). Watch out for time-zone differences |
| Time-series | A sequentially ordered set of values | Assumes the passage of time affects how values are arranged. Text also has a sequential character and can be a target of time-series analysis |

These six attributes form the minimum vocabulary needed to use data tools efficiently. A customer tier (VVIP/VIP/NORMAL), for instance, is an ordinal attribute, so averaging it is meaningless — but counting how many customers fall in each tier (something closer to a mode) is meaningful.

## How Text Data Becomes Numbers

Text data made of sentences — a product description, for example — is generally handled as a three-dimensional structure of **sentence × word × document**. First, every word that appears is collected into a dictionary, and each word is assigned a number. Each sentence is then turned into a numeric array recording how many times each dictionary word appears in it.

```
Sentence 1: A slim fit that narrows naturally from thigh to ankle...
   →  [11, 22, 33, ……… 0, 0]
Sentence 2: The hem can be cut according to preference...
   →  [34, 23, 50, ……… 0, 0]
```

Once text is turned into numbers this way, it can drive sentiment analysis on product comments, chatbots for fashion retailers, product classification through named-entity recognition, and topic modeling for tracking fashion issues.

## How Image Data Becomes Numbers

Image data is generally represented as a four-dimensional structure of **height × width × color channel × image count**. An analyst splits a single photo into three channels — R, G, B — and expresses the brightness of each channel as a number between 0 and 1. A dark area gets a low number; an area close to pure red gets a high number in the red channel. Representations other than RGB, such as HSV, which emphasizes brightness and saturation, are also used.

Once turned into numbers, image data drives product recommendation (finding visually similar products) and object recognition used to spot trends across product images. The next chapter but two (image-similarity recommendation) goes deeper into this principle.

## Two Things Easy to Miss About Data

First, **what isn't recorded can't become data.** No matter how vividly you can imagine a customer near Samsung-dong opening a laptop to shop for a field jacket, that scene cannot be analyzed unless a click log actually captured it. Second, **recording data requires setting priorities.** Not every action can be logged, so deciding what to record first, based on the analysis goal, is also part of an analyst's job.

## Chapter Summary

- Numeric data appears as index, column, and value, but a hidden attribute always sits behind it.
- Data attributes fall into six kinds — nominal, binary, ordinal, numeric, date, time-series — each allowing different operations and comparisons.
- Text data is numericized as a three-dimensional sentence × word × document structure; image data as a four-dimensional height × width × color-channel × image-count structure.
- No matter how vivid an event feels, it cannot be analyzed unless it was captured as data — which is why deciding what to record is itself part of an analyst's job.

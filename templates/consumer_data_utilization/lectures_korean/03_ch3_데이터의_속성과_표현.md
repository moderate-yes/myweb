# 데이터의 의미와 모양: 값·속성·dtype·Shape 이해하기

화면에 보이는 `1`은 구매 수량일 수도 있고 고객 등급 코드일 수도 있다. 두 값이 컴퓨터 안에서 같은 정수형으로 저장되어도 더하거나 평균을 내도 되는지는 전혀 다르다. 데이터를 제대로 다루려면 **값의 업무상 의미**, **계산을 허용하는 척도**, **컴퓨터의 저장 타입**, **배열의 모양**을 구분해야 한다.

> **이 장의 중심 질문**<br>
> 컴퓨터는 값 `1`이 수량인지 등급인지 어떻게 알며, 분석가는 어떤 계산이 정당한지 어떻게 판단할까?

## 생각해 보기: 같은 `1`은 같은 데이터일까?

| 화면의 값 | 실제 의미 | 적절한 저장 예 | 가능한 질문 |
|---|---|---|---|
| 일 | 고객 이름 | 문자열 | 같은 이름이 몇 명인가? |
| 1 | 구매 수량 | 정수 | 총 몇 개를 샀는가? |
| 1 | 고객 등급 코드 | 순서가 지정된 범주형 | 어느 등급이 더 높은가? |
| 2026-08-01 | 구매일 | 날짜·시간 | 구매 후 며칠이 지났는가? |

값의 모양만 보고 의미를 추측하면 잘못된 계산으로 이어진다. 고객 등급을 `1, 2, 3`으로 저장했다고 해서 등급 3이 등급 1의 세 배라는 뜻은 아니다.

## 학습 목표

이 장을 마치면 다음을 할 수 있다.

- 패션 데이터 직무에서 의미·척도·dtype·shape를 확인해야 하는 이유를 설명할 수 있다.
- C와 Python이 변수와 값의 타입을 다루는 방식의 차이를 설명할 수 있다.
- 값·속성·인덱스·컬럼을 구분할 수 있다.
- 명목·순서·간격·비율 척도의 정의와 가능한 계산을 설명할 수 있다.
- 표를 NumPy 배열로 바꾸고 출력값·dtype·shape를 해석할 수 있다.
- 같은 값의 의미·척도·dtype·shape가 분석에서 각각 어떻게 쓰이는지 설명할 수 있다.

## 핵심 용어

- **값(value)**: 한 관측 항목에 실제로 기록된 내용.
- **의미(meaning)**: 값이 현실에서 무엇을 나타내는지에 대한 업무 정의.
- **속성(attribute)**: 고객 나이, 상품 색상, 주문 수량처럼 관측 대상을 설명하는 항목.
- **측정 척도(measurement scale)**: 명목·순서·간격·비율처럼 값의 비교와 계산 범위를 정하는 기준.
- **데이터 타입(dtype)**: 정수, 실수, 문자열, 불리언, 날짜처럼 컴퓨터가 값을 저장하고 처리하는 형식.
- **모양(shape)**: 배열의 축별 원소 수. `(100, 8)`이라면 100행 8열이다.
- **축(axis)**: 배열을 세는 방향. 표에서는 행과 열이 대표적인 두 축이다.

## 1. 패션 데이터 직무자는 왜 이 내용을 배워야 하는가

패션 기업의 상품기획자, MD, 마케터, 데이터 분석가와 AI 담당자는 같은 데이터를 보더라도 서로 다른 결정을 내린다. 이때 컬럼 이름과 숫자의 의미를 잘못 이해하면 계산 자체는 맞아도 결정은 틀릴 수 있다.

| 직무 상황 | 확인해야 할 것 | 확인하지 않았을 때의 위험 |
|---|---|---|
| MD가 사이즈별 판매량을 집계 | `1`이 주문 수인지 상품 수인지 | 세트 상품과 수량을 혼동해 발주량 오류 |
| 마케터가 고객 등급별 전환율 비교 | 등급의 순서와 전환율의 분모 | 숫자 코드 평균을 고객 가치로 오해 |
| 데이터 분석가가 주문·반품 표를 결합 | Key dtype과 행 수·shape | `001`과 `1`이 다르게 처리되거나 행이 복제됨 |
| 상품 담당자가 가격 데이터를 정리 | 정가·판매가·쿠폰가의 의미와 dtype | 서로 다른 가격을 같은 컬럼에서 평균 냄 |
| AI 담당자가 이미지·텍스트를 모델에 입력 | 축의 순서와 입력 shape | 모델 오류 또는 잘못된 예측 |

이 장은 단순한 프로그래밍 문법이 아니다. **업무에서 정의한 의미가 데이터 저장과 계산 과정에서 유지되는지 확인하는 법**을 다룬다. 특히 생성형 AI가 작성한 SQL이나 Python 코드도 컬럼의 의미와 분모를 자동으로 보장하지 않으므로, 직무 담당자가 결과를 검토할 수 있어야 한다.

## 2. 컴퓨터에게 값의 타입을 알려주는 방식

컴퓨터 메모리에 기록된 비트만 보면 그것이 정수인지 문자 코드인지 알기 어렵다. 프로그래밍 언어와 실행 환경은 각 값을 어떤 규칙으로 해석하고 어떤 연산을 허용할지 타입으로 관리한다.

### C: 변수를 선언할 때 타입을 명시한다

C에서는 변수를 만들 때 보통 타입을 함께 선언한다.

```c
int quantity = 1;
float discount_rate = 0.1f;
char size_code = 'L';
```

- `int quantity`는 `quantity`를 정수 변수로 사용하겠다는 선언이다.
- 정수 리터럴 `1` 자체도 C 언어 규칙상 기본적으로 `int` 타입을 가진다.
- `0.1f`의 `f`는 `float`, `1L`의 `L`은 `long` 리터럴임을 나타낸다.
- 선언한 타입에 따라 메모리 사용 방식, 표현 범위와 가능한 연산이 정해진다.

따라서 “C에서는 `1`을 쓸 때마다 사람이 타입 이름을 붙인다”기보다는, **변수 선언에서 타입을 명시하고 숫자 리터럴의 타입은 언어 규칙과 접미사로 정한다**고 이해하는 것이 정확하다.

### Python: 값에는 타입이 있지만 변수 이름에는 보통 고정 타입을 선언하지 않는다

```python
quantity = 1
discount_rate = 0.1
size_code = "L"

print(type(quantity))
print(type(discount_rate))
print(type(size_code))
```

```output
<class 'int'>
<class 'float'>
<class 'str'>
```

Python도 모든 값에 타입이 있다. 다만 `quantity`라는 이름 앞에 `int`를 선언하지 않아도 실행 시점에 값 `1`을 보고 정수 객체로 처리한다. 같은 이름이 나중에 다른 타입의 값을 가리킬 수도 있다.

```python
quantity = 1
quantity = "한 개"
```

이런 방식을 흔히 **동적 타이핑(dynamic typing)**이라고 한다. 편리하지만 잘못된 타입이 실행 중간에 발견될 수 있으므로 데이터 분석에서는 `type()`, pandas의 `dtypes`, NumPy의 `dtype`으로 실제 타입을 확인한다.

### Python에서도 타입을 명시하는 경우

```python
quantity: int = 1
```

위의 `: int`는 **타입 힌트**다. 코드 편집기와 검사 도구가 오류를 찾는 데 도움을 주지만, 기본 Python 실행기가 이 선언만으로 다른 타입의 대입을 항상 막는 것은 아니다.

NumPy처럼 메모리 크기와 계산 정밀도가 중요한 라이브러리에서는 dtype을 명시하기도 한다.

```python
import numpy as np

quantity_array = np.array([1, 2, 3], dtype=np.int32)
price_array = np.array([39800, 59000], dtype=np.float64)
```

Python에서 타입을 특별히 지정하는 대표 상황은 다음과 같다.

- 파일에서 읽은 문자열을 날짜나 숫자로 변환할 때
- NumPy 배열의 메모리 크기와 정밀도를 통제할 때
- 함수의 입력·출력 계약을 타입 힌트로 설명할 때
- 상품 ID의 앞자리 `0`을 보존하기 위해 문자열로 읽을 때
- 모델이나 API가 요구하는 정확한 dtype에 맞출 때

## 3. 표에서 값은 어디에 놓이는가

고객 ‘일’이 22세이고 22일에 상품 1개를 구매했다면 다음과 같은 행을 만들 수 있다.

| 인덱스 | name | age | gender | date | amount |
|---:|---|---:|---|---|---:|
| 1 | 일 | 22 | M | 2026-08-22 | 1 |
| 2 | 민수 | 19 | F | 2026-08-21 | 2 |

- **인덱스**는 행의 위치나 식별 정보를 나타낸다.
- **컬럼**은 `name`, `age`, `gender`, `date`, `amount`처럼 같은 의미의 값을 모은다.
- **값**은 각 칸에 들어 있는 실제 내용이다.
- **속성**은 각 컬럼이 관측 대상을 어떤 관점에서 설명하는지 나타낸다.
- **dtype**은 컴퓨터가 그 값을 어떤 형식으로 저장하는지 나타낸다.

### pandas 표를 NumPy 배열로 바꾸기

```python
import pandas as pd

df = pd.DataFrame(
    {
        "name": ["일", "민수"],
        "age": [22, 19],
        "gender": ["M", "F"],
        "date": ["2026-08-22", "2026-08-21"],
        "amount": [1, 2],
    },
    index=[1, 2],
)

all_values = df.to_numpy()
print(all_values)
print(all_values.shape)
print(all_values.dtype)
```

출력 예시는 다음과 같다.

```output
[['일' 22 'M' '2026-08-22' 1]
 ['민수' 19 'F' '2026-08-21' 2]]
(2, 5)
object
```

- `(2, 5)`는 **2행 5열**이라는 뜻이다.
- pandas의 인덱스 `1, 2`는 `to_numpy()` 결과에 기본적으로 포함되지 않는다.
- 문자열과 숫자가 섞여 있어 하나의 NumPy 배열에서는 공통 `object` dtype으로 표현된다.
- shape가 같아도 각 열의 의미가 같아지는 것은 아니다.

수치 계산이 목적이라면 필요한 숫자 컬럼만 선택하는 편이 안전하다.

```python
numeric_values = df[["age", "amount"]].to_numpy(dtype="int64")

print(numeric_values)
print(numeric_values.shape)
print(numeric_values.dtype)
```

```output
[[22  1]
 [19  2]]
(2, 2)
int64
```

이 배열은 2명의 고객과 2개의 수치 컬럼을 가진다. 그러나 첫 번째 열은 나이, 두 번째 열은 구매 수량이므로 같은 정수형이어도 계산 목적과 단위는 다르다.

## 4. 측정 척도란 무엇인가

측정 척도는 값을 얼마나 강하게 비교하고 계산할 수 있는지를 정하는 기준이다. 명목 → 순서 → 간격 → 비율로 갈수록 허용되는 비교와 계산이 늘어난다.

### 4.1 명목 척도: 이름으로 구분한다

브랜드, 상품 ID, 유입 채널처럼 대상을 구별하는 값이다. 같음과 다름은 판단할 수 있지만 크고 작음은 없다.

```python
brands = ["Brand A", "Brand B", "Brand A"]
brand_a_count = brands.count("Brand A")
print(brand_a_count)
```

```output
2
```

가능한 계산은 빈도, 구성비, 최빈값 등이다. 브랜드 코드가 `1`, `2`여도 평균을 내서는 안 된다.

### 4.2 순서 척도: 순위는 있지만 간격은 알 수 없다

`NORMAL < VIP < VVIP`처럼 순서는 있지만 단계 사이 차이가 같다고 보장할 수 없는 값이다.

```python
level_order = {"NORMAL": 1, "VIP": 2, "VVIP": 3}
is_higher = level_order["VVIP"] > level_order["VIP"]
print(is_higher)
```

```output
True
```

순서 비교, 중앙값, 분위수와 단계별 빈도를 사용할 수 있다. 등급 번호의 평균은 조직이 간격을 정의하지 않았다면 신중해야 한다.

### 4.3 간격 척도: 차이는 계산하지만 비율은 해석하기 어렵다

값 사이 간격이 일정하지만 의미 있는 절대적 0이 없는 척도다. 섭씨 온도가 대표적이다.

```python
temperature_gap = 20 - 10
print(temperature_gap)
```

```output
10
```

차이, 평균과 표준편차를 계산할 수 있다. 그러나 섭씨 20도가 10도보다 두 배 따뜻하다고 말할 수는 없다.

### 4.4 비율 척도: 차이와 비율을 모두 계산한다

구매 수량, 결제 금액과 무게처럼 `0`이 해당 양이 없음을 뜻하는 값이다.

```python
quantity_ratio = 4 / 2
total_quantity = 4 + 2

print(quantity_ratio)
print(total_quantity)
```

```output
2.0
6
```

합계, 차이, 평균, 비율과 배수 비교가 가능하다. 단, 환불을 포함한 금액처럼 0과 음수의 의미가 달라지는 경우에는 업무 정의를 먼저 확인한다.

### 척도별 가능한 계산

| 척도 | 같음·다름 | 순서 | 차이 | 비율 | 자주 쓰는 요약 |
|---|:---:|:---:|:---:|:---:|---|
| 명목 | 가능 | 불가 | 불가 | 불가 | 빈도, 구성비, 최빈값 |
| 순서 | 가능 | 가능 | 간격 가정 없이는 곤란 | 불가 | 중앙값, 분위수, 단계별 빈도 |
| 간격 | 가능 | 가능 | 가능 | 기준점 때문에 곤란 | 평균, 표준편차, 차이 |
| 비율 | 가능 | 가능 | 가능 | 가능 | 합계, 평균, 비율, 증감률 |

계산 순서는 다음과 같다.

1. 값이 현실에서 무엇을 뜻하는지 확인한다.
2. 명목·순서·간격·비율 중 어떤 척도인지 판단한다.
3. 그 척도에서 허용되는 비교와 요약을 고른다.
4. dtype을 확인하고 필요한 경우 변환한다.
5. 표본 수, 결측과 계산 단위를 함께 기록한다.

## 5. 의미·척도·dtype·shape는 서로 다른 질문이다

### 네 개념을 Python 예시와 함께 정의하기

```python
import numpy as np

amount = 1
amount_column = np.array([1, 2], dtype=np.int64)

print(type(amount))
print(np.asarray(amount).shape)
print(amount_column.dtype)
print(amount_column.shape)
```

```output
<class 'int'>
()
int64
(2,)
```

| 구분 | 정의 | `amount = 1` 예 | 분석 역할 |
|---|---|---|---|
| 의미 | 현실에서 무엇을 나타내는가? | 한 주문 행의 상품 수량 한 개 | 컬럼 정의와 단위를 결정 |
| 척도 | 어떤 비교와 계산이 정당한가? | 의미 있는 0이 있는 비율 척도 | 합계·평균·비율 사용 가능 여부 결정 |
| dtype | 컴퓨터가 어떤 형식으로 저장하는가? | Python `int`, 배열에서는 정수 dtype | 저장 범위·정밀도·연산 방식 결정 |
| shape | 값이 몇 축에 어떤 길이로 배열되는가? | 단일 값은 `()`, 두 행의 컬럼은 `(2,)` | 모델·함수 입력 구조와 축 연산 결정 |

</div>

같은 숫자 `1`도 고객 등급 코드라면 답이 달라진다.

| 관점 | 구매 수량 `1` | 고객 등급 코드 `1` |
|---|---|---|
| 의미 | 상품 한 개 | NORMAL 등급을 가리키는 코드 |
| 척도 | 비율 | 순서 또는 명목 |
| dtype | 둘 다 정수일 수 있음 | 둘 다 정수일 수 있음 |
| 가능한 계산 | 합계·평균·배수 | 빈도·순서 비교 중심 |

dtype과 shape만 같다고 의미와 척도까지 같은 것은 아니다. 분석 코드는 실행되더라도 의미에 맞지 않는 계산을 할 수 있으므로, 데이터 사전과 업무 담당자의 정의가 필요하다.

## 6. 자주 생기는 오류와 점검 방법

| 오류 | 예 | 점검 방법 |
|---|---|---|
| 숫자처럼 보이는 ID 계산 | 상품 ID 평균 | 값의 단위와 척도 확인 |
| 문자열 숫자 합산 | `"10" + "20"`이 `"1020"` | dtype과 변환 실패 행 확인 |
| 날짜를 문자열로 정렬 | 10월과 2월 순서 오류 | 날짜 dtype과 시간대 확인 |
| shape만 보고 의미 추측 | `(100, 8)`을 모두 고객 표로 간주 | 축 이름과 컬럼 정의 기록 |
| 정수 범위·결측 무시 | 결측 때문에 정수가 실수로 변환 | pandas `dtypes`, 결측값 수 확인 |

생성형 AI가 만든 코드에는 최소한 다음 확인을 추가한다.

```python
print(df.shape)
print(df.dtypes)
print(df.isna().sum())
print(df.head())
```

출력이 예상과 다르면 분석을 진행하기 전에 원본 데이터, 컬럼 정의와 변환 규칙부터 확인한다.

## 짧은 활동: 한 컬럼을 네 관점으로 진단하기

다음 다섯 컬럼을 각각 진단한다.

1. 고객 등급: `VIP`, `VVIP`, `NORMAL`
2. 구매 금액: `39,800`
3. 성별 항목: `M`, `F`, `미응답`
4. 구매 일시: `2026-08-02 19:35+09:00`
5. 회원 동의 여부: `True`, `False`

각 컬럼에 대해 **업무 의미, 척도, 적절한 dtype, 데이터 전체에서 예상하는 shape와 축의 의미**를 문장으로 적는다. 마지막에는 “컴퓨터가 계산할 수 있는가?”와 “그 계산이 업무적으로 의미 있는가?”를 따로 답한다.

## 이 장의 핵심

- 패션 데이터 직무자는 계산 결과뿐 아니라 값의 업무 의미와 단위를 검토해야 한다.
- C는 변수 선언에서 타입을 명시하고, Python은 값의 타입을 실행 시점에 관리한다.
- Python도 모든 값에 타입이 있으며 필요하면 타입 힌트나 NumPy dtype을 명시한다.
- 명목·순서·간격·비율 척도에 따라 정당한 비교와 계산의 범위가 달라진다.
- 의미·척도·dtype·shape는 각각 업무 정의, 허용 계산, 저장 방식, 배열 구조에 답한다.
- pandas 표를 NumPy 배열로 바꾸면 혼합 컬럼은 `object` dtype이 될 수 있으므로 계산할 숫자 컬럼을 명확히 선택한다.
- 같은 `1`과 같은 shape라도 컬럼 정의가 다르면 사용 가능한 계산도 달라진다.

## 학습 점검

1. C의 `int quantity = 1;`에서 `int`와 `1`은 타입 관점에서 각각 어떤 역할을 하는가?
2. Python에서 변수 앞에 타입을 적지 않아도 값의 타입을 확인할 수 있는 이유는 무엇인가?
3. 상품 ID와 구매 수량이 모두 정수형이어도 가능한 계산이 다른 이유는 무엇인가?
4. 명목·순서·간격·비율 척도의 패션 데이터 예를 하나씩 제시하시오.
5. 혼합 dtype의 DataFrame을 `to_numpy()`로 바꾸면 `object` 배열이 될 수 있는 이유는 무엇인가?
6. `np.asarray(1).shape`와 `np.array([1, 2]).shape`의 차이를 설명하시오.

<details>
<summary>정답과 해설 보기</summary>

1. `int`는 변수 `quantity`의 선언 타입이고, 리터럴 `1`도 C 규칙상 기본 `int` 값을 만든다.
2. Python은 값이 타입을 가지며 변수 이름이 그 객체를 동적으로 가리키기 때문이다. `type()`으로 확인할 수 있다.
3. dtype은 저장 형식일 뿐 의미와 척도를 정하지 않는다. ID는 이름 역할, 수량은 비율 척도다.
4. 브랜드는 명목, 고객 등급은 순서, 섭씨 보관 온도는 간격, 구매 수량은 비율 척도의 예다.
5. 하나의 NumPy 배열은 공통 dtype을 가져야 하므로 문자열과 숫자가 섞이면 일반 Python 객체를 담는 `object`가 사용될 수 있다.
6. 단일 스칼라 배열은 축이 없어 `()`, 두 원소의 1차원 배열은 `(2,)`다.

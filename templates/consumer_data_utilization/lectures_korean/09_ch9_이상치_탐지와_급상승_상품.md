# 판매량 급변은 신호일까: 기준선·3σ·급상승 탐지

> **기준선으로 읽기**
> 3σ는 모든 판매 데이터에 맞는 최신 탐지 정답이 아니라, 기준선과 현재 값의 차이를 설명하기 쉬운 출발점이다. 계절성·희소 판매·프로모션이 강하면 이동 중앙값, 분위수, 예측 잔차 같은 대안과 비교하고 실제 경보의 유용성을 평가한다.

하루 평균 5개가 팔리던 상품이 오늘 11개 팔렸다. 정말 수요가 급상승한 것일까, 광고·재고·집계 오류 때문에 생긴 값일까? 이 장에서는 과거 데이터로 **기준선**을 만들고 오늘 값이 기준선에서 얼마나 멀리 벗어났는지 계산해, 사람이 확인할 후보를 좁힌다.

## 생각해 보기: 11개는 큰 값인가?

최근 9일 판매량이 `5, 6, 4, 6, 5, 4, 5, 6, 11`이라고 하자. 11은 앞선 값보다 크다. 그러나 다음 정보 없이 “인기 급상승”이라고 결론 내리기는 어렵다.

- 11개가 나온 날에 할인이나 광고가 있었는가?
- 이전에는 품절이라 판매 기회가 막혀 있지 않았는가?
- 주말과 평일의 판매량이 원래 다른가?
- 반품을 음수로 처리했는가, 주문 수량만 셌는가?
- 데이터가 중복 적재되거나 일부 날짜가 누락되지는 않았는가?

> **핵심 관찰**
> 이상치 탐지는 원인을 증명하지 않는다. **평소와 달라 확인할 가치가 있는 관측값**을 빠르게 찾는다.

## 학습 목표

이 장을 마치면 다음을 할 수 있다.

- 이상치 탐지가 특정 알고리즘이 아니라 문제 해결 목적임을 설명할 수 있다.
- 과거 평균, 표준편차와 z 점수로 3σ 경보를 계산할 수 있다.
- 오늘 값을 기준선 계산에서 제외해야 하는 이유를 설명할 수 있다.
- 거래 데이터를 상품×날짜 표로 바꾸고 급상승·급하락 후보를 찾을 수 있다.
- 판매량에 정규분포를 가정하기 어려운 상황을 식별할 수 있다.
- 경보를 프로모션·재고·오류 점검과 사람의 의사결정으로 연결할 수 있다.
- 탐지 시스템을 정확도뿐 아니라 경보량과 대응 시간으로 평가할 수 있다.

## 핵심 용어

- **이상치 탐지(anomaly detection)**: 평소의 기준이나 다른 관측값에서 크게 벗어난 대상을 찾는 접근법.
- **기준선(baseline)**: 오늘 값과 비교하기 위해 과거의 정상 구간에서 계산한 기대 수준.
- **표준편차(standard deviation, σ)**: 값들이 평균 주변에서 얼마나 퍼져 있는지를 나타내는 수치.
- **z 점수(z-score)**: 관측값이 평균에서 표준편차 몇 개만큼 떨어져 있는지 나타낸 값.
- **관리 한계(control limit)**: 공정이나 지표의 비정상 변화를 확인하기 위해 정한 통계적 경계.
- **데이터 누수(leakage)**: 판정할 현재·미래 정보가 기준이나 학습 과정에 섞여 평가를 왜곡하는 현상.

## 1. ‘이상하다’를 측정 가능한 질문으로 바꾸기

이상치 탐지는 하나의 알고리즘 이름이 아니다. 제조 불량, 비정상적인 기계 소리, 결제 사기, 갑작스러운 판매량 변화처럼 **정상과 다른 대상을 찾는 목적**을 가리킨다.

| 업무 질문 | 관측 단위 | 정상 기준 | 후보 신호 |
|---|---|---|---|
| 어떤 상품이 갑자기 잘 팔리는가? | 상품별 일 판매량 | 최근 28일 같은 상품 | 기준선보다 큰 값 |
| 어느 지역의 주문이 급감했는가? | 지역별 일 주문 수 | 같은 요일의 과거 값 | 기준선보다 작은 값 |
| 결제 오류가 발생했는가? | 분당 실패 건수 | 최근 정상 시간대 | 짧은 시간의 큰 증가 |
| VIP의 구매가 달라졌는가? | 고객별 월 구매액 | 고객 자신의 과거 | 장기 평균에서 큰 이탈 |

이 장의 질문은 **“각 상품의 오늘 판매량이 그 상품의 과거 기준선에서 얼마나 멀리 벗어났는가?”**이다. 다른 상품과의 인기 순위를 구하는 문제가 아니다.

## 2. 3σ 규칙: 평균에서 얼마나 멀리 떨어졌는가

과거 판매량의 평균을 \(\mu\), 표준편차를 \(\sigma\), 오늘 판매량을 \(x_t\)라 하면 z 점수는 다음과 같다.

\[
z_t = \frac{x_t - \mu_{\text{past}}}{\sigma_{\text{past}}}
\]

- \(z_t = 0\): 오늘 값이 과거 평균과 같다.
- \(z_t = 2\): 과거 평균보다 표준편차 2개만큼 높다.
- \(z_t \ge 3\): 단순 3σ 규칙에서 급상승 경보 후보가 된다.
- \(z_t \le -3\): 단순 3σ 규칙에서 급하락 경보 후보가 된다.

[NIST/SEMATECH의 관리도 설명](https://www.itl.nist.gov/div898/handbook/pmc/section3/pmc31.htm)처럼 Shewhart 관리도는 중심선과 흔히 ±3σ 관리 한계를 사용해 비정상 변화를 살핀다. 정확한 정규분포를 가정하면 관측값의 약 99.73%가 평균±3σ 안에 있지만, 실제 판매량이 정규분포를 따른다는 보장은 없다.

### 3σ와 Six Sigma는 같은 말이 아니다

이 장에서 쓰는 것은 **과거 평균±3표준편차를 경보선으로 삼는 교육용 탐지 규칙**이다. Six Sigma는 품질 개선을 위한 더 넓은 경영·프로세스 방법론이다. 정규분포 그래프를 6등분하거나 3등분해서 이름 붙인 탐지법이 아니다.

| 개념 | 이 장에서의 의미 | 오해하지 말 것 |
|---|---|---|
| 3σ 관리 한계 | 평균에서 표준편차 3개 이상 벗어났는지 보는 경보 기준 | 원인이 증명되었다는 뜻이 아님 |
| Six Sigma | 결함과 변동을 줄이는 조직적 품질 개선 방법론 | 단순히 그래프를 여섯 구간으로 나누는 방법이 아님 |
| z 점수 | 서로 다른 평균·변동을 가진 상품을 표준화한 거리 | 관측값이 발생할 확률 그 자체가 아님 |

## 3. 단순 예: 9일째 11개는 어떤가?

앞 8일 판매량을 기준선으로 사용한다.

`5, 6, 4, 6, 5, 4, 5, 6 | 오늘 11`

앞 8일의 평균은 5.125, 표본 표준편차는 약 0.83이다.

\[
z_{\text{오늘}}
=\frac{11 - 5.125}{0.83}
\approx 7.1
\]

단순 3σ 기준에서는 급상승 경보가 된다. 여기서 가장 중요한 규칙은 **오늘의 11을 평균과 표준편차 계산에 넣지 않는 것**이다. 판정할 값을 기준선에 넣으면 평균과 표준편차가 함께 커져 이상 신호가 약해진다.

| 계산 방식 | 기준선에 사용한 값 | 문제 |
|---|---|---|
| 올바른 비교 | 오늘 이전 8일 | 오늘을 과거 정상 기준과 비교 |
| 누수가 있는 비교 | 오늘을 포함한 9일 | 큰 오늘 값이 자신의 기준선을 끌어올림 |

> **즉시 해석**
> z≈7.1은 “앞 8일의 평균과 변동에 비해 매우 멀다”는 뜻이다. “인기가 7.1배 늘었다”거나 “급상승일 확률이 99%다”라는 뜻은 아니다.

표본 8일은 원리를 배우기 위한 작은 예시다. 실제 운영에서는 충분한 과거 기간과 계절성 검토가 필요하다.

## 4. 거래 기록을 상품×날짜 표로 바꾸기

원본 거래는 보통 한 행이 한 주문 항목이다.

| 시각 | 상품 | 판매수량 | 주문 상태 |
|---|---|---:|---|
| 2023-01-02 19:35 | product_0 | 1 | 결제 완료 |
| 2023-01-02 14:20 | product_21 | 2 | 결제 완료 |
| 2023-01-01 14:55 | product_0 | 1 | 결제 완료 |

먼저 시간에서 날짜를 만들고 [`pandas.pivot_table`](https://pandas.pydata.org/docs/reference/api/pandas.pivot_table.html)로 일별 판매량을 합친다.

```python
import pandas as pd

tx["ordered_at"] = pd.to_datetime(tx["ordered_at"])
tx["date"] = tx["ordered_at"].dt.normalize()

# 예시: 결제 완료 주문만 사용한다.
completed = tx.loc[tx["order_status"] == "completed"].copy()

daily = pd.pivot_table(
    completed,
    index="product_id",
    columns="date",
    values="quantity",
    aggfunc="sum",
    fill_value=0
).sort_index(axis=1)
```

### 0과 결측은 다르다

`fill_value=0`을 안전하게 쓰려면 그 날짜에 상품이 실제로 판매 가능했고 데이터 수집도 정상이라는 전제가 필요하다.

| 상황 | 기록의 의미 | 처리 예시 |
|---|---|---|
| 상품이 판매 중이었지만 주문 없음 | 실제 판매량 0 | 0으로 포함 |
| 상품이 품절·판매 중지 | 판매 기회 없음 | 재고 상태를 별도 변수로 표시 |
| 데이터 파이프라인 장애 | 값을 모름 | 결측으로 두고 경보 계산 제외 |
| 반품 발생 | 순매출·순수량 감소 | 주문 수량과 반품 수량을 분리 |

0과 결측을 혼동하면 시스템 장애가 대규모 급하락으로 표시될 수 있다.

## 5. 오늘을 제외한 과거로 z 점수 계산하기

아래 코드는 마지막 열을 오늘로 보고, 그 앞의 날짜만으로 기준선을 계산한다.

```python
import numpy as np

history = daily.iloc[:, :-1]
today = daily.iloc[:, -1]

past_mean = history.mean(axis=1)
past_std = history.std(axis=1, ddof=1)

# 과거 값이 모두 같아 표준편차가 0인 상품은 별도 검토한다.
safe_std = past_std.replace(0, np.nan)
z_today = (today - past_mean) / safe_std

result = pd.DataFrame({
    "past_mean": past_mean,
    "past_std": past_std,
    "today": today,
    "z_today": z_today
})

result["signal"] = "usual"
result.loc[result["z_today"] >= 3, "signal"] = "spike"
result.loc[result["z_today"] <= -3, "signal"] = "drop"

alerts = result.loc[result["signal"] != "usual"]
alerts.sort_values("z_today", ascending=False).head(20)
```

기존의 `norm.pdf` 값을 상품끼리 비교해 하위 5%를 자르는 방법은 3σ 규칙과 다르다. 확률밀도의 높이는 표준편차가 다른 분포끼리 직접 비교하기 어렵고, 오늘을 포함해 평균·표준편차를 계산하면 누수도 생긴다. 이 장에서는 해석이 분명한 과거 전용 z 점수를 사용한다.

### 매일 운영하려면 이동 기준선을 사용한다

최근 28일을 기준으로 매일 z 점수를 계산하려면 현재 날짜를 제외하도록 `shift(1)`을 적용한다. [`pandas.DataFrame.rolling`](https://pandas.pydata.org/docs/reference/api/pandas.DataFrame.rolling.html)은 이동 구간 통계를 계산한다.

```python
# 계산하기 쉽게 날짜×상품 형태로 뒤집는다.
daily_t = daily.T

rolling_mean = daily_t.rolling(window=28, min_periods=14).mean().shift(1)
rolling_std = daily_t.rolling(window=28, min_periods=14).std().shift(1)

rolling_z = (daily_t - rolling_mean) / rolling_std.replace(0, np.nan)
spike_flags = rolling_z >= 3
drop_flags = rolling_z <= -3
```

`min_periods=14`는 예시일 뿐 정답이 아니다. 판매 주기, 신상품 수명과 계절에 맞춰 백테스트로 정한다.

## 6. 정규분포와 3σ가 잘 맞지 않는 상황

판매량은 0보다 작을 수 없는 **개수 데이터**이고, 적게 팔리는 상품은 0과 1이 대부분일 수 있다. 이런 데이터는 대칭적인 정규분포와 다를 수 있다.

| 상황 | 단순 평균±3σ의 문제 | 보완 방향 |
|---|---|---|
| 판매량이 매우 적고 0이 많음 | 분포가 한쪽으로 치우치고 표준편차가 불안정 | 포아송 등 개수 모형, 최소 판매량 조건 검토 |
| 주말마다 판매량 증가 | 평일·주말이 한 기준선에 섞임 | 같은 요일끼리 비교하거나 계절성 제거 |
| 행사 기간에 구조적 증가 | 과거 평균이 더 이상 정상 기준이 아님 | 행사 여부를 분리하고 새 기준선 설정 |
| 신상품이라 과거가 짧음 | 평균·표준편차를 믿기 어려움 | 카테고리 기준선·최소 관측 기간 사용 |
| 과거 판매량이 모두 같음 | 표준편차가 0이라 z 계산 불가 | 절대 변화량 규칙이나 개수 모형 사용 |
| 수천 상품을 동시에 검사 | 우연한 경보가 많이 발생 | 경보 예산·지속 조건·다중 검정 고려 |

[NIST는 계수형 데이터용 관리도](https://www.itl.nist.gov/div898/handbook/pmc/section3/pmc331.htm)와 작은 지속 변화에 민감한 [CUSUM 관리도](https://www.itl.nist.gov/div898/handbook/pmc/section3/pmc313.htm)도 별도로 설명한다. 3σ는 출발점이지 모든 판매 데이터의 정답이 아니다.

> **즉시 해석**
> 경보가 너무 많거나 특정 유형의 상품에만 몰리면 임계값만 높이기 전에 기준선, 집계 단위와 분포 가정을 먼저 점검한다.

  <div><strong>데이터 확인</strong><span>중복·누락</span><i>→</i><span>취소·반품</span><i>→</i><span>집계 시각</span></div>
  <b>↓</b>
  <div><strong>업무 맥락 확인</strong><span>프로모션</span><i>→</i><span>재고·품절</span><i>→</i><span>요일·날씨</span><i>→</i><span>콘텐츠 노출</span></div>
  <b>↓</b>
  <div class="flow-highlight"><strong>사람의 판단 후 행동하고 결과를 기록</strong></div>
</div>

| 경보 | 가능한 원인 | 확인 데이터 | 가능한 행동 |
|---|---|---|---|
| 급상승 | 인플루언서 노출·광고·가격 인하 | 유입 채널, 캠페인, 가격 이력 | 재고 확보, 콘텐츠 확대 검토 |
| 급상승 | 주문 중복 적재 | 주문 ID 중복, 파이프라인 로그 | 수치 수정, 경보 무효 처리 |
| 급하락 | 품절·노출 중단 | 재고, 판매 상태, 진열 로그 | 재입고·노출 복구 |
| 급하락 | 실제 수요 감소 | 검색·상세 조회·장바구니 | 상품·가격·콘텐츠 점검 |
| 전체 상품 급락 | 데이터 수집 장애 | 시스템 상태, 총 주문 수 | 분석 중단, 데이터 복구 |

이상치가 잡혔다고 즉시 진열 순위를 자동 변경하면 데이터 오류를 더 크게 증폭할 수 있다. 처음에는 담당자에게 근거와 함께 알리고, 반복 검증으로 신뢰도가 확인된 규칙만 제한적으로 자동화한다.

## 8. 탐지 시스템은 어떻게 평가할까?

“경보가 나왔다”만으로 성능을 알 수 없다. 과거 프로모션, 품절과 장애 기록을 정답 후보로 삼아 백테스트한다.

| 평가 항목 | 질문 | 해석 |
|---|---|---|
| 정밀도(precision) | 경보 중 실제 확인 가치가 있었던 비율은? | 낮으면 담당자가 경보를 무시하게 됨 |
| 알려진 사건 재현율 | 기록된 행사·품절·장애를 얼마나 잡았는가? | 중요한 사건 누락 여부 확인 |
| 탐지 지연 | 사건 시작 후 몇 시간·며칠 만에 알렸는가? | 대응 가능한 속도인지 확인 |
| 하루 경보 수 | 담당자가 실제 검토할 수 있는 양인가? | 운영 가능한 경보 예산 확인 |
| 상품군별 편차 | 신상품·저판매 상품만 과도하게 울리는가? | 기준선의 구조적 편향 확인 |
| 행동 성과 | 경보 후 조치가 품절 방지·매출·오류 복구에 도움 되었는가? | 분석이 의사결정 가치로 연결됐는지 확인 |

임계값을 3에서 2로 낮추면 보통 더 많은 변화를 잡지만 거짓 경보도 늘어난다. 4로 높이면 경보는 줄지만 작은 중요 변화를 놓칠 수 있다. 운영 목적에 따라 이 균형을 정한다.

## 짧은 활동: 손으로 이상치 판단하기

한 상품의 최근 9일 판매량은 `5, 6, 4, 6, 5, 4, 5, 6, 11`이다. 기존 실습의 판단 활동을 다음 표로 확장한다.

| 단계 | 계산·판단 | 내 답 |
|---|---|---|
| 1 | 앞 8일의 평균 |  |
| 2 | 앞 8일의 표본 표준편차 |  |
| 3 | 9일째 값의 z 점수 |  |
| 4 | 3σ 규칙의 경보 여부 |  |
| 5 | 확인할 대안 원인 두 가지 |  |
| 6 | 오늘 취할 행동과 확인 지표 |  |

계산 뒤 다음 두 문장을 완성한다.

> “오늘 값은 과거 기준선에서 약 ______σ 떨어져 있어 ______ 경보 후보다.”

> “그러나 ______와 ______를 확인하기 전에는 인기 상승이 원인이라고 단정할 수 없다.”

## 이 장의 핵심

- 이상치 탐지는 ‘평소와 다른 것을 빨리 찾는다’는 목적이며 한 가지 알고리즘이 아니다.
- 이 장의 단순 규칙은 Six Sigma 방법론 전체가 아니라 과거 평균±3σ를 관리 한계로 쓰는 방식이다.
- z 점수는 관측값이 과거 평균에서 표준편차 몇 개만큼 떨어졌는지 나타낸다.
- 오늘을 기준선 계산에 넣으면 데이터 누수가 생기므로 과거 데이터만으로 평균과 표준편차를 구한다.
- 거래 단위 데이터는 상품×날짜로 집계하되, 0 판매와 데이터 누락·품절을 구분한다.
- 저판매·계절성·프로모션·신상품에서는 단순 정규 가정과 3σ 규칙이 잘 맞지 않을 수 있다.
- 경보는 원인이 아니다. 데이터와 업무 맥락을 확인하고 사람의 판단을 거쳐 행동한다.
- 탐지 시스템은 정밀도, 사건 재현율, 탐지 지연, 하루 경보 수와 행동 성과로 평가한다.

## 학습 점검

1. 이상치 탐지를 하나의 알고리즘이 아니라 접근법이라고 부르는 이유는 무엇인가?
2. 3σ 관리 한계와 Six Sigma의 차이를 설명하시오.
3. 오늘 판매량을 포함해 평균과 표준편차를 계산하면 왜 문제가 되는가?
4. z 점수가 3.5라는 말의 정확한 뜻은 무엇인가?
5. 피벗 테이블의 빈칸을 무조건 0으로 채우면 안 되는 이유는 무엇인가?
6. 급상승 경보가 발생했을 때 확인할 데이터 원인과 업무 원인을 하나씩 쓰시오.

## 알아볼 것: 생성형 AI로 풀어보는 과제

1. **임계값 비교하기**: 같은 데이터에서 2σ, 3σ, 4σ를 적용했을 때 경보 수가 어떻게 달라지는지 코드를 제안받고, 가장 큰 경보 수가 가장 좋은지 토론한다.
2. **다른 기준선 조사하기**: 이동 중앙값·MAD, 포아송 모형, CUSUM 중 하나를 조사해 저판매 상품이나 작은 지속 변화에 왜 도움이 될 수 있는지 정리한다.
3. **경보 설명 감사하기**: AI가 `z ≥ 3`을 “인기 상품”이라고 설명하면, 원인과 상관관계를 혼동한 부분을 찾아 수정한다.

> **알아두기**
> 통계 공식이 맞아도 기준선 기간, 결측 처리와 업무 맥락이 틀리면 경보는 쓸모없을 수 있다. 코드뿐 아니라 집계 정의와 원인 확인 절차를 함께 검증한다.

# 패션 데이터 직무와 분석 워크플로우

패션 산업은 다른 산업보다 유난히 빅데이터·AI 분야의 관심을 많이 받는다. 온라인 쇼핑몰을 운영하는 과정 자체가 데이터를 만들어내고, 상품 하나에도 이름·설명 같은 텍스트, 바닥 이미지·모델 착용 이미지·SNS 착용샷 같은 여러 형태의 이미지, 판매량·클릭률 같은 수치 데이터가 동시에 쌓이기 때문이다. 이 장에서는 이런 데이터를 실제로 다루는 직무가 무슨 일을 하는지, 그리고 데이터 수집에서 서비스까지 이어지는 현실의 업무 흐름을 살펴본다.

> **생각해 보기**
> "데이터 분석가는 숫자를 잘 다루는 사람이다"라는 문장에 얼마나 동의하는가? 데이터 수집, 가공, 분석, 서비스 적용 중 어느 단계가 가장 시간이 많이 들 것 같은가?

## 학습 목표

이 단원을 마치면 다음을 할 수 있다.

- 패션 산업이 다른 산업보다 데이터 활용에 유리한 이유를 네 가지로 설명할 수 있다.
- 데이터 직무를 "패턴을 규명하고 활용하는 일"로 정의하고 구체적인 예를 들 수 있다.
- 데이터 수집부터 서비스 제공까지 이어지는 5단계 업무 과정을 pivot·join 예시로 설명할 수 있다.
- 나선형(반복) 워크플로우가 왜 필요한지 설명할 수 있다.

## 핵심 용어

- **피벗(pivot)**: 세로로 나열된 데이터를 날짜·상품 등 기준에 따라 가로·세로 표 형태로 재구성하는 작업.
- **조인(join)**: 서로 다른 두 데이터(예: 판매 데이터와 기온 데이터)를 공통 기준으로 연결해 하나의 표로 합치는 작업.
- **나선형 모델(spiral model)**: 데이터 수집부터 서비스까지 한 번에 끝나지 않고, 세부 내용을 더하며 처음 단계로 되돌아가기를 반복하는 업무 방식.

## 패션 산업이 데이터와 가까운 이유

패션 산업이 빅데이터·AI 분야의 관심을 유독 많이 받는 데는 네 가지 특성이 있다.

| 특성 | 설명 |
|---|---|
| 데이터 생성 | 쇼핑몰 운영, 화보 촬영 등 산업을 유지하는 과정 자체에서 자연스럽게 데이터가 생성된다 |
| 여러 형태의 이미지 | 바닥 이미지, 모델 착용 이미지, SNS 일반인 착용 이미지 등 같은 상품도 다양한 이미지로 존재한다 |
| 다양한 타입의 데이터 | 상품명·설명 같은 텍스트, 판매실적·클릭률 같은 수치 데이터가 함께 쌓인다 |
| 낮은 접근성 장벽 | 공장 데이터처럼 특정인만 볼 수 있는 게 아니라, 누구나 온라인 쇼핑몰에서 데이터를 관찰할 수 있다 |

이 네 가지가 겹치기 때문에 온라인 쇼핑몰은 그 자체로 거대한 데이터의 집합소가 된다. 상품을 대표하는 이미지 하나만 봐도 텍스트·수치 데이터가 함께 따라오고, 그 데이터에 누구나 비교적 쉽게 접근할 수 있다.

## 데이터 직무란 무엇인가

데이터를 다루는 직무를 한 문장으로 표현하면 **데이터의 패턴을 규명하는 일**이다. 규명한 패턴은 시장의 인사이트를 리포트로 전달하거나, 비슷한 상황에 자동으로 대응하는 서비스를 만드는 데 쓰인다.

예를 들어 A 쇼핑몰의 판매 데이터를 분석해 "강남 지역에 거주하는 30대 남성 직장인은 20~25만 원대의 남색 오버사이즈 코트를 가장 많이 산다"는 패턴을 찾았다고 하자. 이 패턴은 두 가지로 쓰일 수 있다. 하나는 상품기획팀에 보고서로 전달되어 광고 컨셉을 짜는 데 참고 자료가 되는 것이고, 다른 하나는 쇼핑몰 시스템과 연동되어 조건에 맞는 신규 고객에게 매일 아침 9시 남색 오버사이즈 코트를 추천하는 이메일을 자동으로 보내는 것이다. 전자는 패턴을 리포트로, 후자는 패턴을 서비스로 활용한 예다.

## 직무 수행 과정: 수집부터 서비스까지

패턴을 찾는 실제 업무는 대체로 다섯 단계를 거친다.

**1) 데이터 수집.** 고객사 및 자사의 데이터 구축 현황을 파악하는 것이 먼저다. 쇼핑몰이 카페24 같은 플랫폼으로 만들어졌다면 API로 데이터를 가져올 수 있고, 보안 문제로 API 제공이 어렵다면 파일을 이메일이나 USB로 전달받기도 한다. 경쟁사나 날씨처럼 고객사 협조 없이는 얻을 수 없는 데이터는 크롤러를 개발해 수집하고, 새로운 캠페인 반응처럼 아직 존재하지 않는 데이터는 A/B 테스트 등으로 새로 만들어낸다.

**2) 분석을 위한 데이터 구축.** 수집한 데이터를 그대로 분석에 쓰는 경우는 드물다. 예를 들어 아래처럼 시간 순으로 쌓인 판매 기록이 있다고 하자.

| 시각 | 상품 | 판매수량 |
|---|---|---|
| 2022-01-02 19:35 | A | 1 |
| 2022-01-02 14:20 | B | 2 |
| 2022-01-01 14:55 | A | 1 |

하루 단위로 상품별 판매량을 비교하고 싶다면, 날짜를 컬럼으로 상품명을 인덱스로 하는 **피벗** 테이블로 바꿔야 한다.

| | 12.31 | 01.01 | 01.02 | 합계 |
|---|---|---|---|---|
| A | 3 | 1 | 3 | 7 |
| B | 2 | 2 | 2 | 6 |

만약 판매량을 그날의 기온과 함께 보고 싶다면, 날짜를 기준으로 판매 데이터와 기온 데이터를 **조인**해 하나의 표로 합친다. 피벗과 조인은 실무에서 가장 자주 쓰이는 전처리 방식이므로, 낯설다면 반드시 별도로 익혀둘 필요가 있다.

**3) 분석과 평가.** 목표에 맞는 분석 모델을 선택·개발하고 적용한 뒤 평가한다. 평가 결과가 만족스럽지 않으면 데이터 구축 단계로 되돌아가기도 한다.

**4) 서비스.** 분석 결과가 발견한 패턴을 근거로 보고서를 제출하거나, 고객사 프로그램이 비슷한 상황에 대응할 수 있도록 API를 제공하거나, 분석 결과를 곧바로 고객사 데이터베이스에 반영하거나, 데이터 수집 코드 자체를 전달하기도 한다.

## 나선형 모델: 한 번에 끝나지 않는 이유

수집→구축→분석→평가→서비스 과정은 마치 한 번에 끝나는 것처럼 보이지만, 실제 업무는 나선형(spiral) 구조를 그리며 반복된다. 각 단계의 세부 내용을 하나씩 추가하다 보면 처음부터 다시 시작해야 하는 경우가 대부분이다. 반복 자체가 비효율처럼 느껴질 수 있지만, **반복적인 작업을 부담 없이 받아들이는 태도가 분석가의 실력을 가른다**는 점을 기억할 필요가 있다.

## 실제 사례: 비전공자의 데이터 사이언티스트 전환기

패션 리테일 업계에는 컴퓨터공학을 전공하지 않고도 데이터 직무로 전환한 사례가 드물지 않다. 한 패션 전공자는 인문계 고등학교와 의류학과를 거쳐 브랜드 영업직으로 사회생활을 시작한 뒤, 대학원의 패션 리테일·서비스 연구실에서 데이터 분석을 접하고 독학으로 프로그래밍을 공부해 데이터 사이언티스트로 전직했다. 코딩 공부를 시작한 지 취업까지 약 19개월이 걸렸으며, 초반에는 논문 작업과 병행하느라 주 2~3일만 학습에 투자했고 후반 6개월은 학원 풀코스에 전념했다고 알려져 있다.

이 사례가 강조하는 점은 두 가지다. 첫째, Python은 데이터 수집·정제·분석·서비스 구현까지 한 언어로 이어서 할 수 있는 범용 언어이기 때문에 추천된다. 둘째, group-by·pivot-table 개념이나 통계 도구(SPSS 등) 사용 경험처럼 프로그래밍 이전에 이미 갖추고 있던 분석 지식이 학습 속도에 큰 영향을 준다. 프로그래밍을 전혀 익히고 싶지 않다면 웹스크래퍼, 래피드마이너, 텍스톰, 구글 애널리틱스 같은 대체 도구들도 존재하지만, 이들을 모두 따로 배우는 데 걸리는 시간은 Python 하나를 배우는 시간과 비슷하다는 것이 이 경험담의 결론이다.

## 짧은 활동: 나만의 피벗 테이블 그려보기

다음 판매 기록을 보고, 상품을 행으로 날짜를 열로 하는 피벗 테이블을 손으로 직접 그려보자.

| 시각 | 상품 | 수량 |
|---|---|---|
| 03-01 10:00 | 청바지 | 2 |
| 03-01 15:00 | 셔츠 | 1 |
| 03-02 11:00 | 청바지 | 1 |
| 03-02 13:00 | 셔츠 | 3 |

완성한 표를 보고 "3월 2일에 셔츠가 급증한 이유는 무엇일까?"에 대한 가설을 하나 세워보자.

## 이 장의 핵심

- 패션 산업은 자연스러운 데이터 생성, 다양한 이미지, 여러 타입의 데이터, 낮은 접근성 장벽이라는 네 가지 특성 때문에 빅데이터·AI 분야의 관심을 받는다.
- 데이터 직무는 한마디로 데이터의 패턴을 규명하고, 이를 리포트나 자동화 서비스로 만드는 일이다.
- 실제 업무는 데이터 수집 → 분석을 위한 구축(피벗·조인) → 분석·평가 → 서비스의 순서를 거친다.
- 이 과정은 한 번에 완성되지 않고 나선형으로 반복되며, 반복을 받아들이는 태도가 분석가의 역량을 좌우한다.
- 비전공자도 목적이 분명한 독학과 충분한 시간 투자로 데이터 직무에 진입할 수 있다.

2. 피벗과 조인의 차이를 예를 들어 설명하시오.
3. 나선형 모델이 필요한 이유를 설명하시오.
4. 데이터 분석 결과를 "서비스"로 만드는 방법을 두 가지 이상 제시하시오.

## 알아볼 것: 생성형 AI로 풀어보는 과제

1. **직무 인터뷰 시뮬레이션**: 생성형 AI에게 "패션 이커머스 데이터 분석가 역할을 맡아서, 매출 데이터 기반 급상승 상품 탐지 업무를 어떤 5단계로 수행하는지 이 장에서 배운 수집-구축-분석-평가-서비스 틀에 맞춰 설명해줘"라고 요청해보자. AI의 답변이 실제 업무 논리와 맞는지 이 장의 설명과 비교한다.
2. **피벗 연습 문제 만들기**: 생성형 AI에게 "초보자가 피벗과 조인 개념을 연습할 수 있는 간단한 판매 데이터 예제를 표로 만들어줘"라고 요청하고, 직접 손으로 피벗해본다.

> **알아두기**
> 생성형 AI가 제시하는 업무 절차나 도구 이름은 실제 조직의 관행과 다를 수 있다. 특정 직무의 실제 업무 범위는 채용 공고나 현직자 인터뷰로 다시 확인하는 것이 좋다.

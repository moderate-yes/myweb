# 선택 실습: 웹 데이터를 안전하게 수집해 코랩에서 확인하기

> **선택 실습**
> 웹페이지 수집은 모든 분석가의 필수 출발점이 아니다. 먼저 자사 운영 DB, 쇼핑몰의 공식 내보내기, 공식 API와 제공 파일을 확인한다. 필요한 데이터가 정당한 권한 아래 다른 방법으로 제공되지 않고, 페이지 정책과 법적·윤리적 조건을 충족할 때만 제한된 웹 수집을 고려한다. 리스틀리는 원리를 보여주는 도구 예시이며 필수 제품이 아니다.

지금까지 데이터의 모양과 분석 질문을 배웠다. 이제 수집이 허용된 웹페이지에서 필요한 항목을 가져와 표로 확인하는 실습으로 넘어간다. 이 장에서는 별도 설치 없이 파이썬을 실행하는 구글 코랩(Colab), 코드 없이 페이지 내용을 표로 추출하는 리스틀리(Listly), 그리고 수집 전에 확인해야 할 권한·개인정보·서버 부담을 함께 다룬다.

웹에서 기술적으로 보이는 정보를 자동 수집할 수 있다는 사실이 곧 수집·저장·재사용 권한을 뜻하지는 않는다. 따라서 실습 순서는 **도구 실행보다 수집 가능성 확인이 먼저**다.

> **판단 기준**
> "어떻게 긁을까?"보다 "이 질문에 이 데이터가 꼭 필요한가, 수집해도 되는가?"를 먼저 묻는다.

> **적용 범위**
> 이 장은 일반적인 학습 기준을 제공하며 법률 자문이 아니다. 실제 조직 프로젝트는 사이트 운영자, 개인정보·법무·보안 담당자와 현재 조건을 확인해야 한다.

> **선수 확인**
> 이 장부터 코드를 직접 실행한다. 변수·리스트·`for`·함수와 pandas의 `read_csv`·필터·`groupby`가 익숙하지 않다면 [Python Basic](templates/python_basic/lectures_korean/00_ch0_과정_안내.md) 1~4장을 먼저 본다.

## 1. 왜 코랩인가

[구글 코랩](https://colab.research.google.com/)은 별도 로컬 설치 없이 브라우저에서 파이썬 노트북을 실행할 수 있다. pandas, NumPy, matplotlib, scikit-learn과 같은 분석 패키지가 기본 환경에 포함되는 경우가 많고, 링크로 노트를 공유하기도 쉽다.

다만 "무료 GPU를 항상 쓸 수 있다"는 설명은 정확하지 않다. [코랩 공식 FAQ](https://research.google.com/colaboratory/intl/en-GB/faq.html)는 무료 계산 자원에 GPU·TPU가 포함될 수 있지만 자원은 보장되거나 무제한이 아니며 사용 한도가 변할 수 있다고 설명한다. 사전 설치 패키지의 버전도 런타임에 따라 바뀔 수 있다.

[RFC 9309](https://www.rfc-editor.org/info/rfc9309/)는 Robots Exclusion Protocol을 자동 클라이언트가 따라야 할 접근 규칙으로 표준화한다. 동시에 이 규칙이 접근 권한 자체를 부여하는 방식도, 콘텐츠 보안을 대신하는 방식도 아니라고 밝힌다. 즉 `robots.txt`가 허용한다고 해서 이용조건·저작권·개인정보 검토가 끝난 것은 아니며, 파일이 없다고 자동 수집이 승인된 것도 아니다.

[국가법령정보센터의 개인정보 보호법](https://law.go.kr/lsInfoP.do?lsId=011357)은 실제 프로젝트에서 확인해야 할 공식 법령 원문이다. 개인정보가 포함될 가능성이 있으면 강의 예제처럼 단순화하지 말고 조직의 담당자와 수집 목적, 법적 근거, 최소 범위, 보관·삭제 방식을 별도로 검토한다.

> **그림 읽기**
> 다섯 질문 중 하나라도 답을 알 수 없거나 접근 통제를 우회해야 한다면 수집을 멈추고 허가된 연습 페이지, 공개 API, 제공된 데이터셋 또는 본인이 관리하는 사이트로 대상을 바꾼다.

> **그림의 한계**
> 공개된 페이지와 공개 데이터는 같은 말이 아니다. 볼 수 있는 정보라도 대량 자동 수집, 재배포와 상업적 이용 조건은 각각 다를 수 있다.

## 4. 리스틀리로 허용된 페이지를 표로 추출하기

리스틀리(Listly)는 브라우저 확장 프로그램으로 페이지 구조를 분석해 화면의 내용을 표 형태로 추출하는 노코드 도구다. [리스틀리 공식 전체 추출 안내](https://help.listly.io/docs/ko/getting-started/listly-basics/whole-extraction)는 다음 기본 흐름을 제시한다.

1. 리스틀리 확장 프로그램을 설치한다.
2. **수집이 허용된 연습 페이지 또는 본인이 관리하는 페이지**를 연다.
3. 브라우저의 리스틀리 아이콘을 클릭하고 "전체(WHOLE)"를 선택한다.
4. 결과 화면의 미리보기 탭에서 필요한 표와 컬럼이 맞는지 확인한다.
5. "엑셀" 또는 "구글시트"로 내보낸다.

기존 수업에서는 쇼핑 랭킹 1위~180위 페이지를 예로 들 수 있지만, 실제 실습 시점의 이용조건이 같다고 가정해서는 안 된다. 강사가 허용 여부를 확인한 연습 자료를 우선 사용한다. 페이지가 여러 장이라면 각 페이지를 별도로 추출할 수 있지만, 페이지 전환을 자동 반복하기 전에도 허용 범위와 요청량을 다시 확인한다.

동적 로딩, 무한 스크롤, 로그인 상태, 광고와 추천 영역 때문에 화면에 보이는 내용이 빠지거나 중복될 수 있다. 추출 성공 메시지는 데이터가 완전하고 정확하다는 보증이 아니다.

## 5. 수집 파일이 분석 표가 되는 흐름

허용된 웹페이지에서 필요한 항목을 Listly로 미리 확인한 뒤 Excel로 내보내고, 필요하면 Drive에 보관해 Colab의 pandas DataFrame으로 읽을 수 있다. 각 단계는 단순한 파일 이동이 아니라 값의 타입·누락·행 수가 달라질 수 있는 변환이다.

> **변환 중 확인**
> 각 화살표에서 데이터가 달라질 수 있다. 페이지의 가격이 문자열로 저장되거나 이미지 링크가 빠질 수 있으므로 원본 화면, 추출 미리보기와 데이터프레임을 차례로 대조한다.

> **수집 범위의 한계**
> 엑셀 파일에는 현재 화면에 렌더링된 내용만 들어갈 수 있다. 서버의 전체 상품, 품절 이력이나 과거 순위까지 포함한다고 가정하면 안 된다.

최소한 다음 수집 기록을 파일과 함께 남긴다.

| 기록 항목 | 예 |
|---|---|
| 분석 질문 | 현재 연습 상품의 가격 분포는 어떠한가? |
| 출처 URL | 허용된 연습 페이지 주소 |
| 수집 시각·시간대 | 2026-08-14 14:00 KST |
| 수집 범위 | 1페이지, 상품명·가격·상품 URL |
| 허가·조건 확인 | 확인한 이용조건과 `robots.txt` 날짜 |
| 알려진 누락 | 품절 상품, 무한 스크롤 이후 항목 미포함 |

## 6. 수집한 엑셀을 코랩에서 확인하기

엑셀 파일을 구글 드라이브에 업로드한 뒤 pandas로 읽는다.

```python
import pandas as pd

file_path = '/content/drive/MyDrive/practice_catalog_1.xlsx'
df_1 = pd.read_excel(file_path)
df_1.head()
```

`head()`는 기본적으로 앞부분 5개 행을 보여주고 `tail()`은 마지막 행들을 보여준다. 화면 몇 줄만 보고 수집이 성공했다고 판단하지 말고 구조와 결측치를 함께 확인한다.

```python
print(df_1.shape)          # 행 수, 열 수
print(df_1.columns)        # 컬럼 이름
print(df_1.dtypes)         # 저장 타입
print(df_1.isna().sum())   # 컬럼별 결측치 수
```

여러 페이지를 허용 범위 안에서 각각 추출했다면 컬럼이 같은지 확인한 뒤 합칠 수 있다.

```python
df_2 = pd.read_excel('/content/drive/MyDrive/practice_catalog_2.xlsx')
df_all = pd.concat([df_1, df_2], ignore_index=True)
```

합친 뒤에는 상품 URL 같은 식별 후보를 기준으로 중복 여부를 확인한다. 가격에 쉼표와 "원"이 붙은 문자열, 할인 가격과 정상 가격의 혼합, 비어 있는 상품명도 다음 분석 전에 정리해야 한다.

## 7. 왜 파이썬과 노코드를 함께 쓰는가

웹 수집에는 리스틀리·웹스크래퍼 같은 도구, 네트워크 분석에는 NodeXL, 머신러닝에는 RapidMiner, 텍스트 분석에는 TEXTOM·UCINET, 대시보드에는 Looker Studio 같은 목적별 GUI 도구가 있다. GUI 도구는 빠른 탐색과 반복 가능한 화면 작업에 유리하다.

파이썬은 Beautiful Soup·Scrapy·Selenium 같은 수집 도구, pandas·NumPy·SciPy·scikit-learn 같은 분석 도구, TensorFlow·PyTorch 같은 AI 도구를 한 작업 흐름에서 연결할 수 있다. SQLAlchemy로 데이터베이스에 연결하고 Django·Flask로 서비스까지 확장할 수도 있다.

그러나 "여러 GUI를 배우는 총시간과 파이썬 하나를 배우는 시간이 같다"는 보편적 근거는 없다. 적합한 선택은 팀 역량, 데이터 규모, 재현성, 유지보수와 서비스 연결 필요에 따라 달라진다.

| 상황 | 노코드 도구 | 파이썬 | 권장 접근 |
|---|---|---|---|
| 허용된 한 페이지를 한 번 확인 | 빠름 | 준비가 더 필요할 수 있음 | 노코드로 추출 후 검증 |
| 여러 파일을 같은 규칙으로 정리 | 반복 실수 가능 | 코드로 재현 가능 | 파이썬 중심 |
| 페이지 구조가 자주 변함 | 설정도 깨질 수 있음 | 코드도 깨질 수 있음 | 작은 표본으로 지속 점검 |
| 실제 서비스에 연결 | 기능에 따라 제한 | 확장 가능 | 팀 운영 역량을 보고 결정 |

> **표 읽기**
> 노코드와 파이썬은 경쟁 관계가 아니다. 허용된 자료를 빠르게 확인할 때 노코드로 시작하고, 반복 가능한 정리·검증은 파이썬으로 이어갈 수 있다.

> **표의 한계**
> 파이썬을 사용한다고 자동으로 정확성, 합법성 또는 재현성이 생기지 않는다. 코드 버전, 실행 환경, 수집 시각과 원본 정의를 함께 기록해야 한다.

## 짧은 활동: 안전한 수집 계획 세우기

허용된 공개 데이터셋, 연습 페이지 또는 본인 사이트를 하나 정하고 아래 표를 채운다.

| 요청량과 서버 부담을 어떻게 줄일 것인가? |  |
| 수집 뒤 무엇을 대조하고 언제 삭제할 것인가? |  |

허가 여부가 불분명하면 수집 계획을 진행하지 말고 같은 질문에 답할 수 있는 공식 API나 제공 데이터셋을 찾는다.

## 이 장의 핵심

- 코랩 노트와 관리형 런타임, 구글 드라이브는 역할과 지속성이 다르다.
- 무료 코랩의 GPU·TPU와 사용 시간은 보장되거나 무제한이 아니다.
- 웹 수집은 이용조건, `robots.txt`, 접근 통제, 개인정보와 최소 요청량을 도구 실행 전에 확인한다.
- `robots.txt`는 자동 클라이언트의 규칙이지 수집·재사용 권한 전체를 보장하는 허가서가 아니다.
- 리스틀리 추출 결과는 원본과 대조하고, pandas에서 shape·컬럼·dtype·결측치를 다시 확인한다.
- 노코드와 파이썬은 목적과 운영 조건에 따라 함께 사용할 수 있다.

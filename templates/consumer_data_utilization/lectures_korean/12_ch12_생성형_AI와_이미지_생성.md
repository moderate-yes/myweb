# 프롬프트에서 패션 이미지까지: 생성 원리, 제어와 검증

생성형 AI는 패션 화보, 상품 콘셉트, 상세페이지 배경과 카피 초안을 빠르게 만든다. 하지만 ‘그럴듯한 이미지’와 ‘실제 상품을 정확하고 책임 있게 보여주는 이미지’는 다르다.

이 장에서는 프롬프트로 요구사항을 구조화하는 법, 확산모델이 노이즈에서 이미지를 만드는 기본 원리, 출력에 영향을 주는 통제 변수, 패션 이미지의 품질·권리·소비자 오인 위험을 하나의 제작 흐름으로 연결한다.

## 생각해 보기: 같은 문장인데 왜 결과가 다를까?

이미지 생성 모델에 ‘우아한 네이비 린넨 원피스, 여름 결혼식’이라고 두 번 요청했더니 모델의 얼굴, 원피스 주름, 배경이 달라졌다.

- 같은 프롬프트면 같은 결과가 나와야 하지 않을까?
- 결과가 달라진 원인은 프롬프트뿐일까?
- 실제 판매 상품에는 없는 소매나 단추가 생겼다면 그 이미지를 광고에 써도 될까?

> **중심 질문**
> 생성형 AI를 ‘한 번에 정답을 내는 도구’가 아니라 통제 가능한 후보 생성과 검증 과정으로 어떻게 사용할까?

## 학습 목표

이 단원을 마치면 다음을 할 수 있다.

- zero-shot·one-shot·few-shot과 구조화된 프롬프트의 차이를 설명할 수 있다.
- 확산모델의 노이즈 추가 학습과 반복적 노이즈 제거 생성을 구분할 수 있다.
- 프롬프트·참조이미지·마스크·seed·모델 버전이 출력에 미치는 역할을 설명할 수 있다.
- 대표적인 이미지 변환·패션 생성 연구가 해결한 과업과 한계를 구분할 수 있다.
- 생성 이미지를 제품 충실도·시각 품질·권리·소비자 오인 관점에서 평가할 수 있다.

## 핵심 용어

- **프롬프트(prompt)**: 모델에 제공하는 과업, 맥락, 입력, 제약과 출력 요구의 묶음.
- **in-context learning**: 모델 파라미터를 다시 학습하지 않고 프롬프트 안의 지시와 예시를 이용해 과업 패턴을 수행하는 방식.
- **conditioning(조건 부여)**: 텍스트, 참조이미지, 마스크, 포즈 같은 정보를 사용해 생성 방향을 제어하는 것.
- **확산모델(diffusion model)**: 학습 시 데이터에 노이즈가 더해지는 과정을 이용해 노이즈 제거를 배우고, 생성 시 노이즈에서 시작해 반복적으로 이미지를 복원하는 생성모델 계열.
- **seed**: 의사난수의 시작값. 같은 구현·모델·설정을 고정했을 때 결과 재현과 비교에 도움을 준다.
- **프로비넌스(provenance)**: 콘텐츠가 어디에서 어떤 도구와 편집 과정을 거쳐 왔는지에 관한 출처·이력 정보.

## 1. 좋은 프롬프트는 주문이 아니라 작업 명세다

GPT-3 연구는 모델을 추가 학습하지 않고도 프롬프트 안의 설명과 예시 수에 따라 여러 과업의 성능이 달라질 수 있음을 보였다. 이것은 ‘마법 문구 하나면 항상 정답’이라는 뜻이 아니다. 모델, 과업, 예시 품질과 평가 방식에 따라 결과가 달라진다.

| 방식 | 프롬프트 구성 | 패션 예시 | 한계 |
|---|---|---|---|
| Zero-shot | 지시만 제공 | “상품 설명을 작성해줘” | 형식·톤·사실 범위가 모호할 수 있음 |
| One-shot | 예시 1개 제공 | 브랜드의 승인된 설명 1개 제시 | 한 예시의 오류·편향을 따라갈 수 있음 |
| Few-shot | 여러 입력·출력 예시 제공 | 서로 다른 소재 설명 3개 제시 | 긴 맥락과 예시 선택 비용이 생김 |

### 프롬프트 계약 여섯 요소

| 요소 | 묻는 질문 | 원피스 이미지 예시 |
|---|---|---|
| 목표 | 무엇을 만들 것인가? | 상품 상세페이지용 정면 이미지 |
| 사실·맥락 | 무엇이 사실인가? | 실제 상품은 네이비 린넨 혼방, 긴소매, 허리끈 없음 |
| 참조 | 어떤 입력을 따라야 하는가? | 승인된 상품 정면·후면 사진 |
| 제약 | 무엇을 바꾸거나 만들면 안 되는가? | 단추·주머니·로고·핏을 새로 만들지 않음 |
| 출력 형식 | 어떤 크기·구도·배경이 필요한가? | 4:5, 전신, 중립 배경, 텍스트 없음 |
| 평가 기준 | 성공을 어떻게 판정할까? | 제품 디테일 일치, 인체 오류 없음, 광고표시 준수 |

**개선 전**

> 예쁜 원피스 그려줘.

**개선 후**

> 첨부한 승인 상품 사진을 기준으로 4:5 상세페이지 이미지를 만든다. 네이비 린넨 혼방, 긴소매, V넥, 허리끈이 없는 실제 구조를 유지한다. 정면 전신, 자연광, 중립적인 밝은 회색 배경으로 표현하고 로고나 문자는 추가하지 않는다. 상품에 없는 단추·주머니·벨트·패턴을 만들지 않는다. 결과를 제품 디테일 일치 여부를 검토할 수 있는 후보 3개로 제시한다.

프롬프트가 길다고 자동으로 좋아지는 것은 아니다. 서로 모순되는 요구, 모델이 알 수 없는 내부 용어, 검증할 수 없는 ‘고급스럽게’ 같은 표현이 늘면 오히려 불안정해진다.

### Chain of Thought를 과장하지 않기

Chain-of-Thought 연구는 산술·상식·기호 추론 과제에서 중간 추론 예시를 제공했을 때 일부 대규모 언어모델의 성능이 향상될 수 있음을 보였다. 그러나 ‘단계별로 생각해’라는 문구가 모든 문제의 정확도를 보장하지 않으며, 모델이 보여주는 긴 설명도 사실 검증의 증거가 아니다.

실무에서는 내부 추론을 길게 요구하기보다 다음을 분명히 하는 편이 재현 가능하다.

- 확인할 기준을 체크리스트로 제공한다.
- 사실과 아이디어를 별도 열로 출력하게 한다.
- 불확실한 항목은 ‘확인 필요’로 표시하게 한다.
- 승인된 원자료와 최종 결과를 사람이 대조한다.

> **즉시 해석**
> 프롬프트는 결과를 통제하는 하나의 입력이다. 모델의 학습 데이터, 버전과 생성 설정을 대신하지 않으며, 사실 정확성과 권리를 보장하지도 않는다.

## 2. 확산모델은 ‘자주 검은 픽셀’을 독립적으로 고르지 않는다

이미지는 픽셀 값의 배열로 표현할 수 있다. 그러나 현대 이미지 확산모델을 ‘각 위치에서 자주 나온 색을 골라 칠한다’고 설명하면 공간 구조와 반복적 노이즈 제거 학습을 놓치게 된다.

확산모델의 핵심은 두 방향을 구분하는 것이다.

  <div><strong>Generation: Reverse Process</strong><span>Random noise</span><i>→</i><span>Iterative denoising</span><i>→</i><span>Candidate image</span></div>

### 학습: 깨끗한 이미지에 노이즈를 더한다

단순화하면 시점 \(t\)의 noisy image \(x_t\)는 깨끗한 이미지 \(x_0\)와 무작위 노이즈 \(\epsilon\)의 조합으로 표현할 수 있다.

\[
x_t=\sqrt{\bar{\alpha}_t}x_0+\sqrt{1-\bar{\alpha}_t}\epsilon
\]

모델은 여러 노이즈 단계에서 어떤 노이즈가 더해졌는지 또는 더 깨끗한 표현이 무엇인지 예측하도록 학습한다. 실제 구현과 목적함수는 모델마다 다르지만, 중요한 직관은 **노이즈가 낀 전체 이미지 구조에서 되돌리는 법을 배운다**는 점이다.

### 생성: 무작위 노이즈에서 반복적으로 제거한다

새 이미지를 만들 때는 학습된 분포를 ‘살짝 변형’하는 것이 아니라, 무작위 노이즈에서 시작해 모델이 여러 단계를 거쳐 노이즈를 줄인다. 텍스트 ‘네이비 린넨 원피스’와 참조이미지 같은 조건은 각 단계의 생성 방향에 영향을 준다.

DDPM은 이 반복적 확률 과정을 현대 이미지 생성의 핵심 틀로 정리했다. Latent Diffusion은 고해상도 픽셀 공간 전체가 아니라 압축된 **latent space**에서 확산 과정을 수행해 계산 효율을 높이고 텍스트 같은 조건을 결합했다.

> **한계**
> ‘노이즈를 제거한다’는 말이 사진 속 실제 원피스를 복원한다는 뜻은 아니다. 모델은 조건과 학습된 패턴에 맞는 후보를 생성하므로, 실제 제품에 없는 구조를 그럴듯하게 만들어낼 수 있다.

| 통제 변수 | 하는 일 | 기록해야 하는 이유 |
|---|---|---|
| 텍스트 프롬프트 | 장면·상품·제약을 언어로 조건화 | 요구사항 변경 이력 확인 |
| 참조이미지 | 색·구조·스타일·정체성의 시각적 조건 제공 | 참조 권리와 실제 상품 대조 |
| 마스크 | 편집할 영역과 보존할 영역 구분 | 상품 영역이 의도치 않게 바뀌었는지 확인 |
| 포즈·배치 조건 | 인체 자세와 공간 구성을 유도 | 구도 차이를 줄여 비교 |
| seed | 시작 노이즈를 정함 | 같은 설정의 재현과 한 변수 비교 |
| 모델·버전 | 학습 데이터와 생성 능력에 큰 영향 | 업데이트 전후 결과가 달라질 수 있음 |
| sampler·steps 등 | 반복 노이즈 제거 경로·횟수에 영향 | 품질·속도·재현 조건 기록 |

같은 seed라도 모델 버전, 구현, 하드웨어·연산 방식이 달라지면 완전히 동일한 결과가 보장되지 않을 수 있다. 반대로 seed를 고정하지 않고 프롬프트 A와 B를 한 장씩만 비교하면 프롬프트 차이와 무작위 변동이 섞인다.

## 4. 패션 생성 연구는 서로 다른 과업을 해결한다

‘패션 AI’라는 이름 아래 이미지 변환, 속성 편집, 사람 재착장, 텍스트 생성이 섞여 있다. 논문의 입력과 출력부터 구분해야 한다.

| 연구·연도 | 입력과 과업 | 핵심 아이디어 | 강의에서 볼 점 | 한계 |
|---|---|---|---|---|
| pix2pix, 2017 | 짝지어진 입력→출력 이미지 변환 | 조건부 GAN과 paired data | 스케치→사진 등 지도 변환 | 정확히 짝지어진 학습쌍 필요 |
| CycleGAN, 2017 | 짝 없는 두 이미지 영역 변환 | cycle consistency | 속성·도메인 변환의 출발점 | 원하는 부분만 바뀐다는 보장 없음 |
| Be Your Own Prada, 2017 | 사람 이미지+의복 디자인 코딩→재착장 이미지 | 사람·의복 표현을 조건으로 합성 | 패션 전용 조건부 생성 | 자유로운 모든 의복·포즈를 해결한 것은 아님 |
| TailorGAN, 2020 | 기준 의복 이미지+목표 속성→편집 의복 | collar·sleeve 등 속성 제어 | 사용자 지정 디자인 편집 | 학습 속성·데이터 범위 밖 일반화 한계 |
| DDPM, 2020 | 노이즈→이미지 | 반복적 확률 노이즈 제거 | 현대 확산 생성의 기본 원리 | 반복 생성의 계산비용 |
| Latent Diffusion, 2022 | latent noise+텍스트 등→고해상도 이미지 | 압축된 잠재공간의 조건부 확산 | 효율적인 text-to-image 기반 | 학습 데이터·조건·평가의 편향과 오류 |

이 발전표는 ‘이전 연구가 틀리고 최신 연구가 모든 문제를 해결했다’는 순위가 아니다. paired data 없이 변환하기, 속성을 더 세밀하게 제어하기, 계산 효율을 높이기처럼 **문제 정의가 달라진 과정**이다.

## 5. 패션 이미지의 평가는 보기 좋음에서 끝나지 않는다

상세페이지 후보가 매우 사실적으로 보여도 실제 상품과 다르면 나쁜 결과다. 반대로 연구 벤치마크 점수가 좋아도 브랜드의 실제 제품·고객·채널에서 유용하다는 보장은 없다.

| 평가 영역 | 확인 질문 | 실패 예 | 확인 방법 |
|---|---|---|---|
| 제품 충실도 | 실제 소재·색·봉제·핏·옵션과 일치하는가? | 없는 주머니·단추 생성 | 승인 원본과 항목별 대조 |
| 인체·의복 구조 | 손·관절·주름·가림이 물리적으로 가능한가? | 소매와 손이 합쳐짐 | 확대 검수·실물 착장 비교 |
| 장면 품질 | 구도·조명·해상도가 채널 목적에 맞는가? | 그림자 방향 불일치 | 채널별 품질 기준표 |
| 텍스트·로고 | 글자·상표·라벨이 정확하고 허용되었는가? | 가짜 로고·깨진 글자 | 별도 원본 합성·법무 검토 |
| 대표성 | 체형·피부톤·성별 표현이 편향되지 않았는가? | 특정 체형에서만 자연스러움 | 다양한 승인 테스트셋 |
| 권리 | 참조·모델·소재를 사용할 권리가 있는가? | 무단 인물·작품 참조 | 라이선스·동의·계약 기록 |
| 소비자 오인 | 실제 판매 상품과 장면을 과장하지 않는가? | 방수 아닌 상품을 폭우 장면에서 무결점 표현 | 광고 주장과 실물 검증·고지 |
| 출처 이력 | 생성·편집 과정과 승인본을 추적할 수 있는가? | 어떤 모델로 만든 최종본인지 모름 | 파일·프롬프트·설정·승인 로그 |

## 실습: 프롬프트 A/B가 아니라 통제된 후보 비교

실제 또는 가상의 원피스 한 개를 정하고 승인된 사실 목록을 먼저 만든다.

### 1단계: 제품 사실과 창작 허용 범위

| 구분 | 작성 |
|---|---|
| 바꾸면 안 되는 제품 사실 |  |
| 바꿔도 되는 배경·구도 |  |
| 사용할 수 있는 참조이미지와 권리 |  |
| 금지 요소 |  |

### 2단계: 두 프롬프트 설계

- **A**: 기존의 짧고 모호한 프롬프트
- **B**: 목표·사실·참조·제약·출력·평가 기준을 포함한 프롬프트

가능하면 같은 모델·버전·seed·비율·steps를 사용해 프롬프트만 바꾼다. 각 조건에서 후보를 여러 장 만들고 한 장의 우연한 결과로 결론내리지 않는다.

### 3단계: 평가표

| 기준 | 가중치 | A 후보 점수·근거 | B 후보 점수·근거 |
|---|---:|---|---|
| 제품 디테일 일치 | 30 |  |  |
| 인체·의복 구조 | 20 |  |  |
| 목적에 맞는 구도 | 15 |  |  |
| 다양성과 대표성 | 10 |  |  |
| 권리·소비자 오인 | 20 |  |  |
| 재현·승인 기록 | 5 |  |  |

> **결과 문장**
> “B가 더 예뻤다”가 아니라 “통제한 조건에서 B 후보들은 제품 디테일 오류가 __에서 __로 줄었지만, __ 오류는 남았다. 실제 광고 사용 전 __ 검증이 필요하다”처럼 쓴다.

## 이 장의 핵심

- 프롬프트는 목표·사실·참조·제약·출력 형식·평가 기준을 담는 작업 명세다.
- few-shot은 예시를 프롬프트 안에 제공하는 방식이며 모든 과업의 정확도를 자동으로 높이지 않는다.
- Chain of Thought의 긴 설명은 정답의 증거가 아니다. 검증 가능한 기준과 원자료 대조가 필요하다.
- 확산모델은 위치별 빈도에서 픽셀을 독립적으로 뽑는 것이 아니라, 노이즈가 더해진 표현에서 반복적인 노이즈 제거를 학습한다.
- 생성은 학습된 모델을 ‘살짝 변형’하는 과정이 아니라 시작 노이즈를 조건에 따라 반복적으로 제거하는 과정이다.
- 결과는 프롬프트뿐 아니라 참조·마스크·seed·모델·버전·생성 설정에 달려 있다.
- 사실적인 이미지와 실제 상품에 충실한 이미지는 다르며, 권리·대표성·소비자 오인·출처 이력을 함께 평가해야 한다.

## 학습할 점

1. 생성 목적과 바꾸면 안 되는 사실은 무엇인가?
2. 프롬프트 외에 어떤 조건을 기록하고 통제해야 하는가?
3. 모델은 학습과 생성 단계에서 무엇을 하는가?
4. 후보를 어떤 기준과 여러 샘플로 비교할 것인가?
5. 제품·인물·참조의 권리와 고객 오인 위험을 누가 승인하는가?

## 학습 점검

1. zero-shot과 few-shot의 차이를 패션 카피 예시로 설명하시오.
2. 확산모델의 학습 방향과 생성 방향을 각각 설명하시오.
3. 같은 프롬프트의 결과가 달라질 수 있는 변수를 세 가지 쓰시오.
4. seed를 고정한 비교가 왜 유용하며, 무엇까지 보장하지는 않는가?
5. TailorGAN과 일반 text-to-image를 같은 과업이라고 부르면 안 되는 이유는 무엇인가?
6. 프로비넌스 정보가 있어도 별도 검증이 필요한 이유는 무엇인가?

<details>
<summary>정답과 해설 보기</summary>

1. zero-shot은 지시만 주고, few-shot은 원하는 입력·출력 예시 여러 개를 함께 준다. 승인된 소재 설명 예시를 제공해 새 상품 설명의 형식을 유도하는 것이 few-shot 예다.
2. 학습에서는 깨끗한 이미지에 노이즈가 더해진 여러 단계에서 노이즈 제거를 배우고, 생성에서는 무작위 노이즈에서 시작해 조건을 이용해 반복적으로 노이즈를 줄인다.
3. seed, 모델·버전, 참조이미지, 마스크, pose/layout 조건, sampler·steps 등이 있다.
4. 시작 노이즈를 맞추어 한 변수의 영향을 더 공정하게 비교하는 데 유용하지만, 다른 버전·구현·연산 환경까지 달라졌을 때 완전히 같은 결과를 보장하지는 않는다.
5. TailorGAN은 기준 의복과 목표 속성을 이용한 의복 속성 편집 문제를 다루며, 자유 텍스트에서 임의 장면을 만드는 일반 text-to-image와 입력·출력·데이터가 다르기 때문이다.
6. 출처 이력은 내용의 사실성, 실제 상품과의 일치, 참조 권리와 광고의 비기만성을 자동으로 증명하지 않기 때문이다.

</details>

## 알아볼 것: 생성형 AI로 풀어보는 과제

1. **통제 비교**: 짧은 프롬프트와 구조화된 프롬프트를 같은 생성 조건과 여러 seed에서 비교하고 평가표를 작성한다.
2. **검증 가능한 작업 분해**: 모델에게 ‘좋은지 단계별로 생각해’라고만 하지 말고 제품 사실·시각 오류·권리·오인 위험을 별도 열로 검사하게 한 뒤 사람이 원본과 대조한다.
3. **출처 이력 확인**: 사용 도구가 모델·생성 여부·편집 이력을 어떤 방식으로 기록하거나 내보내는지 공식 문서에서 확인한다.

> **알아두기**
> 모델 이름, 기능, 가격, 콘텐츠 정책은 빠르게 바뀐다. 비공식 코드명이나 홍보 문구 대신 사용 시점의 공식 모델 문서와 이용 조건을 기록한다.

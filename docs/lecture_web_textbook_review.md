# A. 웹 교재 전체 평가

## 현재 교재의 장점

- 패션 과정은 추상적인 데이터 개념을 SKU, 재고, 피팅룸, 룩북, 수요 예측 등 익숙한 실무 상황에 연결한다.
- ‘자동화가 먼저이고 인사이트가 그 위에 쌓인다’, ‘확률은 덜 틀리기 위한 수비 전략이다’처럼 기억하기 쉬운 중심 비유가 있다.
- 대부분의 패션 단원에 핵심 정리와 사례가 있어 장별 메시지는 비교적 선명하다.
- Flask 과정은 기획→라우팅→마크다운→수익 영역→보안·배포 순서가 논리적이다.
- 코드가 실제 사이트 구조와 연결되어 학습자가 결과물을 만들며 배울 수 있다.
- 문단이 대체로 짧고 Markdown 제목 구조가 사용되어 웹 본문으로 변환하기 쉽다.

## 내용 측면에서 보완이 필요한 부분

- 서로 다른 두 과정이 하나의 연속 목차로 노출된다. 12번 ‘생성형 AI’ 다음에 13번 ‘Flask 기획’이 이어져 학습 맥락이 끊긴다.
- 모든 단원에 행동 중심의 학습 목표가 없다. 학습자는 무엇을 이해하거나 수행해야 하는지 미리 알기 어렵다.
- 패션 과정의 ‘실제 사례’에는 출처가 없다. 잘란도, 자라, 유니클로, ASOS, H&M 등에 대한 구체적 주장은 **사실 확인 필요** 상태다.
- BCG는 일반적으로 Boston Consulting Group matrix의 약자로도 널리 쓰인다. ‘Brand Generated Content’를 BGC가 아닌 BCG로 표기할 경우 혼동될 수 있어 용어 출처와 표기 근거 확인이 필요하다.
- 1단원은 다른 패션 단원보다 분량이 약 2배 길다. 데이터 시장·양면시장·정책 비용까지 한 화면 흐름에 포함되어 초급 학습자의 인지 부담이 크다.
- Flask 글은 실습 목록은 있으나 학습 목표, 결과 확인 기준, 흔한 오류, 단원 요약과 자기점검이 부족하다.
- 광고·보안·배포 내용은 정책과 기술 변화가 빠르므로 발행 시점과 공식 문서 확인일을 표시해야 한다.

## 웹 가독성 측면에서 보완이 필요한 부분

- 왼쪽 메뉴에 과정 구분과 단원 묶음이 없어 현재 위치를 파악하기 어렵다.
- 긴 단원에서 본문 내부 목차가 없다. 모바일에서 원하는 절로 이동하기 어렵다.
- 사례, 핵심 정리, 주의, 사실 확인 필요가 모두 일반 본문 형태라 시각적 위계가 약하다.
- 코드 블록은 있으나 ‘파일명’, ‘입력할 위치’, ‘실행 결과’가 한 세트로 표시되지 않는다.
- 이전·다음 단원 버튼과 전체 진행률이 없어 연속 학습 흐름이 끊긴다.
- 오른쪽 후원·광고 영역은 PC에서는 괜찮지만 학습 보조 기능보다 수익 영역이 먼저 강조되지 않도록 유지해야 한다.

## 학습 효과 측면에서 보완이 필요한 부분

- 패션 과정은 설명을 읽는 비중이 높고, 관찰·분류·계산·판단 활동이 일정하게 배치되지 않았다.
- 5, 7, 9단원 등 일부 단원은 명시적인 점검 문제가 부족하다.
- 생성형 AI 과제가 거의 모든 패션 단원 마지막에 반복되어 단원 고유 역량보다 도구 사용이 앞설 수 있다.
- 정답 또는 해설이 없어 학습자가 자신의 이해를 확인하기 어렵다.
- Flask 과정은 코드를 복사했을 때 성공 화면이 무엇인지, 실패하면 어디부터 확인할지 안내가 부족하다.

## 가장 우선적으로 수정해야 할 사항

1. 패션 데이터와 Flask 과정을 별도 트랙으로 분리한다.
2. 모든 단원에 ‘학습 목표→도입 질문→본문→활동→핵심 정리→점검→다음 단원’ 공통 구조를 적용한다.
3. 구체적인 기업 사례에는 출처를 달거나 ‘사실 확인 필요’ 표시를 한다.
4. 메뉴에 과정명과 진행 상태를 표시하고 이전·다음 이동을 추가한다.
5. Flask 코드에 파일 위치, 예상 결과와 오류 해결 정보를 추가한다.

## 전체적인 발전 방향

이 사이트는 ‘읽는 블로그’보다 ‘짧은 화면 단위로 개념을 배우고 즉시 적용하는 웹 교재’로 발전시키는 것이 적합하다. 패션 과정은 의사결정 시뮬레이션 중심으로, Flask 과정은 실행 결과가 남는 프로젝트 중심으로 차별화한다. 광고는 학습 흐름 밖에 유지하고, 학습 완료와 다음 행동을 본문 끝에서 더 강하게 안내한다.

- 두 과정 분리: 학습 목적과 선수지식이 완전히 다르기 때문이다.

- 과정 홈 추가: 학습자가 자신의 목적에 맞는 경로를 선택하게 하기 위해서다.
- 공통 단원 구조 추가: 읽기, 적용, 점검의 리듬을 반복해 학습 부담을 낮추기 위해서다.

# D. 단원별 개선안

## 과정 A: 패션 데이터 리터러시

### 1. 데이터의 경제학

- **학습 목표:** 데이터의 가치와 관리 비용을 구분하고 자동화와 인사이트의 관계를 설명한다.
- **도입 질문:** “매장에 쌓인 기록은 모두 자산일까?”
- **활동:** 종이 장부, POS, 피팅룸 기록의 활용 비용 비교표 작성.
- **도식:** 기록→정제→연결→자동화→인사이트 흐름도.
- **점검:** 데이터 저장 비용이 낮아져도 전체 비용이 사라지지 않는 이유는?
- **연결:** 다음 단원에서 패션 정보를 컴퓨터가 표현하는 방식으로 이동한다.

### 2. 컴퓨터가 패션을 기억하는 법

- **학습 목표:** 정형·비정형 데이터와 RDB·NoSQL·Graph DB를 사례에 맞게 구분한다.
- **도입 질문:** “부드러운 촉감과 오버핏을 숫자로 저장할 수 있을까?”
- **활동:** 상품 상세페이지의 정보를 세 데이터 구조로 분류.
- **도식:** 동일 상품을 표·문서·그래프로 표현한 비교 그림.
- **점검:** 고객과 상품 관계를 탐색할 때 Graph DB가 유리한 이유는?
- **연결:** 표현된 데이터를 혼동 없이 찾기 위한 식별자로 이어진다.

### 3. 식별자와 패션 마스터 데이터

- **학습 목표:** SKU와 상품명 차이를 설명하고 간단한 SKU 규칙을 설계한다.
- **도입 사례:** 같은 ‘블랙 티셔츠’가 서로 다른 재고로 잡힌 상황.
- **활동:** 브랜드·시즌·품목·컬러·사이즈로 SKU 만들기.
- **주의:** 코드 안에 의미를 너무 많이 넣을 때의 변경 비용.
- **점검:** 식별자가 중간에 바뀌면 어떤 데이터가 끊기는가?
- **연결:** 정확한 식별자를 SQL로 조회하는 단원으로 이어진다.

### 4. SQL과 질문의 기술

- **학습 목표:** 모호한 업무 요청을 SELECT·FROM·WHERE·GROUP BY 구조로 바꾼다.
- **도입 질문:** “‘요즘 잘 나가는 옷’에서 요즘과 잘 나간다는 무엇인가?”
- **활동:** 자연어 질문 세 개를 쿼리 요구사항으로 변환.
- **웹 요소:** SQL 절을 순서대로 맞추는 드래그 활동.
- **점검:** 집계 기준 없이 판매량만 비교할 때 생기는 문제는?
- **연결:** 추출한 데이터를 어떤 집단끼리 비교할지 살펴본다.

### 5. 집단 비교

- **학습 목표:** 세그먼트와 클러스터의 차이, A/B 테스트의 기본 조건을 설명한다.
- **도입 사례:** 연령이 같지만 취향이 다른 두 고객.
- **활동:** 고객 카드 분류 후 사람이 만든 기준과 데이터 기준 비교.
- **도식:** 세그먼트와 클러스터 2열 비교표.
- **점검:** A/B 테스트에서 한 번에 여러 요소를 바꾸면 안 되는 이유는?
- **연결:** 차이가 생긴 원인을 증명하는 문제로 이동한다.

### 6. 관계 증명

- **학습 목표:** 상관관계와 인과관계를 구분하고 제3의 변수를 찾는다.
- **도입 질문:** “숏패딩 매출은 디자인 때문에 올랐을까, 한파 때문일까?”
- **활동:** 관찰 데이터에서 가능한 교란변수 세 개 찾기.
- **도식:** 상관→실험→예측 사다리.
- **점검:** 상관계수가 높아도 인과를 말할 수 없는 이유는?
- **연결:** 인과를 확정하기 어려운 상황에서 확률로 판단한다.

### 7. 확률적 사고

- **학습 목표:** 기댓값을 계산하고 안정형·모험형 상품의 생산 배분을 비교한다.
- **도입 사례:** 베이직 두 품목과 트렌드 한 품목에 예산 배분.
- **활동:** 확률과 이익을 바꿔 기댓값 다시 계산.
- **웹 요소:** 슬라이더 기반 생산 배분 시뮬레이터.
- **점검:** 기댓값이 같아도 위험이 다를 수 있는 이유는?
- **연결:** 결과를 측정할 지표를 설계하는 단원으로 이어진다.

### 8. 온라인 콘텐츠와 허영 지표

- **학습 목표:** 허영 지표와 행동 지표를 구분하고 목적에 맞는 KPI를 고른다.
- **도입 질문:** “좋아요가 늘었는데 매출이 그대로라면 성공일까?”
- **활동:** 조회수·클릭률·전환율·LTV를 퍼널 단계에 배치.
- **도식:** 노출→관심→행동→구매→유지 퍼널.
- **점검:** 조회수가 유효한 지표가 되는 조건은?
- **연결:** 콘텐츠의 생성 주체와 데이터 편향으로 이어진다.

### 9. 브랜드 생성 콘텐츠와 사용자 생성 콘텐츠

- **학습 목표:** 두 콘텐츠의 목적·통제력·편향·도달 범위를 비교한다.
- **도입 사례:** 룩북 이미지와 고객 실착 사진이 서로 다른 인상을 주는 상황.
- **활동:** 같은 상품의 공식·사용자 콘텐츠 평가표 작성.
- **주의:** BCG/BGC 약어는 **사실 확인 필요**.
- **점검:** UGC가 항상 더 진실하다고 볼 수 없는 이유는?
- **연결:** 다양한 피드백을 조직의 반복 업무에 반영하는 자동화로 이동한다.

### 10. 패션 자동화와 실험 환경

- **학습 목표:** 자동화하기 좋은 업무를 식별하고 잘못된 자동화의 위험을 설명한다.
- **도입 질문:** “틀린 발주 규칙을 자동화하면 무엇이 더 빨라질까?”
- **활동:** 반복성·예외·위험 기준으로 업무 자동화 후보 평가.
- **도식:** 사람 판단과 기계 반복의 역할 경계.
- **점검:** 자동화 전에 실험 문화가 필요한 이유는?
- **연결:** 기계가 오차를 줄이는 최적화 원리로 이어진다.

### 11. AI 최적화와 미분의 직관

- **학습 목표:** 선형 함수의 기울기와 경사하강법을 직관적으로 설명한다.
- **도입 사례:** 예측 생산량과 실제 판매량의 오차를 줄이는 상황.
- **활동:** $f(x)=ax+b$에서 $a$, $b$를 바꾸며 예측 변화 관찰.
- **웹 요소:** 기울기와 절편 슬라이더, 그래프 즉시 갱신.
- **점검:** 학습률이 너무 클 때 생길 수 있는 문제는?
- **연결:** 학습된 확률 모델로 콘텐츠를 생성하는 원리로 이어진다.

### 12. 생성형 AI와 패션 프롬프트

- **학습 목표:** 생성 모델의 확률적 성격과 프롬프트 요소를 설명하고 결과를 비판적으로 평가한다.
- **도입 질문:** “같은 ‘우아한 드레스’ 요청이 매번 다른 결과를 내는 이유는?”
- **활동:** 목적·실루엣·소재·조명·제약 조건으로 프롬프트 재작성.
- **주의:** 특정 기업 사례와 사회적 반발 내용은 **사실 확인 필요**.
- **점검:** 구체적인 프롬프트가 사실의 정확성을 보장하지 않는 이유는?
- **연결:** 전체 과정의 데이터 질문→표현→검증→자동화 흐름을 회고한다.

## 과정 B: Flask 프로젝트

### 1. 기획과 개발 환경

- **학습 목표:** 프로젝트 구조를 만들고 최소 Flask 앱을 실행한다.
- **도입 문제:** 강의 글이 늘어날 때 HTML을 매번 복사하지 않고 관리하려면?
- **활동:** 가상환경 생성, 패키지 설치, `/` 응답 확인.
- **웹 요소:** 단계별 완료 체크와 터미널 출력 예시.
- **점검:** 가상환경을 사용하는 이유는?
- **연결:** 다음 글에서 화면을 템플릿으로 분리한다.

### 2. 라우팅과 템플릿

- **학습 목표:** URL을 함수에 연결하고 공통 레이아웃을 상속한다.
- **도입 문제:** 내비게이션 수정 내용을 모든 페이지에 한 번에 반영하려면?
- **활동:** 세 라우트와 `base.html` 작성.
- **점검:** `include`와 `extends`의 역할 차이는?
- **연결:** 템플릿에 Markdown 콘텐츠를 주입한다.

### 3. Markdown 강의 시스템

- **학습 목표:** 파일을 정렬하고 선택한 Markdown을 안전하게 HTML로 변환한다.
- **도입 문제:** 파일 하나만 추가해도 메뉴가 자동 갱신되게 하려면?
- **활동:** 세 강의 파일 생성 후 첫 페이지 자동 표시 확인.
- **주의:** 요청 경로가 실제 허용 목록에 있는지 검증한다.
- **점검:** 사용자 입력 경로를 그대로 열면 위험한 이유는?
- **연결:** 완성된 본문 주변에 수익 영역을 설계한다.

### 4. 후원과 광고 영역

- **학습 목표:** 후원·광고 카드를 구현하고 모바일에서 본문을 우선한다.
- **도입 문제:** 광고가 수익은 만들지만 학습을 방해한다면 어디에 둘 것인가?
- **활동:** 두 카드 구현 후 데스크톱·모바일 비교.
- **주의:** 최신 플랫폼 정책과 표시 의무는 발행 시 공식 문서 확인 필요.
- **점검:** 가짜 광고 배너 대신 빈 슬롯을 사용하는 이유는?
- **연결:** 공개에 필요한 보안과 테스트로 이동한다.

### 5. 보안, 테스트와 배포

- **학습 목표:** 비밀 값을 분리하고 접근 제어와 핵심 경로를 테스트한다.
- **도입 문제:** 로컬에서 동작하는 코드가 왜 그대로 공개되면 위험할까?
- **활동:** 환경변수 설정, 로그인 흐름과 17개 URL 테스트.

- **점검:** 디버그 모드를 공개 서버에서 끄는 이유는?
- **마무리:** 배포 체크리스트와 다음 개선 백로그 작성.

# E. 실제 수정본 적용 규격

실제 원고는 아래 형식을 모든 단원에 공통 적용한다. 기존 본문을 한 번에 자동 변환하지 않고, 1단원부터 내용의 정확성과 출처를 확인하며 순차 편집한다.

```markdown
# 단원 제목

> 도입 질문 또는 문제 상황

## 학습 목표

- 학습자는 …을 설명할 수 있다.
- 학습자는 …을 적용할 수 있다.

## 핵심 용어

- **용어(영문)**: 쉬운 정의

## 본문 절 제목

3~5문장 이내의 짧은 문단으로 설명한다.

> **핵심 정리**  
> 반드시 기억할 내용을 1~3문장으로 정리한다.

> **주의**  
> 자주 하는 오해 또는 적용 범위의 한계를 설명한다.

### 사례

사례 설명과 출처를 제시한다. 출처가 없으면 **사실 확인 필요**라고 표시한다.

## 짧은 활동

학습자가 직접 분류·계산·작성할 과제를 제시한다.

## 핵심 내용 요약

- 핵심 1
- 핵심 2
- 핵심 3

## 학습 점검

1. 개념 확인 문제
2. 적용 문제
3. 판단 또는 성찰 문제

<details>
<summary>정답과 해설 보기</summary>

정답과 해설

</details>

## 다음 단원

이번 단원의 개념이 다음 단원에서 어떻게 사용되는지 설명한다.
```

## 실제 수정 우선순위

1. 1단원을 위 규격의 대표 단원으로 먼저 완성한다.
2. 2~4단원에 동일한 구조를 적용하고 난이도를 확인한다.
3. 5~12단원의 기업 사례 출처를 검증한 뒤 편집한다.
4. Flask 1~5편에 목표·예상 결과·오류 해결·점검을 추가한다.
5. 모든 단원 수정 후 전체 용어집과 참고자료 페이지를 만든다.

## 화면 구성 원칙

- PC: 왼쪽 과정 목차, 중앙 학습 본문, 오른쪽 후원·광고를 유지한다.

- 핵심 정리·주의·사실 확인 필요는 색상뿐 아니라 아이콘과 텍스트 라벨을 함께 사용한다.

# G. 추가 제안

## 추가하면 좋은 내용

- 과정 소개와 선수지식, 예상 학습 시간을 보여주는 홈.

- Flask 과정의 `requirements.txt`, `.gitignore`, 오류 해결표.

## 보완하면 좋은 사례

- 기업명 중심 사례보다 작은 가상 패션 브랜드의 일관된 데이터를 1~12단원에 반복 사용하면 개념 연결이 쉬워진다.
- 실제 기업 사례는 공식 기업 보고서, 공식 기술 블로그, 학술 논문 또는 신뢰할 수 있는 1차 자료로 검증한다.
- 생성형 AI 사례는 사용 도구, 시점, 공개 범위와 논란의 근거를 함께 표시한다.

## 삭제하거나 축소해도 되는 내용

- 1단원의 데이터 시장·양면시장 상세 설명은 핵심 흐름에서 분리해 보충 아코디언으로 이동한다.
- 모든 단원의 생성형 AI 과제 반복은 축소하고 단원 고유 활동으로 바꾼다.
- 확인되지 않은 기업 성과 수치나 단정적인 인과 표현은 출처 확보 전 삭제하거나 가상 사례로 바꾼다.

## 이미지나 영상이 필요한 부분

- RDB·NoSQL·Graph DB 비교 도식.
- 상관→인과→예측 사다리.
- 고객 행동 퍼널과 KPI 지도.
- 경사하강법 그래프 애니메이션.
- Flask 요청→라우트→템플릿→응답 과정도.

## 학습 활동으로 전환하면 좋은 부분

- SKU 구조 설명→직접 SKU 설계.
- SQL 구문 설명→질문 카드를 쿼리 순서로 배열.
- 확률 설명→생산 예산 배분 시뮬레이션.
- 허영 지표 설명→지표 분류 활동.
- Flask 폴더 구조→파일을 올바른 폴더로 드래그하는 활동.

## 접근성 개선

- 모든 이미지에 의미 있는 대체 텍스트를 제공한다.
- 핵심 상태를 색상만으로 구분하지 않는다.
- 키보드만으로 목차, 아코디언, 퀴즈에 접근할 수 있게 한다.
- 코드와 본문의 명도 대비를 확인한다.
- 애니메이션에는 `prefers-reduced-motion`을 적용한다.
- 링크 문구는 ‘여기’ 대신 목적지를 설명한다.
